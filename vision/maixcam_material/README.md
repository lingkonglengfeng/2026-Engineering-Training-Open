## MaixVision 实时查看物料阈值

在 MaixVision 停止统一入口后，打开本目录 `material_threshold_debug.py` 并运行；这是单文件调试程序，不需要把 `_threshold_debug_app.py` 或原物料 `main.py` 上传到设备。它运行与统一入口相同的物料 `calibrated_threshold()` 和 `detect_material_center()`，从相机上的 `~/maixcam_material_colors.json` 读取现场取样，并使用统一入口相同的 A19/PWM7、20 kHz、50% 补光设置。顶部显示当前颜色和实际生效的 `L/A/B` 上下限、默认/取样状态、检测原因、图像像素偏差 `dx/dy`（右/下为正）；换色或取样后控制台也打印 `[THRESHOLD]`。画面和启动日志会显示 `TX:OFF`；它不打开串口，不会向 STM32 发送位置，也不能触发 V65 抓取。

底部 `Color` 手动循环红、黄、蓝、绿、黑、浅蓝；`View` 切换彩色原图与二值掩码，两个视图都运行同一检测；`Learn` 进入/退出取样，触摸物料表面或按 `Sample` 取画面中央 12×12 像素的 LAB 中位数。这些按钮接收 MaixCAM 实体触屏事件；MaixVision 电脑预览的鼠标点击不会转发为设备触摸。首次有效新样本替换该颜色旧样本，最多保留6个；保存成功后统一入口下次切入物料模式会重新载入阈值。`Lock` 冻结曝光和白平衡，`Auto` 恢复。若提示 `OVERLAP`，蓝色/浅蓝取样无法稳定分开，应在实际补光下重取样。调试脚本为便于观察每帧保留原图并绘制阈值，屏幕 FPS 不代表统一入口运行帧率。确认阈值后，停止调试脚本，再运行统一 `../maixcam_service/main.py`。

## 独立运行圆盘切线（2026-10-04）

圆盘切线现在有独立的 **`plate_tangent.py`**。在 MaixVision 中停止原程序，打开本目录的这个文件并运行；**只上传这一个 `.py` 文件即可**，启动直接识别白色圆盘前沿的水平切线。物料识别继续使用 `main.py`。两者使用同一摄像头和 UART0，切换运行。

已确认原程序存在一个与“切换到圆盘后停止”吻合的接口错误：`draw_ellipse` 漏传了 `start_angle`、`end_angle`。MaixPy v4 要求 `x, y, a, b, angle, start_angle, end_angle, color`；原调用在检出圆盘、连续确认完成并开始画椭圆时会抛 `TypeError`。`main.py` 和独立程序均已改为传入 `angle, 0, 360, color`。这确认了代码缺陷；没有设备上的原始报错，仍不能排除其他启动/运行问题。

独立程序保持彩色盘沿算法、320×240 相机画面、连续 3 帧确认；圆盘串口现在使用统一8字节 `PLATE_PX(0x09)`，包含切点的图像X/Y偏差。默认在 224×168 小图拟合，再将切点和椭圆映射回相机原图。X/Y 均取红色切点，以实际屏幕中心为原点，右正、上正，单位是**实际屏幕像素**；旋转椭圆的切点 X 与圆心 X 可能不同。黄色为拟合盘沿，绿色为水平切线，红色为切点。顶部第一行显示 X/Y，第二行显示 FPS，使用固定间距及黑色细描边，没有整块黑色背景；异常时额外显示一行简短提示。串口计数和检测状态放在控制台，检测在绘制界面之前完成。底部按钮：

- **Edges / Image**：切换稀疏边缘图和彩色预览。
- **Retry**：清除检测故障并重新确认目标。
- **Lock / Auto**：锁定或恢复曝光、白平衡。

错误排查：

- MaixVision 控制台打印启动阶段、OpenCV/NumPy 版本和完整异常堆栈。
- 检测异常会清除坐标、发送 `valid=0`、保留预览并显示 `PLATE_ERROR`；按 Retry 重试。
- UART 初始化失败时显示 `TX:OFF`，视觉仍继续；需要串口输出时检查日志、端口与引脚配置。
- 启动/摄像头/绘图错误会显示错误阶段，等待 MaixVision 停止，不循环重启摄像头。
- Python 异常保存到**相机**的 `~/maixcam_plate_error.log`（通常 `/root/maixcam_plate_error.log`）；支持 faulthandler 时，原生崩溃栈另存 `~/maixcam_plate_fatal.log`。强制杀进程、掉电或内存不足可能来不及写日志。
- 原 `main.py` 的错误保存到 `~/maixcam_material_error.log`；PLATE 检测异常会锁存，切换到其他颜色后再切回 PLATE 可重试。

独立程序使用固件自带的 `maix`、`cv2`、`numpy`；电脑直接运行无参数会因没有 `maix` 失败。在电脑验证照片时执行：

### 低帧率优化与耗时诊断

截图的 3.3 FPS 约每 0.3 秒更新一次；连续 3 帧确认需要约 0.9 秒，车辆移动时会产生测量滞后。30 FPS 是相机请求值，不代表完整检测循环能达到 30 FPS。

`plate_tangent.py` 默认 `PROCESS_WIDTH=224`，拟合像素数约为原来的 49%。相机和显示保持 320×240，输出仍按原图和实际屏幕换算。两张实拍映射回原图后的切线 Y 与全分辨率结果相差约 0.34 / 0.55 px。缩小可能损失弱边缘或细节；现场需要全分辨率时，将 `PROCESS_WIDTH` 改回 `320`。

两份程序的拟合核心均已优化：仅在边缘点检查色度、提前剔除跨度不足的断弧组合、缓存迭代中不变的梯度、批量评估相同的 32 组鲁棒拟合种子。独立程序精简了画面上的状态文字，MaixVision JPEG 预览质量设为 80，检测仍使用未压缩的相机图像。

`SHOW_TIMING=True` 时，控制台每 2 秒打印一次 `C / D / V`、串口计数和检测状态：C 为当前帧取帧耗时，D 为当前帧检测耗时，V 为绘制和显示/预览传输耗时，单位 ms。画面上不显示这些调试数据。它们用于定位瓶颈，不能把电脑耗时换算成 MaixCAM 帧率。

电脑同进程测量：全分辨率核心两张实拍约 2.83 / 2.31 ms，小图路径约 1.99 / 1.78 ms；相对于优化前原路径约 3.14 / 2.58 ms，检测时间减少约三成。此数据只覆盖电脑上的图像检测，不包括真实相机、显示、UART 和 MaixVision 传输。

回归验证：`python -m unittest discover -s . -p 'test_*.py'`，65 项通过。新增测试覆盖按官方签名绘图、两张实拍精度、独立设备循环、连续确认/退出失效、检测异常后继续预览、UART 初始化失败后继续视觉、短写重同步、小图遮挡/误检拒绝、边缘图恢复尺寸、原图不被修改、非等比旋转椭圆坐标恢复、全分辨率选项、切点 X 的屏幕换算以及 X/Y 显示与串口一致。模拟设备接口用于验证控制流程，真实 MaixCAM 帧率需重新上机测量。单文件内置拟合核心与 `main.py` 保持一致，修改核心时需同步两份并运行回归测试；`main.py` 沿用全分辨率检测。

接口依据：[Sipeed MaixPy 图像 API](https://en.wiki.sipeed.com/maixpy/api/maix/image.html)。

## 白色原料转盘：彩色盘沿与底部切线

按 Color 循环选择：红→黄→蓝→绿→黑→浅蓝→**PLATE**→红。物料模式继续使用原生颜色二值化并发送 MAT；PLATE 模式保留彩色图，识别盘沿并发送最低点水平切线切点的 X/Y。两种任务轮流执行。

用户实拍表明盘和背景均为白色，白色 LAB 阈值会把两者合并。因此 PLATE **不再对白色做整面二值化**，也不再使用旧的 PLATE_WHITE_LAB 或白盘颜色标定数据。彩色图中的明暗边界和有色物料位置仍提供可用信息：

```text
RGB 原图 → LAB（提取亮度及色度）→ 轻度平滑 → Canny 局部边缘
         → 抑制饱和有色物料边缘和由暗返亮的阴影边
         → 长弧提取/断弧合并 → 鲁棒种子与椭圆拟合
         → 边缘极性/拟合误差/左右支撑/弧跨度检查
         → 椭圆最低点水平切线 → 连续 3 帧确认 → PLATE 串口帧
```

保留原图颜色用于预览和排除有色物料；主要定位信号是盘沿的亮度梯度，颜色不能凭空区分没有边缘对比度的两块白色区域。边缘图是稀疏调试结果，不是把整幅白色背景作为盘面。

用户确认的切线是圆弧靠近小车一侧、最低点处的水平切线。沿用相机俯视条件，并用椭圆处理照片中轻微倾斜/非圆投影；圆心可在画面上方。最低点由椭圆形状求出，不能简单用任意旋转椭圆的 cy+半高。只有切点位于画面内，并且有两侧可靠弧线支持时才输出；短弧、严重遮挡、歧义或完全没有盘沿信号时发送无效，不输出旧值。这里不把画面裁切直边作为切线。

规则 PDF 第 4 页表 2/图 2规定顶面 Ø300 mm、高度 80–100 mm；白色按用户实物描述。尺寸不直接换成未经标定的像素半径，也没有把像素转换为毫米。

### 串口与参数

串口保持115200 8N1，正常最高20Hz，切换/失效优先。圆盘使用 `PLATE_PX=0x09`，ID固定0；两个坐标均取红色切点，若只按水平切线控制，则主控只读取Y。

界面仍是屏幕像素、右/上正；**线上是相机图像像素、右/下正**，发送前除以显示缩放比例并反转Y。320×240相机、552×368屏幕时显示比例为368/240；界面Y=-40屏幕像素对应线上dy约+26.1图像像素。无目标/确认不足/非有限或超范围坐标发送VALID=0、XY=0；真实有效零点仍VALID=1。

实际示例（传给编码器的屏幕坐标(30,-40)，缩放比例1，SEQ12）：`6B 09 E0 2C 01 90 01 9E`，即 dx=+30.0、dy=+40.0 图像像素。独立圆盘程序使用统一协议源码，不再发送@PLATE文本；物料main.py主循环不再切换圆盘。主控已接入 `Vision_GetPixel(camera,VISION_TYPE_PLATE_PX,...)`。
| 参数 | 默认 | 调节方向 |
|---|---|---|
| PLATE_EDGE_LOW / HIGH | 4 / 12 | 盘沿太弱时适度降低；大量噪声时提高，先检查 Edges 图。 |
| PLATE_NEUTRAL_CHROMA_MAX | 35 | 抑制饱和有色物料；若光源染色使盘沿丢失，可适当放宽。 |
| PLATE_MAX_JOIN_GAP_FRACTION | 0.20 | 允许合并相近断弧的间隙，占处理图宽度比例。 |
| PLATE_MIN_INLIER_RATIO | 0.60 | 圆弧候选至少 60% 点符合边缘/拟合条件。 |
| PLATE_MIN_ARC_DEG | 35° | 最小可见角跨度，还需切点左右的有效支撑。 |
| PLATE_CONFIRM_FRAMES | 3 | 连续确认后才输出 valid=1。 |

物料识别的原生快速路径保持不变，只有 PLATE 加载 NumPy/OpenCV；首次加载可能耗时。PLATE 使用局部 Canny、受限数量轮廓和拟合候选，不使用全图 Hough。电脑耗时不能换算为 MaixCAM 帧率，实时帧率仍需设备验证。

## 串口发送坐标

`UART_ENABLED=True`，默认 MaixCAM 的 `/dev/ttyS0`、115200、8 数据位、无校验、1 停止位、无流控。`UART_PIN_FUNCTIONS` 将 A16 映射为 UART0_TX，A17 为 UART0_RX。需要其他串口时同时修改设备路径和引脚映射，不能只改路径；本默认引脚配置适用于 MaixCAM，不适用于 MaixCAM2。

按本仓库 `Core/Src/usart.c` 实际 USART2 配置接线：

| MaixCAM | STM32H723 | 用途 |
|---|---|---|
| A16 / TX | PA3 / USART2_RX | 坐标发送，必接 |
| GND | GND | 共地，必接 |
| A17 / RX | PA2 / USART2_TX | 预留反向通信；当前只发送，可不接 |

信号为 3.3V TTL，电源按实际相机供电接口连接。UART0 启动时可能输出系统日志，也用作默认maix protocol端口；接收端只接受正确帧头、类型、字段和CRC8的二进制帧。A16也与启动检测有关，不要在上电时拉低。

三种位置发送已统一为工程[8字节协议](../../docs/electrical/MaixCAM_STM32_统一8字节串口协议_v0.1.md)：

| 程序/目标 | TYPE | ID | 位置数据 |
|---|---|---|---|
| main.py 物料圆心 | 0x02 MAT_PX | 工程颜色ID：1红/2黄/3蓝/4绿/5浅蓝/6黑 | 图像dx/dy |
| plate_tangent.py / 统一服务模式8 切点 | 0x09 PLATE_PX | 0 | 切点图像dx/dy；只控制切线Y可忽略X |
| middle_ring.py 中间圆环 | 0x03 RING_PX | 2 | 圆心图像dx/dy |

```text
6B TYPE META X_LO X_HI Y_LO Y_HI CRC8
META = VALID<<7 | (图像SEQ模16)<<3 | ID
XY = 有符号int16、小端、0.1图像像素，右正、下正
CRC8：poly07/init00/不反射/xorout00，覆盖前7字节
```

物料有效示例（图像偏差+30,+20，蓝色，SEQ12）：`6B 02 E3 2C 01 C8 00 AF`。无目标、蓝色、SEQ13：`6B 02 6B 00 00 00 00 29`；这里META本身为6B，不能将正文的6B重新当帧头。串口助手使用HEX显示/发送，不附加CRLF。

比赛/UI内部编号仍5黑/6浅蓝，发送时映射到工程冻结编号，原颜色标定文件不需重做。中心零坐标是否有效必须看META.VALID，不能仅凭坐标0判断。图像序号包含限频跳过帧，4位会回绕，必须同时看接收年龄。

发送器每次新图像构造当前帧，普通最高20Hz；最多缓存一个短写帧。丢失/切换/写入错误时放弃半帧并等待55ms，让主控50ms半帧超时后接收新帧；不添加换行、不主动sleep。超时期间不积压历史观察，正常完整写入时失效立即发送。退出只尽力发无效帧，断电靠主控200ms接收超时处理。

**主控已接入**：`Vision_GetPixel(camera,type,&value,&age_ms)` 返回快照，检查value.valid后读取dx_px/dy_px；200ms无新帧自动无效。各端口独立、模式/目标切换和DMA丢包会清除旧有效位置。像素未写入旧毫米结构。主控默认两个相机口均为二进制；旧ASCII相机须显式选legacy协议，不能混发。本次修改包含接收解析和读取接口，未调用底盘运动接口。

相机三个程序仍单文件上传，无需额外上传protocol8.py；协议代码由 `tools/sync_protocol8.py` 嵌入，`--check`可验证副本一致。部署时相机程序与主控固件必须一起更新；先用USB-UART和HEX串口助手核对位置、VALID、颜色ID，再实测纠偏运动符号。界面右/上正的旧标定不能不经转换直接用于线上右/下正坐标。

## 蓝色和浅蓝的现场校准

旧示例 BLUE 和 LIGHTBLUE 的 LAB 范围有重叠，并且浅蓝依赖 L（亮度）下限；在不同光照下可能出现 BLUE 两个都白、LIGHTBLUE 只留下亮斑。二值截图已经丢失 RGB/LAB 数据，不能从截图可靠反推阈值，因此要在相机上取样。

1. 使用最终工作时的光照、相机位置和距离，先让自动曝光/白平衡稳定。如果最终不用补光，就在不补光的情况下校准。手机补光不宜作为无补光运行的标定条件。
2. 可点击 `Lock` 冻结当前曝光、增益和白平衡，顶部应出现 `LOCK`。若提示 `LOCK FAIL`，检查固件接口/重启恢复自动模式；不必为此停下使用取样功能。`Auto` 按钮恢复自动模式，之后应复核校准效果。
3. 用 `Color` 切到 `BLUE`，按 `Learn`。此时显示**原始彩色图**，点击真实蓝色物料表面的 3 个不同位置，避开白色反光、深阴影、背景、边缘。每次统计点击处 12×12 的 LAB 中位数，顶部显示 `N` 和 `LAB`。按 `Done` 回到二值图。
4. 切到 `LIGHTBLUE`，重复上述取样步骤。分别选择正确的实物，程序不会替你判断取样对象的真实标签。
5. 校准后切换两种颜色，核对每种模式下是否只有对应物料变白，并显示中心坐标。光照/相机参数变化后，应重新取样两种颜色。

程序只接收 MaixCAM 的触屏事件，未实现 MaixVision 电脑预览点击到相机的转发。Learn 中新增中央 12×12 取样框，低频显示该框的 LAB；可以移动物料让干净表面覆盖框，在设备上按 `Sample` 保存中央样本，或直接触摸图中的物料位置取样。Learn 时右侧按钮是 Sample，回到检测模式后才是 Lock/Auto。

蓝色族默认阈值已根据用户彩色截图中蓝紫/青蓝差异调整为 BLUE `[5,100,15,90,-128,-18]`、LIGHTBLUE `[5,100,-60,14,-90,-10]`，A 通道互斥，不再使用浅蓝高亮度下限。截图经 JPEG/缩放，这只是可直接测试的起点；现场取样结果优先于默认值，读取到旧标定时不会自动覆盖它。

进入 Learn 后的第一份有效样本替换当前颜色的旧样本，最多保存最近 6 份；若直接按 Done 而未取样，保留原标定。样本即时保存至相机用户目录下 `maixcam_material_colors.json`（通常 `/root/maixcam_material_colors.json`），下次运行自动读取。`SAVE FAIL: RAM only` 表示当前内存标定可用但未保存，修复写入权限后需重取样。其他颜色也可使用 Learn 校准。

校准状态：

| 状态 | 含义 |
|---|---|
| `NEED_PAIR` | 蓝色/浅蓝至少一组未取样，当前仍是示例或单色取样阈值，可能互相误选。 |
| `LAB_A` / `LAB_B` | 两组样本在对应色度通道上有间隙，用该通道生成互斥阈值，并放开 L 范围以减少明暗变化的影响。 |
| `LAB_L` | 两组样本色度不足以分开，只能按亮度区分；必须保持照明/曝光稳定，无法保证适应任意光照变化。 |
| `OVERLAP` / `CAL_OVERLAP` | 两组样本重叠，不输出有效中心；请确认点击对象正确、避开反光/阴影，并在统一光照下重取样。 |

阈值使用矩形 LAB 范围，互斥不代表一定能正确分类所有像素。应覆盖物料正常表面的多个位置，并用未参与取样的位置验证。严重欠曝、反光或两种材质的实际颜色分布重叠时，仅靠颜色不能保证区分。

## 圆心估计与未检出原因

处理流程：320×240 RGB → 所选颜色 LAB 原地二值化 → 灰度二值图 → 一次原生 find_blobs → 尺寸/长宽比/填充比例筛选 → 区域质心估计圆心。显示由 Display 按 FIT_CONTAIN 等比例居中缩放，触摸按同一几何关系映射。

已去掉 SDK `roundness()` 的硬过滤；填充比例直接用 `pixels/(w*h)` 计算。默认半径范围 5–110 px、长宽比下限 0.55、填充比例 0.35–0.96，顶部和底部圆均接受。这些设置用于避免轻微椭圆或亮度分割差异导致拒绝，并不是严格的圆周拟合。

屏幕 `B` 是原生检测返回的区域数；`R` 为包围框估计半径，`A` 为短边/长边，`D` 为白像素占包围框面积比例。状态 `OK` 表示选中了目标；拒绝时显示最大候选框及原因：

| 原因 | 排查方向 |
|---|---|
| `NO_BLOBS` | 二值图没有足够大的白色连通区域；检查颜色阈值、碎片化和 MIN_BLOB_PIXELS。 |
| `PIXELS` / `AREA` | 像素数太少，或区域超过画面面积 65%。 |
| `EDGE` | 区域被画面边缘裁切。 |
| `SIZE` | 包围框估计半径超出 MIN_RADIUS_PX/MAX_RADIUS_PX。 |
| `ASPECT` | 区域太细长。 |
| `DENSITY` | 区域太稀疏，或几乎填满矩形框。 |

`NO_BLOBS` 不一定是完全没有白像素：低于原生面积/像素阈值的小碎片不会返回。多个合格区域时选最大区域，同大小选靠近中心者。完整、均匀的圆形二值区域的质心与圆心重合；斜视、遮挡、反光孔洞、分割残缺会导致估计偏移。未检出时立即清空坐标，不展示旧值。

白色外环为形状示意，黑色中心十字为区域中心。正常检测界面使用黑白两色，Learn 界面使用彩色图，顶部状态和底部按钮会遮挡部分预览，检测在叠加界面之前完成。

## 规则、验证与性能

比赛规则 第 5–6 页：1红、2黄、3蓝、4绿、5黑、6浅蓝；物料顶部 Ø30、底部 Ø50、总高 60 mm，且现场可能存在色差。这里没有像素到毫米标定，串口输出屏幕像素坐标。

电脑需安装 NumPy/OpenCV 后运行 `python -m unittest discover -s vision/maixcam_material -p 'test_*.py'`。65 项检查覆盖两张打光/未打光实拍、彩色路径不做白色二值化、边缘预览内存持有、半圆/椭圆切线、遮挡、无信号/矩形拒绝，以及原有坐标/触摸映射、形状筛选、校准、UART、独立入口、小图提速与切点 X/Y 回归。它们不验证设备上的 native find_blobs/统计/相机锁定/串口接口或真实接线效果。

物料取样统计只在 Learn 模式点击时及中央框低频预览时运行；物料检测不使用 Canny/Hough，PLATE 使用局部边缘与圆弧拟合，均没有逐像素 Python 采样或主动等待。CAM_FPS=30 是摄像头请求值，显示 FPS 包含取帧、处理、绘制、串口、显示/传输开销。用户取样界面截图约为 29–30 FPS；加入串口后的帧率和真实链路仍需上机确认。

接口依据：[图像与统计 API](https://wiki.sipeed.com/maixpy/api/maix/image.html)、[相机曝光和白平衡 API](https://wiki.sipeed.com/maixpy/api/maix/camera.html)、[触摸屏 API](https://wiki.sipeed.com/maixpy/api/maix/touchscreen.html)、[Display API](https://wiki.sipeed.com/maixpy/api/maix/display.html)。

串口接口与引脚核对：[官方 UART 文档](https://wiki.sipeed.com/maixpy/doc/en/peripheral/uart.html)、[UART API](https://wiki.sipeed.com/maixpy/api/maix/peripheral/uart.html)。

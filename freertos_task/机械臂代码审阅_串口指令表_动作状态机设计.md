# 机械臂代码审阅、串口指令表与动作状态机设计

更新：5/6号轴及最高点参考限位已接入，当前实际指令以《ZDT机械臂接入_最高点参考与达妙限位.md》为准。下面保留接入前的审阅和完整动作状态机设计，自动抓放仍未实现。

原审阅状态：**当轮先设计，未接入三轴或修改固件。** 当前工程可直接使用的指令、独立模块已有但尚不可用的指令、建议新增的指令分别列出。轴ID不等于工位编号：工位1物料、2中转/粗加工、3最终暂放；电机dm旋转、5升降、6伸缩。

用户已确认：原料台旋转，物料经过固定抓取点；第二轮最终叠放在第一层姿态上增加一个物料的实测高度。

## 1. 审阅结论：先补接入，再做整个机械臂的状态机

建议采用已有ArmTask内的两级非阻塞状态机：**动作FSM**管理观察、等料、夹取、放置、收回；**工位FSM**把这些动作按三个物料及两轮任务组合。夹爪开闭是夹取/放置内部步骤，不单独再建一个抓爪任务。

| 现有文件 | 当前实现 | 当前构建/接入情况 |
| --- | --- | --- |
| Core/Src/arm_task.c、dm_motor.c | 达妙初始化、旋转服务、现有dm调试 | 已加入Keil，ArmTask每10ms服务 |
| Core/Src/arm_driver.c | 三轴封装，ID5/6相对脉冲/毫米，旋转角度接口 | 独立文件，未加入当前Keil |
| Core/Src/arm_calibration.c | ID5/6状态/位置、端点标定、命令/反馈队列 | 未接入UART、CAN分发或任务Poll |

以下具体缺口需要先处理：

1. **三轴尚未形成实际执行链。** 当前发arm命令不会进入候选ArmCalibration解析器。必须加入3个源文件、初始化、轮询、命令/反馈路由后才可三轴联调。
2. **“任意轴当前点置零”不完整。** 当前只能legacy达妙软件零点；候选arm zero也仅旋转。mark 5/6 min记录机械端点，不是任意工作零点。新增独立zero_count，不改机械端点记录。
3. **运动返回成功不等于到位。** 当前DM_Motor_SetPos忽略发送结果而返回HAL_OK；候选ArmDriver补查last_err并撤销失败目标，统一动作执行器应保留这种发送结果检查。 ArmDriver的HAL_OK通常表示CAN入队；默认线性pulses_per_mm=0，毫米动作会拒绝。需标定指令脉冲/mm和反馈计数/mm，并新增执行请求的到位结果。
4. **CAN2发送需统一所有权。** 底盘和两臂轴共用FDCAN2；候选ArmDriver直接调用ZDT发送。接入后不能两个任务随意并发操作同一HAL TX FIFO。建议ArmTask投递CAN2发送请求，由现有ZDT任务执行，再回报发送结果；ID5/6反馈只投递ArmTask，不让另一个接收器读取同一FIFO。
5. **达妙也要统一命令所有者。** 当前串口任务直接跑DM_Console，同时ArmTask服务同一实例。正式三轴模式应把控制指令交给ArmTask；普通诊断读取快照，不并发改模式/零点/目标。
6. **两套舵机驱动不能同时拥有TIM4。** 选ArmServo统一管理PD12/PD13。其ramping=0只说明PWM斜坡结束，不是物料已夹住/已放好。夹爪开闭和载物台槽位须实机示教；候选载台默认360°映射不是实物证明，连续旋转舵机也不能当绝对角度舵机用。
7. **停机入口尚未统一。** ChassisMotor_EmergencyStop函数会联动达妙，但当前串口stop/&STOP实际走ChassisMotor_SetCommand(STOP)，没有调用这个整车紧停函数；ID5/6及新舵机更未接入。不能把当前串口STOP当成所有机构已停。三轴接入后普通arm stop保持升降力矩、保留夹爪现态；不能把垂直轴失能或开爪当成普通停止。
8. **通讯/实际位置验证与导航补偿不同。** 不恢复前面移除的底盘过冲/自动补走。机械臂动作需要新反馈确认到位，否则不能继续下降或松爪；没有物料反馈时使用人工确认，不拿发帧成功替代抓取成功。

9. **新指令不能被旧解析器吞掉。** ArmCalibration_ProcessCommand对任何arm前缀（含未知指令）都会返回已处理；新pose/batch/zero带轴参数必须由统一ArmConsole先分派。自动动作期间禁止普通手动move/zero插入，stop/status及确认事件单独处理。停止请求用独立事件，不排在已满普通命令队列后。

现有独立arm_driver测试脚本已执行通过，但底层为模拟接口，不代表它们已接入当前HEX或机构方向/行程已经验证。

## 2. 串口指令表

调试UART4为115200、8N1，逐条发送，普通有线命令用CRLF结束。尖括号是参数占位，不要原样发送；例子是接口说明，不是连发动作脚本。

### A. 当前固件即可使用：达妙旋转

| 指令 | 用途 | 语义/条件 |
| --- | --- | --- |
| `dm help` | 列出现有达妙命令 | 只查看 |
| `dm status` | 状态、实际位置、在线和使能 | 角度单位rad |
| `dm enable` | 使能并确认POS保持 | 等新反馈，确认使能后再操作 |
| `dm pos <rad> [rad/s]` | 旋转到目标 | 如dm pos 0.1745 0.5，约10°；零点取当前dm偏移 |
| `dm zerohere` | 当前点作为RAM软件零点 | 当前实现要求已使能且有新反馈；应停稳后执行 |
| `dm target` | 查看目标与软件偏移 | 设置零点后检查 |
| `dm disable` | 请求失能 | 反馈确认后才认为释放 |
| `dm clear` | 清达妙故障 | 不等于自动使能 |
| `dm zero confirm` | 改电机保存的零点 | 会写电机Flash；当前实现检查enable_sent为0，执行前用状态确认失能 |

上述短命令也可按现有入口发送&dm ...。日常示教优先RAM零点；不要把dm zerohere和候选arm zero的使能要求混用：前者需使能，后者当前实现要求旋转已失能。

当前没有可直接使用的升降、伸缩、夹爪**arm**入口，不过有线控制台已有通用步进诊断指令。若实际ID5/6支持当前Emm/CAN协议，可用以下入口测试；它们不提供机械臂零点、毫米坐标、行程标定或抓放状态机，也不能验证到位。

| 指令 | 功能 | 实际源码行为 |
| --- | --- | --- |
| `zpos 5 <signed_pulses> <rpm>` | 指定ID5相对位置测试 | 先发送使能，再发送位置脉冲，加速度字段固定200 |
| `zpos 6 <signed_pulses> <rpm>` | 指定ID6相对位置测试 | 同上；方向先实机确认 |
| `test 5 <rpm> / test 6 <rpm>` | 指定轴速度测试 | 先使能再发速度，不是自动寻端点 |
| `test 5 0 / test 6 0` | 请求指定轴零速度 | 仍发送使能；不能冒充停止/到位反馈 |

这四类是裸诊断入口，发送普通有线ASCII行，不声称支持&zpos/&test。需要指定轴可靠停止/工作零点时先接统一arm接口。不要拿底盘EN/U/D等命令当机构命令，也不要用这些裸入口串起自动抓放。

## 3. 三个电机任意零点的设计

区分三件事：**软件工作零点、机械端点、设备Flash零点**。用户要求的任意位置置零采用软件工作零点；不自动驱动到硬端、不自动写电机Flash。

- dm：零点保存达妙原始输出轴rad；机械臂显示角=(raw-zero)×方向/传动比，指令角度单位deg。
- 5/6：各自保存zero_count；工作位置mm=(raw_count-zero_count)×反馈毫米/计数比例；该带符号比例可由实测travel_mm/(upper_raw-lower_raw)确定，和控制脉冲/mm分开。机械min/max原始计数独立保存，不被工作零点覆盖。
- 轴停止、收到置零请求之后的新位置样本，并确认稳定后才记录；动作运行中不改坐标。升降停止仍保持使能力矩，不能先失能让负载掉落。
- 改一个轴零点只改该轴，增加该轴zero_revision，并让依赖旧坐标的姿态失效/重新示教。不能把原有XYZ目标默认为新零点下仍有相同物理含义。
- 旋转低高度约束使用物理高度，不能把任意工作z=0当成机构最低点。没有毫米标定时可以记录原始计数零点，但不能宣称可以按mm或叠放高度移动。
- 候选旋转默认范围0～360°；改变零点后要重新确认机械范围/避让角区，不能把这个默认值当无限旋转。
- 首版零点留RAM，重启后重新建立可信参考。保存姿态/比例不意味着掉电后任意原始计数零点仍有效。

现有mark min不是这个新zero功能；现有arm zero也不支持5/6。下一实现要补这两个接口和绝对位置规划，再接示教表。

## 4. 五类基础动作：复用，不每个动作建任务

| 动作 | 主要步骤 | 完成含义 |
| --- | --- | --- |
| OBSERVE | 到CAM_LOCATE，保持机构姿态，等待对应视觉上下文生效 | 相机观察姿态就绪；底盘定位仍由底盘模块完成 |
| WAIT_TARGET | 到PICK_READY，打开夹爪，锁定期望颜色，跟踪进入固定抓取窗口 | 形成一次有效抓取触发，锁存目标和观测 |
| PICK | 按固定PICK路径接近/下降→闭爪→抬离→核实夹持 | 物料确已取到；不是只发了close |
| PLACE | 抬到CARRY→必要退让/转向→指定载台槽或圆环预放位→下降→开爪→抬离→核实放置 | 指定目的位得到物料、夹爪已释放 |
| STOW | 抬升避让→缩回→运输角/运输高度 | 三轴到运输姿态，物料去向已确定，可允许底盘粗导航 |

OBSERVE分CAM_LOCATE和CAM_SCAN两个示教姿态：前者看固定地标/工位，后者看物料抓取点。两者可能数值相同，但语义分开。PICK可先保持在接近抓取高度，缩短触发后的动作耗时；是否可这样放置由实际台面和夹爪间隙确认。

姿态表至少有theta_deg、lift_mm、reach_mm、进出顺序、稳定等待及标定版本：CAM_LOCATE、CAM_SCAN、PICK_READY、PICK_CONTACT、CARRY、TRAY_1/2/3、ROUGH_1/2/3、TEMP_1/2/3、STOW。夹爪开/闭脉宽与载物台槽PWM单独标定，不能在状态分支里写死任意角度。

## 5. 转动原料台：固定点抓取的关键

**采用固定抓取点，不让机械臂一直追着物料做复杂轨迹。** 底盘先定位好，机械臂进入重复可达的PICK_READY，摄像头锁定待抓颜色，等它随原料台经过。赛场原料转盘不默认受本车载物台舵机控制。

但相机看到到点和夹爪实际闭合之间有延迟：图像年龄、UART/调度、下降时间和闭爪时间都会让物料继续转动。因此需要预抓姿态和可调lead_ms；不能看到x/y近0才开始一大段伸出/下降。

首版流程：

```text
CAM_SCAN_READY → TRACK_COLOR → ARM_PICK_READY
  → WAIT_TRIGGER → LATCH_ONE_TARGET → PICK_CONTACT
  → GRIP_CLOSE → LIFT_CLEAR → VERIFY_HELD
  → PLACE_TRAY(slot) → VERIFY_PLACED → ITEM_DONE
```

- 静止观察姿态下标定目标恰好能被夹住的像素点(u_pick,v_pick)，不是默认图像中心。移动摄像头/升降后重新建立观测上下文，不能用旧观察姿态的像素点。
- 相机输出当前目标偏差及有效性；主控从连续同一目标的新观测估计移动方向/速度，或由相机发送已标定的过点触发信息（协议需明确TYPE，不在原MAT里私自塞字节）。
- 以已知lead_ms预测到夹持时的目标位置，判断预测位置是否进入抓取窗口。像素窗口初版可直接调，不要求先做完整3D逆解；未知时延/目标跳变不宣告自动抓取就绪。
- 锁存一次触发后停止“每帧再抓一次”。成功放载台才增加item_index，三个物料完成后才STOW；中间回CAM_SCAN/PICK_READY，不每次整臂收回。
- 同颜色多物料由相机维持同一目标跟踪；拾取后的目标消失/脱离需确认后才能重新武装，不能拿同一物料的重复帧重复计数。
- 自动等料无结果时报告WAIT_TARGET继续等待/人工重试；机械运动失联或执行失败再进入动作错误处理。无夹持/放置传感器时先WAIT_PICK_CONFIRM/WAIT_PLACE_CONFIRM，由串口确认，不把PWM到值当作物料成功。

lead_ms实际对应总触发提前量，标定时需避免把图像年龄重复加两遍；完整实现再分别记录图像年龄、执行等待与夹爪耗时，明确总量。先验证低速/单个物料，再三色连续抓取。

## 6. 工位流程与动作次数

### 物料区：抓3个装载物台

```text
OBSERVE_LOCATE → BASE_ALIGN_DONE → CAM_SCAN_READY
  → 按二维码任务列表选color[i]
  → WAIT_TARGET → PICK_GATE → PLACE_TRAY(slot[i])
  → i++，i<3返回寻找下一个
  → STOW → RAW_BATCH_DONE
```

载物台如果确为3槽旋转机构，PLACE_TRAY内部先转到当前槽；舵机位置到位/稳定后才放。slot/color占用在核实放置后提交，不仅靠发过指令更新。

### 中转/粗加工区：先下料，再取回

当前比赛状态机的ROUGH提示要求“放置、再取回载物台”，因此按两个3物料阶段设计：

```text
OBSERVE_LOCATE → BASE_ALIGN_DONE → FIND_RINGS
  → 3次：PICK_TRAY(slot) → PLACE_ROUGH(color)
  → WAIT_PROCESS_DONE（首版人工确认，后续按比赛设备机制接入）
  → 3次：FIND_ROUGH(color) → PICK_ROUGH(color) → PLACE_TRAY(slot)
  → STOW → ROUGH_BATCH_DONE
```

工位上的物料/圆环是静态对准，不沿用原料转盘的动态等料提前量。先用视觉定位工位/目标，按示教姿态或受控的小量修正定位，再抓/放。如果实际比赛设备流程不同，修改这个工位表；不把加工完成条件猜成固定延时。

### 最终暂放区：第一轮普通放，第二轮同色叠放

```text
OBSERVE_LOCATE → BASE_ALIGN_DONE → FIND_TARGETS
  → 3次：PICK_TRAY(slot) → PLACE_TEMP(color, layer)
  → STOW → TEMP_BATCH_DONE
```

第二层放置目标：`z_place(color,2) = z_place(color,1) + measured_material_height_mm`。theta和reach先复用第一层同色姿态，下降路径及预放高度也随层高调整；厚度/公差导致需要修正时再标定。向上的Z正方向下加高度是正确的，不把升降倒置的电机原始符号直接代入。

第二层观察也要匹配目标平面：可示教对应STACK_OBSERVE，或选第二层的相机标定模型。第一层物料会遮挡底部圆环时，使用已确认的第一层同色物料作局部对齐目标，不把它当固定地图地标。8字节SET草案当前没有层数/目标平面高度字段；实施时需补一个明确的8字节配置TYPE或等价的双方已知观察姿态配置，不能私占保留位或只改下降高度却沿用错误毫米换算。

把每个物料的一次PICK→PLACE视为一笔转移：每轮raw3笔、rough放3+取回3共6笔、temp3笔，合计12笔；两轮24笔，即24次抓取、24次放置。五种基础动作被重复调用，不是24个线程或24份重复代码。

## 7. 状态机、任务和请求接口

```text
MatchControl（工位/批次）
  → ArmRoutine（3物料、源/目的、层数）
      → ArmAction（观察/等料/抓/放/收回）
          → 单轴驱动 + 夹爪/载台PWM
VisionTask → 观测事件 → ArmRoutine/底盘定位模块
CAN2反馈/发送结果 → ArmTask
ArmTask → 一次DONE/FAILED + request_id → MatchControl
```

- 继续复用10ms ArmTask；每轮处理队列、驱动服务、标定、舵机Update和一个状态推进。一次动作只在状态入口发命令，轮询等待结果，不while等反馈，不用阻塞延时拼整套抓放。
- 内部可以用IDLE/ISSUE/WAIT_AXIS/WAIT_SERVO/WAIT_VISION/WAIT_CONFIRM/DONE/FAILED；工位流程另存station、batch、item_index、phase、color_order和tray占用。
- 每个请求含uint32 request_id、动作、station、batch、color、slot/layer、姿态和零点版本。相机4位SEQ不是机械动作编号；旧/重复结果不推进下一物料。
- 每轴完成需发命令后的新状态/位置，达妙用实际角/速度及新反馈，步进用到位状态和实际位置。舵机等待PWM斜坡+实测稳定时间；夹持/放置另有确认策略。
- 底盘负责视觉平移/航向纠偏，机械臂先保持已知观察姿态，定位完成事件后再抓。粗导航仅在ARM_TRAVEL_READY后开始；不能在夹取时自动depart/goto。
- 本次已设计的8字节协议用相机上下文和数据年龄关联目标；当前MAT原始打印不能直接作为动作输入，需先实施新协议或明确临时MAT解析方案。
- 失败保留holding/库存不确定状态，不自动开爪、清零或跳到下一颜色；再由操作者决定重试/回收。原导航的手工ok联调模式先保留，自动工位完成回报在机械动作验证后才替代它。

## 8. 推荐落地顺序

1. 接入三轴/舵机模块、CAN/UART队列和停止路径；验证单轴正反、使能和实际反馈。先不接自动比赛。
2. 实现arm zero dm/5/6、绝对位置与pose save/go/list；示教开闭脉宽、观察、固定抓取、载台3槽、工位放置、运输姿态。
3. 实现单次PICK/PLACE/STOW状态机，通过串口逐个验证；没有物料反馈先人工confirm。
4. 实施相机协议和固定点等待、lead_ms；原料台转动时抓一个，再三物料循环。
5. 接粗加工“放3+取回3”和第一层最终放置。
6. 设置实测物料高度，验证第二层同色叠放，再由MatchControl串起两轮。

首版不需要另建机械爪任务或完整机器人逆运动学求解器；固定点、示教姿态表和统一PICK/PLACE模板足以表达这些流程。缺失的实机参数由示教/测量填入，不靠源码默认角度猜测。

# 串口步进比赛状态机

这是整车联调模式：只自动控制底盘去各区域，扫码、显示任务码、颜色/圆环定位和所有取放料暂由操作者完成/确认。`ok` 是人工确认，不会启动机械臂或伪造视觉结果。流程顺序依据项目规则提取正文 `sim/docs/rules_text.txt` 中的初赛搬运流程。

## 操作

UART4：9600、8N1，每条指令单独发送并带CRLF。也支持蓝牙`&`形式300 ms空闲派发。新命令均支持不带`&`的串口形式。

1. 将车摆回对应始停区，车头朝场内。
2. 发送 `&startpose 1`（右下区）或 `&startpose 2`（右上区）。
3. 保持静止约3秒，等 `[IMU] zero-drift ready`。
4. 发送 `&depart`。会在需要时提交底盘使能，再检查四轮位置反馈，执行`leave`，确认轮子有运动后自动规划到`qr`。
5. 看到`[MATCH] WAIT_OK QR`，确认二维码步骤完成后发送一个新的`&ok`。
6. 后续每次到站，按提示完成人工动作，再发送一次新的`&ok`。

完整流程：

```text
startpose N → depart → leave → qr
  ok → raw（第一批）
  ok → rough（第一批）
  ok → temp（第一批）
  ok → raw（第二批）
  ok → rough（第二批）
  ok → temp（第二批码垛）
  ok → h1/h2（出发时选择的始停区）→ FINISHED
```

| 等待点 | 这次ok确认什么 | 下一站 |
| --- | --- | --- |
| QR | 人工确认扫码与任务码显示步骤完成 | 第一批原料区 |
| RAW_BATCH1 | 第一批物料按顺序逐个抓取并放上载物台；机构处于运输姿态 | 粗加工区 |
| ROUGH_BATCH1 | 第一批按任务码放置，随后按顺序取回并重新装台；机构已收回 | 暂存区 |
| TEMP_BATCH1 | 第一批已放置到暂存区 | 第二批原料区 |
| RAW_BATCH2 | 第二批已按顺序装台；机构已收回 | 粗加工区 |
| ROUGH_BATCH2 | 第二批放置并取回重新装台；机构已收回 | 暂存区 |
| TEMP_BATCH2 | 第二批已在第一批正确物料上完成同色码垛 | 原始始停区 |

当前每个区域使用已有中间接近点`raw/rough/temp`，不按任务码自动切换六个圆环，也不移动物料。需要分孔定位/视觉纠偏后，可替换动作适配层，主流程不必按每个圆环重新创建线程。

返场左右按实际航向计算：右上区出发车头朝下时，出区为前进、右移；返场最后一段车头已朝上时，地图上向右进区应为车体右移。`nav_frame.c`将发车零航向参考叠加当前IMU航向后转换到车体系，避免转180°后仍按发车朝向选左移。短横移和车道居中共用该转换；未与横移方向正交时先由导航对准。横移里程投影同时按四轮交替符号计算，避免将其当成四轮同向直行而相消。

`goto h1/h2`返场与手动`home`有区别：本状态机仍按地图到原始停区；手动home是固定逆出区动作，要求车头恢复对应发车朝向，不应在车头朝外时直接调用。

## 状态、停止和重跑

- `&match status`：显示当前状态、等待点、锁定始停区和动作请求编号。
- `&match help`：显示命令列表。
- `&STOP`或串口`stop`：停止并中止当前流程；`&dis/&off`也会中止。
- `&match reset`：显式调试复位并清除始停区确认。重新摆车、发送`startpose N`、等IMU标定，再`depart`。
- `FINISHED/FAULT`时不会自动重启；需要显式reset。
- 行驶中处理到的`ok`会被拒绝，不存成下一站确认。自定义串口事件保留最后一个命令字符的处理时间，避免300 ms空闲派发把已过期的确认变成新确认；仍应等到WAIT_OK提示后人工逐条发送，不用周期自动发送。
- 流程活动期间禁止另发`goto/leave/home/nudge/pose`等底盘命令或改变起点，避免两个流程争抢底盘；只用`ok`推进，停止命令始终保留。

此模式是用户要求的串口联调流程。正式比赛的一键启动、自动任务码校验和动作确认需在后续替换人工入口；本版本不把串口人工确认视为自主比赛流程已经实现。

## 完成与失败的判定

- 请求带递增编号；旧动作回报、重复回报和reset前回报不能推进新流程。
- 出区前后都查询四轮位置；全部有效且每轮检测到超过10 mm的编码器等效变化才继续去QR。这是避免“完全没动却计时完成”的最低检查，不是精确位姿或真实地面位移验证。
- 串口联调导航仍要求本次四轮位置查询齐全，但删除四轮spread超过30mm停机判断；spread只打印。航向保持会主动让左右轮速度不同，累计差不能直接当作反馈故障。
- 删除比赛流程中段末20 RPM、最多3次的低速补走。平移开始时直接按 `D_command = D_nominal × (1+dcomp)` 计算行驶时间，一次连续行驶；默认dcomp=0.10。地图目标和编码器对照目标仍是原计划距离。适用于速度/时间直行、横移及leave/nudge脚本；0xFD位置模式和转向/圆弧本身不使用此补偿。
- 残差超过20mm只打印供调参，不再因到点距离残差进入FAULT，也不自动前后补走。WAIT_OK表示本次行驶执行完毕，实际是否对准工位由操作者确认。无运动（少于原段长25%）、反向和无效反馈仍FAULT。
- 停稳采样要求软件下发轮速归零，两次编码器变化小于0.5mm等效距离；至少间隔20ms，停稳超时仍FAULT。
- 出区最多15秒，每段导航最多120秒。等待人工ok没有自动超时，便于调试取放料。
- CAN进入Bus-Off/错误被动、控制发送失败、规划失败、动作超时或停止都会进入FAULT，并取消待执行出区/导航。
- 继承现有栅格与里程导航误差，位姿仍含计划累积；没有增加视觉重定位或随机障碍物识别。工位坐标按实车确认后再跑完整场地。

## 线性补偿调参

当前日志1700mm段约走1556mm、1750mm段约走1599mm，估计需要增加约9%~10%。先使用10%作为试调值：

```text
&dcomp 0.10
&nav
&save
```

1000mm预先多算100mm，1700mm预先多算170mm；`&dcomp 0.08`改为8%，`&dcomp 0`关闭，范围-0.30~0.30。尚未够就增大，走过头就减小，可每次改0.01~0.02。先保持spd和t1000不变，仅调dcomp，避免同时重复放大。停住或WAIT_OK时可改；行驶中拒绝改变dcomp。

这是加在距离上的比例，补偿距离先进入现有加减速时间规划，因此时间增加比例不严格等于距离比例。直行/横移日志中的`cmd=...mm`显示补偿后的规划输入，`residual`仍相对原目标打印。参数版本升级为v5；有效v4记录自动保留原spd、t1000、cnt和转向/圆弧参数，新增dcomp默认0.10，发送save后保存为v5；不会在加载时自动擦写Flash。

用户随后确认偏差来自原料区→粗加工区去程短走，因此已撤销粗加工区→暂存区第一段减30mm。现在只给两批原料区→粗加工区的第一段向南直行预先多算50mm，作为待实车验证的起始调参量：`D_command = D_nominal × (1+dcomp) + 50mm`；例如1700mm、dcomp=0.10时，从1870mm增加到1920mm。返程和其他路线继续按原dcomp执行。增量在`Core/Src/zdt_motor.c`的`ZDT_NAV_RAW_ROUGH_EXTRA_MM`修改，设0关闭，改后重新编译烧录；这是源码参数，不随save/read写入Flash。触发时按等待点名称打印总增量，例如`ROUGH_BATCH1: extra 50mm after dcomp`（1区另加点位增量）。仅在比赛流程速度/时间模式、无圆弧的相应直行段启用。软件位置仍按名义目标推进，调参时应先确认去程实车真正到粗加工接近点，再观察返程经过中间的位置。

两次前往原料区（QR→RAW_BATCH1、TEMP_BATCH1→RAW_BATCH2）的最后一段向北直行额外多算30mm，计算为`D_command = D_nominal × (1+dcomp) + 30mm`；只用于最后接近原料区的一段，中间转弯前的段不增加。源码参数为`ZDT_NAV_RAW_APPROACH_EXTRA_MM`，修改后重新编译烧录；这与原料区→粗加工区的50mm增量分别作用于各自路线，均在dcomp之后加入，不执行段末低速补走。触发日志按等待点名称打印总增量，例如`RAW_BATCH1: extra 30mm after dcomp`（1区另加点位增量）。

车体碰撞模型按实车280×280mm设置，半宽140mm，旋转外接圆半径约198mm；启停区仍为300×300mm。固件轴对齐通行检查和旋转碰撞检查共用GRID_NAV_CAR_MM。400mm直通道中精确居中的车体可在理想几何下旋转，45°占宽约396mm、每侧仅约2mm余量；不能据此默认允许有定位偏差的边走边转。

1区出发的比赛流程另外给每个非QR目标点位的最后接近段再加30mm，包括两批raw/rough/temp和返场h1。中间路径段及leave不加；2区仍沿用原参数。该增量在dcomp之后与已有增量叠加：通常1区到物料区最后一段为原30+新30=60mm，物料区→粗加工区1700mm单段为原50+新30=80mm，暂存区和返场最后一段各加30mm。最后一段若为短横移也加，避免只延长前进而漏掉返场横移。源码参数为`ZDT_NAV_ZONE1_POINT_EXTRA_MM`，设0关闭，修改后重新编译烧录；不写入Flash。日志显示`zone1 point 30mm`或`zone1 point extra 30mm ... (strafe)`。不改变地图目标，不启动段末低速补走。

## 工位末端起步混合运动（已回退，以下为历史实现）

按用户最新要求，已禁用边转头边移动：编译开关为0，`&endturn 1`也只回复disabled，不再开启。当前仍采用停车转向、前进运输；保持目标航向的小幅纠偏继续工作。2区左侧机械臂到站朝向、左下/左上外圈选路另见《2号区_左侧机械臂到站朝向与外圈路线方案.md》，已自动用于startpose 2比赛路线。以下内容仅记录此前实验实现和可复用底层，不是当前启用功能。

当前只用于比赛流程每次导航的第一段，软件位姿靠近raw/rough/temp/qr接近点（两轴均相差不超过50mm）、速度模式、tarc=0、需要转头至少15°时才尝试。不是工位附近则照常原地转头。建议在到达工位的WAIT_OK发送endturn 1，再发新的ok观察该次起步，验证后再扩展。

起步窗口最多300mm、最少75mm，每次缩短25mm尝试；至少保留100mm后续直行。窗口是平移的上限，不是必须走完的目标：转头完成且已离开起点后即可停稳，减去实测已走距离并继续剩余直行；若先到窗口末端，则在该处转完最终角度。旋转目标始终为本段最终朝向，取消原来“平移进度决定中间目标角度”的绑定，避免只对准一半角度就停留。

几何预检查按5mm位置、3°角度采样。转头阶段每个位置检查整个转角范围（包括原地继续转头及±3°余量），车体每边扩展10mm，包含场边、黄区、工位台面和动态障碍。工位台面前若直接旋转空间不足，先按当前朝向保持姿态向路线方向平移40mm，再开始转头；该退让段也检查±15°航向范围。仍无可用窗口则打印endturn skipped并走原地转头。实际执行周期检查估计位姿的车体占用。

控制周期20ms。平移上限使用当前spd（例如0.30约320mm/s、0.35约373mm/s），转向使用普通快速档的120 RPM轮速上限、当前kp/ki/kd和同一最小推力，不再限为85mm/s。接近窗口上限按制动距离提前减速，并为转动和车体速度分解预留轮速斜坡余量；四轮合成超上限时仍统一缩放，短窗口不能保证全过程同时保持两个满速。

混合模式新增整车场地坐标斜坡chassis_field.c/.h：在原底盘4ms发送循环里对地图平移向量与旋转分量作联动规划，每一帧按最新IMU角度重新换算四轮速度。轮速增量取共同插值比例，避免每轮独立减速/先停零再换向把原本的直线合成成弧线；四轮饱和仍统一缩放。该模式不再叠加旧的独立单轮斜坡；普通直行、原地转向仍使用原斜坡。进入混合模式要求软件轮速已归零，并重置发送时钟，避免空闲时间被算成一次大加速。STOP把整车速度目标清零，沿此斜坡停车；故障或取消立即发送停止。混合期间非停止类调参/诊断命令被丢弃，提示延后到停稳输出，防止9600波特率阻塞日志破坏4ms节拍；STOP、dis、off、disable及match reset仍立即处理。无效或单次突变超过12°的IMU角度会停止而不是重新投影运动中的车体速度。新增静态整车状态约64字节，无新任务或动态分配。

四轮位置每20ms异步查询，消除自转分量后结合IMU中点角度解算沿线位移、横向偏差及其滤波速度。使用横向位置+横向速度反馈纠偏，上限为当前平移速度的一半；使用沿线速度反馈抑制转向期间的残余前进量。即使沿线前进已结束，也继续修正横向误差；结束要求横向偏差不超过8mm、沿线及横向速度估计均低于15mm/s，停稳后二次校验不超过10mm。30mm横向硬门槛和10mm几何余量保留。每4ms更新场地坐标转换后不再给20ms控制命令加80ms角度预测。

超过60ms未更新轮子位置时暂停平移；超过400ms、缺轮反馈、IMU超过150ms未更新、发送失败、编码器跳变、反向超过10mm、超过窗口15mm、实际姿态碰撞或总时长超过15s均停止。2s无位置、航向或横向误差改善时明确FAULT。各类失败拆分原因并打印BLEND diag。故障在串口日志之前立即提交四轮底盘停止，避免阻塞打印期间延续旧速度；整车STOP仍包括机械臂急停。

窗口结束停稳后，使用停稳四轮基准继续该段剩余直行；只减去实测已走的窗口距离，地图位姿在整段末仍按原名义路径推进。窗口使用编码器闭环，不加dcomp；剩余普通直行仍加dcomp和已有点位固定增量，各增量只执行一次。本版本保留窗口结束的停稳；尚未实现全过程无停车。

日志：新版以BLEND field开头，便于确认烧录了整车斜坡版本，显示窗口长度、开始/最终航向、retreat距离、当前spd和turncap=120RPM；BLEND done显示实测进度、横向偏差和剩余距离。nav_blend.c/.h运行于原ZDT任务，无动态分配。角度完成、常速平移、实际4ms整车联动斜坡、普通单轮斜坡保留、正反90/180°、短窗口、QR→原料区向西首段和几何回退均有软件回归。用户2026-10-03旧日志明确在RAW_BATCH1→ROUGH_BATCH1触发合并的cross-track/reverse/overshoot故障，未打印具体值，因此不能断言当次是哪一项。新版本需重新编译烧录后实车验证，几何仍依赖软件起点与地图，编码器受滑移影响，尚未实现视觉重定位。

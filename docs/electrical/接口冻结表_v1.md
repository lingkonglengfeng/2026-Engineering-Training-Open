## 1. 生效规则

1. 工程根目录的 `Engineering_Training_Project.ioc` 及其生成的 `Core/Src` 是“当前实际配置”的事实源。
2. 本表用于阶段 0 的跨组约定：硬件、电控、视觉、机械确认后才能进入联调。
3. 任何修改必须更新本表版本号、日期、变更原因和批准人。
4. 引脚、电源极性、安全输入、通信协议在没有书面变更前不得改动。
5. 未标“已确认”的项仍然按草案执行联调准备，但不允许作为最终比赛配置。

状态定义：

| 状态 | 含义 |
|---|---|
| 已配置 | 根目录 `.ioc` 已经生成对应初始化代码 |
| 待实物确认 | 文档和代码已确定，需要与原理图/接线再次核对 |
| 待实现 | CubeMX 引脚已定或方向明确，但协议帧、控制参数还冻结不足 |
| 预留 | 当前不使用，不允许临时占用 |

### 3.2 设备层动作接口

底层驱动向上提供以下语义；应用状态机不得直接操作 HAL/FDCAN 寄存器：

| 接口 | 语义 |
|---|---|
| `enable()` | 使能电机/驱动器，返回统一结果码 |
| `set_velocity()` | 设置四轮目标速度；内部包含限幅和斜坡 |
| `set_position()` | 设置短距离位移目标；带超时和到位误差阈值 |
| `stop_immediate()` | 立即停止输出，安全态必须可调用 |
| `read_status()` | 读取在线、故障字、温度、电流和最近心跳时间 |

|---|---|---|---|---|---|---|---|
| USART1 | PB14=TX，PB15=RX | 主控 ↔ MaxiCAM #1 | 115200 8N1 | 二维码识别 | ASCII 统一帧，见第 8 节 | 电控 + 视觉 | 引脚已配置，DMA 协议待实现 |
| USART2 | PA2=TX，PA3=RX | 主控 ↔ MaxiCAM #2 | 115200 8N1 | 视觉避障/颜色/圆环 | ASCII 统一帧，见第 8 节 | 电控 + 视觉 | 引脚已配置，DMA 协议待实现 |
| USART3 | PB10=TX，PB11=RX | 主控 ↔ 屏幕设备 | 115200 8N1 | 陶晶驰串口屏预留 | 触摸反馈运行状态、任务码、统计和故障码 | 电控 + 硬件 | 引脚已配置，页面协议待定 |
| UART4 | PC10=TX，PC11=RX | 主控 ↔ JDY-23 | 9600 8N1 | 蓝牙按钮/调试日志 | 七路按钮指令及日志 | 电控 | 引脚已配置 |
| USART10 | PE2=RX，PE3=TX | 主控 ↔ HWT101 TTL | 115200 8N1 | 姿态传感器 | WIT 标准 `0x55 ...` 帧；模块实际波特率必须先用工具核实 | 电控 | 引脚已配置，模块配置待实物确认 |

> 注（2026-08-30）：底部拓展板上**两个视觉模块座为 PH2.0-4P**（WAFER-PH2.0-4PZZ，板上已焊），全车其余信号座为 XH2.54；相机线束按 PH2.0-4P 配置，属全车唯一例外。

接收策略：

1. USART1、USART2、USART10 最终采用 DMA + IDLE 或环形缓冲；ISR 只搬字节并唤醒解析任务。
2. ISR 内禁止浮点计算、解析完整协议帧、直接调用阻塞 HAL。
3. 所有接收链路必须有字节超时、帧校验错误计数、重复序号计数和丢包计数。

显示内容契约：

| 显示项 | 最小刷新要求 |
|---|---|
| 当前状态机阶段 | 状态变化后立即刷新 |
| 任务码原文/解析结果 | READ_TASK 成功或失败后刷新 |

### 6.1 PWM 输出

|---|---|---|---|---|---|---|---|
| SERVO_GRIP | PD12 | TIM4_CH1，AF2 | 50 Hz | 500–2500 μs，具体角度零位待机械标定 | 物料抓取舵机 DS3218 | 机械 + 电控 | 引脚已配置，50Hz 参数待复核 |
| SERVO_TURNTABLE | PD13 | TIM4_CH2，AF2 | 50 Hz | 按转盘机械结构和行程冻结后写入参数表 | 转盘舵机 | 机械 + 电控 | 引脚已配置，50Hz 参数待复核 |

规则：

1. 舵机角度最大变化率和软启动值由参数模块限制。
2. SAFE_STOP 时禁止新增夹取/放置动作；已处于危险持料状态时由人工确认处理。
3. 所有零位、正方向、极限角必须在整车上重新标定，不能沿用其他车身参数。

|---|---|---|---:|---|---|---|

| STOP / ESTOP | PA1 | 上拉输入，EXTI1 下降沿触发 | 中断置位 + SafetyTask 去抖确认 | 进入安全停机 | 电控 + 硬件 | 已配置，拓展板按键位 CN3，需实物确认 |
| ~~MODE~~ | ~~PA8~~ | — | — | ~~模式切换~~ | 电控 | **已取消（v1.2）**，PA8 释放为空闲 GPIO |
| ~~DEBUG~~ | ~~PA10~~ | — | — | ~~调试按键~~ | 电控 | **已取消（v1.2）**，PA10 释放为空闲 GPIO |

安全约束：

1. 急停 ISR 只设置事件位/标志，不在 ISR 内做长流程和可能阻塞的 HAL 操作。
2. 急停必须直接触发 SAFE_STOP 并禁止普通任务继续输出运动目标。
3. START 一旦消费成功即锁存；复活、重跑必须按赛前授权流程清空状态。

### 6.3 LED 输出（v1.2 全部取消）

原 PWR/RUN/ERR/COM 四路 LED（PD0~PD3）输出**全部取消**；电源/运行/故障/通信状态改由陶晶驰串口屏与 UART4 日志呈现。PD0/PD3 释放为空闲 GPIO。

### 6.4 补光灯 PWM 控制（v1.2 新增，v1.3 定案）

| 信号 | STM32 引脚 | 实现方式 | 用途 | Owner | 状态 |
|---|---|---|---|---|---|
| LIGHT_PWM1 | PD1 | 软件 PWM（**已定案**） | 补光灯亮度调节/开关 | 电控 | 驱动已实现（`light.c`），调光参数待标定 |
| LIGHT_PWM2 | PD2 | 软件 PWM（**已定案**） | 补光灯第二通道或备用 | 电控 | 同上 |

定案说明（v1.3）：

1. 实现方式**定案为软件 PWM**：TIM6 更新中断 16kHz × 16 级灰度 ≈ 1kHz 调光，CPU 占用 <0.5%，放弃 PB0/PB1 飞线方案；
2. **补光灯供电定案为 3.3V 直驱**：PD1/PD2 高电平=导通，限流电阻由灯侧处理；单通道电流超过 GPIO 20mA 上限时在灯侧加三极管/MOS，驱动极性不变；
3. 驱动代码已落地：`Core/Inc/light.h` + `Core/Src/light.c`（Light_Init / Light_SetDuty / Light_On / Light_Off），默认灯灭启动，输出由 TIM6 中断维持、无需任务刷新；
4. 原 12V 轨与 NMOS 驱动模块方案作废，采购清单已同步取消；
5. 调光参数（默认亮度、渐变斜率）待灯光实测后写入参数模块。

## 8. 视觉与二维码通信协议

本节为 ASCII 协议 v1。方向均为主控接收帧；主控可回复 ACK/NACK，具体回执字段由视觉与电控在下一小版本补充。

### 8.1 通用帧规则

```text
@TYPE,<field>=<value>[,...],seq=<n>*<CS>\r\n
```

| 项目 | 冻结值 / 目标 |
|---|---|
| 字符集 | 可打印 ASCII |
| 行结束符 | `\r\n` |
| 最大帧长 | 128 bytes，超过立即丢弃并计错 |
| 序号 | `seq` 从 0 开始递增，模 65536 |
| 校验 | `CS` 为 `@` 后到 `*` 前所有字节的 XOR-8，两位大写十六进制 |
| 时间戳 | 主控收到帧时记录本地 tick，不代表视觉端发送绝对时间 |
| 数据有效性 | 只有 `valid=1` 且置信度达到当次动作阈值的帧可用于闭环动作 |
| 旧数据 | 每类数据都要记录接收时间；动作允许的最大数据年龄按状态单独设定 |

### 8.2 必须支持的四类帧

| 类型 | 示例 | 语义 |
|---|---|---|
| `QR` | `@QR,156+123+516+231,seq=12*71\r\n` | 二维码任务码；每组 3 位数字，共 4 组 |
| `RING` | `@RING,id=3,x=12.4,y=-1.8,theta=0.6,conf=0.94,seq=21*09\r\n` | 圆环相对坐标和朝向 |
| `COLOR` | `@COLOR,id=2,color=6,conf=0.91,seq=22*5C\r\n` | 物料颜色编号与置信度 |
| `OBS` | `@OBS,front=400,left=9999,right=250,valid=1,seq=23*77\r\n` | 障碍物距离；`9999` 表示无目标/无效测距，最终仍以 `valid` 为准 |

### 8.3 数字与坐标约定

| 项目 | 暂定冻结值 | 待确认点 |
|---|---|---|
| 颜色编号 | 1=红，2=黄，3=蓝，4=绿，5=浅蓝，6=黑 | 以正式规则页颜色命名为准 |
| 圆环编号 | 1–6 | 与第二批圆环一一对应 |
| 平面坐标系 | 以机器人前进为 X 正方向，左侧为 Y 正方向 | 视觉相机安装方向换算由视觉侧完成后复核 |
| 长度单位 | 毫米 `mm` | 视觉输出是否已经转换为地面平面坐标 |
| 角度单位 | 弧度 `rad`，逆时针为正 | 是否与整车航向角方向一致 |
| `OBS` 单位 | 毫米 `mm`，`9999` 表示无效/无目标 | 三路数值的实际安装角度和盲区 |

## 9. 任务码解析契约

任务码示例仍以规划中的：

```text
156+123+516+231
```

作为标准输入形态。

| 校验项 | 冻结规则 |
|---|---|
| 组数 | 恰好 4 组 |
| 每组长度 | 恰好 3 个十进制字符 |
| 字符范围 | 每个字符必须是 `1` 到 `6` |
| 分隔符 | 3 个英文加号 `+` |
| 缓冲区结束 | 必须 NUL 结尾，禁止无界拷贝 |
| 非法输入 | 长度错、缺分隔符、越界编号、不完整帧都返回 `TASK_PARSE_ERROR` |
| 成功输出 | 保存规范化字符串，同时输出颜色数组、圆环数组和序号 |
| 显示更新 | 解析成功或失败都必须发送显示事件 |

## 10. 动作原语接口

所有动作对象至少暴露四个操作，供比赛状态机调度：

| 操作 | 语义 |
|---|---|
| `start` | 提交目标并开始执行；同一执行器同一时刻只允许一个活动动作 |
| `poll` | 查询 running/succeeded/failed/cancelled |
| `cancel` | 请求取消；执行器内部收敛到安全保持态 |
| `timeout/result` | 返回耗时、错误码和最小必要观测值 |

动作家族：

| 家族 | 必要子动作 |
|---|---|
| chassis | 直行、横移/旋转、路径点到点、避障降速、原地回站 |
| turntable | 转盘到取料位、到位保持、异常回零 |
| gripper | 张开、闭合抓取、释放、负载保持 |
| arm | 抬升/下降、伸出/收回、辅助对位、快速收回 |
| place | 普通放置、粗加工区放置、暂存区码垛、第二遍叠放颜色校验 |

每个动作都必须登记：目标值、容差、加速度/速度上限、最长允许时间、成功判定源、失败转移和取消后的保持策略。

## 11. 状态机边界

阶段 0 先冻结以下顶层状态名：

```text
BOOT -> SELF_TEST -> WAIT_START -> READ_TASK
-> FIRST_PICK_1 -> FIRST_PICK_2 -> FIRST_PICK_3
-> FIRST_PLACE_PROCESSING -> MOVE_TEMP_STORAGE
-> RETURN_RAW_MATERIAL
-> SECOND_PICK_1 -> SECOND_PICK_2 -> SECOND_PICK_3
-> SECOND_PLACE_PROCESSING -> STACK_TEMP_STORAGE
-> RETURN_START -> FINISH
SAFE_STOP 可从任意运行态进入
```

冻结原则：

1. 只有 MatchTask/比赛状态机能推进比赛阶段。
2. 任何状态必须有进入动作、持续条件、成功条件、失败条件和超时。
3. 设备驱动可以报告故障，但只有 SafetyTask 锁存统一故障位。
4. `READ_TASK` 未得到合法任务码前不得抓取物料。
5. 第二遍码垛放置前必须检查颜色一致；不一致进入 `STACK_COLOR_MISMATCH` 故障态。

## 12. 统一故障码和安全态

| 故障码 | 来源 | 是否锁存 | SAFE_STOP 要求 |
|---|---|---|---|
| `ESTOP` | STOP 按键 | 是 | 立即停电机，禁危险舵机/机械臂动作，故障码上屏+日志（LED 已取消） |
| `CAN_TIMEOUT` | FDCAN1/FDCAN2 心跳或回包超时 | 是 | 发送目标清零/急停命令；显示对应 CAN 编号 |
| `VISION_TIMEOUT` | 二维码/圆环/颜色数据年龄超限 | 按状态配置 | 不允许使用旧定位数据推进动作 |
| `MOTOR_FAULT` | 驱动器报堵转、过流、过热、离线 | 是 | 停止对应总线目标并请求安全刹车 |
| `LIMIT_HIT` | 限位/边界触发 | 是 | 反向退出动作只能由人工授权启用 |
| `PAYLOAD_MISSING` | 抓取后载物台无物料确认 | 是 | 禁止继续带料流程 |
| `STACK_COLOR_MISMATCH` | 第二遍码垛颜色不一致 | 是 | 禁止盲放，进入人工/裁判可辨识的故障态 |
| `TASK_PARSE_ERROR` | QR 帧非法 | 是 | 回到合法读码流程，不清除故障历史 |
| `WATCHDOG_NOT_READY` | 喂狗前置条件未满足 | 是 | 记录最后安全快照后受控复位前尝试停机 |

进入 SAFE_STOP 的顺序：

```text
1. 清除/锁定运动目标；
2. 向底盘和相关执行器发送停止或急停；
3. 禁止新的舵机、机械臂危险动作；
4. 故障状态上屏 + UART4 日志（LED 输出已取消）；
5. 显示/记录故障码和关键快照；
6. 等待人工确认复位。
```

## 13. RTOS 对象契约

| 对象 | 类型 | 生产者 → 消费者 | 冻结论点 |
|---|---|---|---|
| `q_vision_rx` | Queue | UART/CAN ISR → PerceptionTask | 有边界队列；满队列丢弃旧帧并计数 |
| `q_cmd_motion` | Queue/通知 | Match/Motion → ControlTask | 只保留最新目标或显式序列号 |
| `q_actuator` | Queue | MatchTask → ActuatorTask | 每个动作携带超时、取消令牌 |
| `q_display` | Queue | 各服务 → DisplayTask | 低优先级，重复项可合并 |
| `q_can_tx` | Queue | 领域层 → CommsTask | 同一总线发送入口单一所有权 |
| `eg_system` | EventGroup | ISR/任务 → Safety/Match | 至少包含 START/STOP/FAULT/READY/ESTOP |
| `sem_control_tick` | 通知/CountingSemaphore | TIMx ISR → ControlTask | ISR 只发节拍，不做浮点和总线访问 |
| `mtx_params` | Mutex | 参数服务 ↔ 显示/遥测 | 更新参数用快照，禁止持锁写慢速串口 |

任务优先级以架构文档为基础：安全/控制任务高于流程任务，显示和遥测最低。栈尺寸首版只作初始值，必须用 `uxTaskGetStackHighWaterMark()` 实测后收敛。

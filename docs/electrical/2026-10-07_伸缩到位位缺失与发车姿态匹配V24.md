# V24：伸缩到位位缺失的测量确认，发车姿态匹配诊断

03:30日志是两个独立事件：

1. arm camera收到原生FD接受ACK02，6号停在-54545counts、41.1290%，目标41.1805%，差约0.0515%（约0.092mm、0.38deg）。flags81表示使能、无堵转/保护，但没有REACHED位。旧判断即使位置稳定也坚持等该位，10秒后超时。日志只给出超时瞬间，稳定性由新版本实时多帧验证，不用单帧假定停稳。
2. depart已通过准备入口并投递ARM任务；随后ARM START报告no matching saved pose。这表示保存记录不存在或零点/行程/方向/IDs等不匹配，不能只凭这句断定是哪一个字段。之前切换DM内部零点会令旧软件参考记录不匹配。V24增加saved、当前/保存DM参考、5/6参考和行程/方向输出，明确下一次失败的字段。

## 缺失REACHED位时的安全确认

仍要求目标误差在原0.5%容差内、位置及状态均为新鲜反馈、使能且无堵转/保护，至少3组新数据且稳定200ms。若驱动器没有到位位，先发送伸缩STOP（保留使能），清空稳定样本，要求STOP后的新位置/状态再次满足目标与稳定条件，才认定到位。停车验证限时2秒。

不把ACK02当到位，不放宽位置容差；拒绝回包、无ACK且无运动、反向、明显过冲、失能、堵转、保护或陈旧反馈仍故障。已有REACHED位正常时保留原到位流程。

## 发车姿态需录入一次

DM内部零点正确后，把机械臂摆回你希望的发车姿态，例如原日志5号约-43.37deg、6号约-279.44deg，DM也摆到希望的发车角度。当前camera状态是近乎全展开，不能直接把它误录为折叠发车姿态。

确认底盘已失能，机构静止：

```
&arm stop
&dm off
&arm start save
&arm start status
```

先等SAVED，再查询status；保持机构静止录入。当前已在FAULT准备流程里底盘已失能；如果并未失能，需先处理底盘状态并取消运行中的流程。此过程只记录三轴姿态，不设置DM零点。不要为了重录姿态每次再次dm zero save。

之后使用match reset、startpose、等IMU、depart；等WAIT_START_OK再发送新的OK。保存记录与当前参考不匹配时仍拒绝执行，不从旧零点猜测目标角度。

保持DM内部零点、30/80RPM、CAM2屏蔽、边走边展开及视觉/里程计功能。仅编译、模拟验证，未实际烧录或录入实车姿态。

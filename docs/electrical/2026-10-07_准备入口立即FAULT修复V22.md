# V22：PREPARING后立即FAULT的准备入口修复

03:01日志显示PREPARING之后直接FAULT，没有restore arm launch pose提示，也没有ARM START恢复动作，说明Match启动回调在投递机械臂任务之前拒绝。旧日志缺少拒绝原因，不能精确区分当时是残留转向/运动请求、底盘失能发送失败或其他入口条件；不能据此认定相机或DM零点错误。

V21准备入口发现的缺陷：

- 直接因残留运动需求/转向标记拒绝，而没有先按准备流程清零停机。
- 调用ChassisMotor_Disable会先调用整车EmergencyStop，对DM设置急停故障闩锁；它不适合“停止底盘但接着恢复机械臂”的准备动作。
- 单次CAN发送忙/失败直接REJECTED，且未打印具体原因。

V22增加底盘专用准备失能接口：立即取消底盘转向、清零目标/场地速度并停止/失能四轮，不调用DM急停。原STOP/dis的整车急停语义不变。准备入口使用新接口，即使软件已显示底盘失能也能补发未成功的停止/失能请求；短暂发送问题按100ms间隔重试，最长2秒。成功后保持停止标记，不在ARM忙时反复发送四轮失能。

拒绝会打印navigation/script仍活动、wheels-only disable的HAL/FIFO/CANerr、或ARM请求HAL。真正失败仍进入FAULT，不伪造准备成功。

## 使用

烧录V22并重新上电，按原步骤match reset、startpose 1|2、等IMU、depart。看到恢复机械臂和WAIT_START_OK后，再发送新的OK出库。内部DM零点、已重新录入并匹配内部零点的发车姿态、CAM2屏蔽、30/80RPM、边走边展开和心跳/像素保护保持。

如果之后看到ARM START的无匹配姿态或参考错误，那是已经通过入口、进入实际姿态恢复后的另一项检查：在DM内部零点设置正确后，摆回发车姿态并重新arm start save。当前修复不自动清除真实DM故障、重定义零点或替换姿态。

测试覆盖真实底盘接口清零运动需求/失能四轮且DM急停计数不变、失能BUSY可再次补发，以及实际准备入口的BUSY重试、等待ARM、2秒持续失败和拒绝原因。编译/模拟通过，未实车烧录验证。

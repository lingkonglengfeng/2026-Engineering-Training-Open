# 视觉纠偏诊断版 DIAG_V1

原始工程：`E:\Engineering_Training_Project`。固件：`MDK-ARM/Engineering_Training_Project/Engineering_Training_Project.hex`。

本版添加记录与查询，仍使用原来的100ms脉冲、250ms停稳和新帧确认；增益、视觉速度、导航速度、固定补偿、到站朝向与QR回场均沿用现有配置。相机不需为本次诊断更换协议或重新打包。2026-10-05起视觉自动纠偏和诊断记录均默认ON；无需额外发valign on，原命令可继续用于确保开启。

## 一次采集步骤

1. 烧录本版，开启串口保存日志。相机继续运行当前统一程序，同时保留它的`[SERVICE PERF]`日志。
2. 按正常摆车流程发`&match reset`、`&startpose 1`，等IMU标定完成。在静止时依次发：

```text
&valign on
&valign trace on
&valign status
&nav
&camstat
&depart
```

`trace on`应返回`[VDIAG] DIAG_V1 enabled=1 ...`，用于确认烧录版本。完整`valign status`每站输出3行，含源/ID/增益、容差/速度/脉冲/稳定要求、超时与运动预算，读取实际RAM配置。

3. QR到达`WAIT_OK`，发`&OK`去1号点。圆盘纠偏完成后，等日志显示`WAIT_OK RAW_BATCH1`，先不要发下一次OK。发：

```text
&valign trace dump
```

导出以`[VDIAG] BEGIN`开始、`[VDIAG] END station=1 ...`结束。等END出现，再发`&OK`去2号点。

4. 圆环纠偏完成、显示`WAIT_OK ROUGH_BATCH1`后，重复`&valign trace dump`，等`[VDIAG] END station=2 ...`。把这份完整串口日志与同次相机PERF日志一起提供。可附一段显示车辆与相机画面的现场视频。

记录只保留最近一次工位纠偏，新纠偏开始会重置上一站记录，因此应每站导出后再继续。成功、失败和取消都会冻结已有记录；失败后先等车停稳导出，再复位。不要靠反复reset清除需要分析的日志。

## 命令

| 命令 | 行为 |
| --- | --- |
| `&valign status` | 查询三站实际生效的完整参数 |
| `&valign trace on` / `off` | 启用/关闭后续诊断，独立于自动纠偏开关 |
| `&valign trace status` | 查看开关、冻结状态、工位、条数、溢出数、RAM占用 |
| `&valign trace dump` | 有界逐行导出已冻结记录，可重复导出 |
| `&valign trace cancel` | 取消当前导出，保留记录 |
| `&valign trace clear` | 清记录，保留诊断开关 |

轨迹命令只在底盘无运动任务、无待执行速度、轮速指令归零且陀螺角速度小于等于1.5deg/s时接受。WAIT_OK允许导出，不必等待整场结束。导出中若启动运动，会停止导出，停车后提示中断；没有END的输出不能视为完整文件。命令不会触发底盘移动、相机切换或标定动作。

## 记录含义

控制任务在内存中记录每个看到的新`observation_id`、状态/有效性变化和速度命令变化。即使处于PULSE、还没消费下一帧，诊断也记录该新帧；诊断计数独立于控制计数，重复读取不增加稳定帧数。运动中不格式化或输出轨迹，不分配动态内存；停车后每轮任务至多格式化/发送一行。

固定容量512条，满后保留已有记录，新增事件计入`dropped`；统计和末端信息继续更新。`dropped>0`表示波形不完整，不能据前512条声称已覆盖整个收敛过程。每个BEGIN/END都显示溢出数。关闭诊断会保留上一份冻结记录，需要用station判断是哪一站。

时间统计如下，单位ms；各项相加为记录的整次纠偏阶段时间：

| phase | 名称 | 含义 |
| --- | --- | --- |
| 0 | ACK | 模式握手与等待相机确认 |
| 1 | BASE | 等待初始四轮位置查询 |
| 2 | PULSE | 脉冲输出阶段 |
| 3 | BRAKE | 等待轮速指令归零/角速度变小 |
| 4 | SETTLE | 计时停稳等待 |
| 5 | WAIT | 等合格新观察/停止后的稳定帧确认 |
| 6 | END | 结束后四轮位置查询等收尾 |

阶段耗时按主控采样间隔归属上一阶段，是诊断估计。`tick_max`含握手/查询阶段的主控服务间隔，不等同于相机帧间隔或严格的四轮CAN更新周期。PULSE时间也不是实车行驶时间：有加减速，BRAKE仍可能有平移。

CSV行前缀`VDR`。列名在导出中给出：

- `t_ms`：相对本次诊断开始的主控时间；`obs_id`是本地发布编号。
- `rx_age_ms`：收到/解析后经过时间；4294967295表示当前无观察。**不是曝光年龄**。
- `dx_px,dy_px`：主控可见的像素偏差，已经过接收模块有效性处理。invalid时偏差可能被清零；无新观察的阶段行可能保留上次偏差，必须结合flags解释。
- `F_1e4,R_1e4,O_1e4`：请求的归一化前/右/角速度乘10000，读取后除10000。量化仅用于记录，不影响控制输出。
- `yaw_cdeg,gyro_cdeg_s`：航向/角速度乘100，航向归一化到±180deg。
- `FL_cmd_rpm`等：主控软件已下发轮速，**不是驱动器实测速度**。
- `state`：原控制状态，0=IDLE、1=SETTLE、2=WAIT、3=PULSE、4=DONE、5=FAILED；`stable`是稳定帧计数。

flags位：1=像素valid、2=接收年龄小于200ms、4=相机模式/工位上下文匹配、8=软件轮速归零且角速度小、16=新观察、32=阶段/状态/有效性变化、64=请求速度变化。组合位按相加解释，8不证明实车平移已完全停止。

`frames`只统计主控读到的不同观察，`same_obs_polls`是重复轮询次数，不是相机发了重复包。`rx_gap_max`及5个gap_bins统计这些观察的本地接收时间间隔（<=50/100/200/500ms及>500ms）；不是传感器曝光间隔。`can_enqueue_fail`是本次期间共享FDCAN2的入队失败增量，不只包含某一电机，也不证明HAL_OK帧已实际执行。

`wheel_start/end`保留四轮位置计数和有效mask。有效mask=15才是四轮齐全；端点差是编码器估计净位移，不能当作完整行驶路径或无打滑的地面位移。本版不增加运动中的位置查询、不用诊断补走、不改变现有停稳算法。

这次导出用于决定后续连续P控制的近端减速和延迟预算。两个轴实际20mm位移标定、最低稳定可动轮速与真实采样延迟仍需另行测量，诊断命令不会自动执行这些动作。

# V204：圆盘下降ACK确认与同一绝对目标重发

本版落实用户选定的方案1：**确认下降接收ACK，缺ACK重发同一绝对目标，不增加位置起步或到位等待**。只更新主控固件；上位机继续使用2.5.5，现有相机桥和W25参数无需更新。

## 修复的问题

本轮日志已证实6次圆盘抓取中3次没有下降ACK，闭爪时反馈停在约30.04%等待高度，目标46.653%。V203在CAN发送返回HAL_OK后便开始约539ms计时，没有把“成功入队”与“驱动器接收”区分开，导致缺ACK仍闭爪、抬升和继续放料。

本版修复这条软件衔接路径。它不证明总线或驱动器缺回执的硬件根因已经排除，也不把ACK等同于实物到位或抓住；用户没有选择方案2的起步检测或方案3的完整到位确认。

## 动作时序

1. 目标物料触发后，仍在同一ArmTask轮询中下发下降与伸出20mm，夹爪保持张开。
2. 缓存首次计算的5号绝对脉冲目标、RPM、目标高度及原预计时长，开始监听5号原生FD回执。此时还不启动闭爪计时。
3. 收到本次有效`0x02`接收回执后，从处理确认的当前时刻开始完整预计运动计时，之后闭爪。`0x9F`已完成回执也可作为接收确认，但正常动作不要求等待它。
4. 100ms未获有效确认，仅重发**同一5号绝对目标**；缓存的速度和目标高度也不变。不会重复下发6号20mm伸出，不会把下降变成多次相对累加。
5. 初次加两次补发，最多3次成功入队。补发遇到HAL_BUSY时没有命令入队，间隔100ms再尝试，不消耗成功下发次数；实际CAN发送错误仍沿用原故障处理。
6. 三次仍无有效确认，保持张爪，不闭爪、不开始后续抬升放料，也不伪报完成。可接受该同目标事务的迟到有效回执；始终未确认时仍由原有120秒机械动作超时及原有上层故障流程处理，没有增加“三次就立即整车停机”的条件。

正常有ACK时不强制等待100ms，下一次所有者轮询处理回执后即可计时。收到ACK后继续按原预计时长衔接，位置反馈仍用于原有健康检查和诊断，不作为新闭爪门槛。PWM闭合完成后的抬升及半程并行沿用原流程。

## 旧回执与生命周期

原生回执经已有CAN RX队列进入ArmTask。新增每轴FD接收序号和接收时间，缓存并提供给圆盘流程读取。

- 在第一次发送前读取序号边界，**包括已进入RX队列但尚未被任务取出的回执**。这些旧消息即使稍后取出，或与新发送处于同一毫秒，也不能作为新确认。
- 只消费5号、序号更新且接收时间不早于本次发送窗口的有效校验回执。6号回执、错误校验、其它功能/地址、拒绝码均不会启动闭爪计时。
- 补发属于同一绝对目标事务，沿用第一次发送的边界，允许任一次尝试的迟到有效确认。
- 确认只锁存一次，后续ACK不重复启动计时。STOP/取消后不会再补发、闭爪或抬升；下一次抓取建立新的回执边界。
- ISR共享接收序号和队列字段按原有中断边界维护，回执快照及抓取状态只在ArmTask处理。新增等待采用时间戳轮询，没有阻塞延时、额外线程或动态内存。

## 可核对日志

```text
[MAT EXTEND] ... id5 ABS=... speed=... planned=...ms AFTER_LIFT_ACK
[MAT] TRIGGER ... wait lift ACK THEN planned=...ms ...
[MAT ACK] id5 retry=2/3 SAME ABS=... speed=...; wait100ms; reach goal unchanged
[MAT ACK] id5 accepted=0x02 attempt=2 ABS=...; START planned=...ms NOW, no position wait
[MAT CLOSE] actual5=... target5=... planned=...; diagnostic only, NO position gate
```

持续无ACK时只打印一次预算耗尽提示，后续仍保持张爪并沿用已有超时处理：

```text
[MAT ACK] id5 no accepted ACK after3 sends; keep OPEN; no close/raise, existing120s stage timeout retained
```

分轮日志仍由PC2.5.5保存到`serial/runs/`；后续先读取`latest.json`，只核对对应本轮文件。升级后确认启动标志`CAMERA_DEPLOY_V204: MAT_LIFT_ACK100_RETRY3_SAME_ABS`，或`arm ui`显示`firmware=204`。

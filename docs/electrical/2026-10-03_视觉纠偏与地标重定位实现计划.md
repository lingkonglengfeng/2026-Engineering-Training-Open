# 视觉纠偏与地标重定位实现计划

日期：2026-10-03。针对当前 H723 + FreeRTOS + 轮端里程/IMU + MaixCAM 架构的增量设计。本次只编写实现计划，未修改固件或进行实车验证。

## 1. 方案与实现边界

采用“轮端里程 + IMU 粗导航 → 捕获已知地标 → 视觉相对纠偏 → 停稳后的位姿校正 → 继续导航”。

同一份视觉观测有两种用途：

- 相对纠偏：使圆环相对车体的位置接近期望值，满足抓取/放置的局部精度。
- 地标重定位：利用圆环在场地中的已知位置，反算车体的场地位姿，修正下一段导航的起点。

两者通过独立接口实现。能对准一个目标，并不自动证明该目标的地图身份和坐标已知；未知身份的物体可以用于局部对准，但不能直接重置全局位姿。

首版选“工位停靠时校正”，待标定、时间戳和关联稳定后再做行驶中融合。首版不必先引入 EKF 或完整 SLAM。

相机安装与实际输出仍待用户确认。下文首版按“测量时相机相对车体处于可重复的已知观察姿态，视觉输出可标定为目标平面上的毫米相对坐标”设计；像素输出、运动相机另见 §5。

## 2. 当前源码需要调整的地方

1. `Core/Inc/vision.h` 已有 `vision_ring_t`：id、x_mm、y_mm、theta_rad、conf、seq；可复用类型思想，但目前缺少站点身份、朝向有效标志、拍摄时间/时延和完整有效性定义。
2. `Core/Src/zdt_motor.c` 的 `ZDT_Nav_Service()` 末段结束处，按名义路径推进坐标，并直接将末段位姿设为精确目标 mm。这是计划位置，不是独立定位测量。正式接入估计器后，应以实际里程预测和视觉校正作为当前位置来源，计划终点只作为导航目标。
3. `GridNav_SetPoseMm()` 存整数毫米 x/y，不存航向，可保留为规划/显示兼容接口；不应作为完整定位器。新定位快照采用浮点 x/y/yaw，不能在融合过程中吸附到 50 mm 栅格或车道中心线。
4. 视觉协议暂定车体 X 前、Y 左；当前底盘 `ChassisMotor_SetVelocity()` 的 vy 正方向为右。统一变换适配器必须处理这一个符号差，不能让不同状态机各自猜正负。
5. 当前视觉解析逐字段直接修改共享结果，并在 conf 字段处置 valid。用于重定位前应改为局部临时结构解析，确认完整必需字段、数值范围和校验后一次发布；防止缺字段时混入上一帧数据。

## 3. 任务分工和唯一位姿写入者

| 模块/任务 | 责任 | 向外输出 |
| --- | --- | --- |
| PerceptionTask | 完整解析、校验、帧序号/时延、站点和地标候选识别；转换到统一观测模型 | 带时间和质量的地标观测 |
| MotionTask | 粗导航、观察姿态请求、视觉对准、到位/停稳判定、校正请求、校正完成等待 | 底盘目标；LocalizationFixRequest |
| ActuatorTask | 如相机随机构运动，将机构移动到观察姿态并保持，回报实际姿态/版本 | 观察姿态就绪和关节快照 |
| Localization（运行于 SensorFusionTask） | 实际里程+IMU预测、观测一致性检查、位置/航向校正；唯一发布全局位姿 | NavPose 快照；校正接受/拒绝回报 |
| ControlTask | 根据当前控制目标和测量做有界计算 | 最新轮速 |
| MatchTask | 请求“移动并视觉停靠”，完成后才抓取/放置 | 下一步动作请求 |

MotionTask 可以计算候选视觉位姿，但不能直接写定位器内部状态。统一由 Localization 提交和发布；其他模块只读快照。SafetyTask 通过独立停止锁存覆盖执行许可，不加入第二个位姿写入者。

## 4. 停靠子状态机

```text
COARSE_APPROACH
  → COARSE_STOP
  → WAIT_OBSERVE_POSE（机构相机时需要；固定相机可跳过）
  → ACQUIRE_LANDMARK
  → VISUAL_ALIGN
  → STOP_AND_SETTLE
  → COLLECT_FRESH_FIX_FRAMES
  → SUBMIT_POSE_FIX
  → WAIT_POSE_FIX_ACK
  → DOCK_DONE

超时/目标错误/定位校正被拒绝 → 停止并回报失败，或执行明确定义的有限重试
```

### 各状态行为

- COARSE_APPROACH：用里程/IMU走到目标可被可靠看见的捕获区域。捕获区应覆盖实测粗导航误差和相机视野边缘余量，不要求预测位置已毫米级到位。
- COARSE_STOP：结束旧导航动作，禁止旧脚本继续更新目标；确认停止。零速度指令不等于已经停稳，需轮端位置变化/实际速度与 IMU、视觉稳定性等可用信息共同确认。
- WAIT_OBSERVE_POSE：通过动作队列请求固定观察姿态，等待实际关节到位并保持；不得让两个服务同时控制机构。
- ACQUIRE_LANDMARK：仅接受本工位期望地标，连续若干个不同 seq 的新帧身份一致且质量合格。重复读取同一帧不能增加稳定计数。
- VISUAL_ALIGN：基于实时相对误差低速前后/横移；只有方向可观测时才加入视觉 yaw 纠偏，否则保持 IMU 航向。
- STOP_AND_SETTLE：误差进入容差且稳定满足要求后发零速度，等待底盘与相机机构稳定。
- COLLECT_FRESH_FIX_FRAMES：丢弃停稳前拍摄的观测，收集停稳后的新帧，检查散布和异常值。没有拍摄时间时，需要可靠的最大延迟上界和停稳后等待策略；不能只按接收时间断定测量是新的。
- SUBMIT_POSE_FIX：提交带当前动作、地标、测量时间和位姿版本的校正请求。
- WAIT_POSE_FIX_ACK：等待定位模块接受并发布新 pose revision；拒绝或超时不能宣告“重定位成功”。
- DOCK_DONE：一次性回报外层移动请求完成。MatchTask 此时才启动抓取/放置。

对只需要局部对准、且允许不校正全局定位的动作，应使用明确的另一种完成模式；不要以这种降级结果冒充全局重定位完成。

## 5. 坐标、安装与可观测性

### 坐标系

- M：场地系，沿用项目左下角原点，x 向右、y 向上，mm。
- B：车体系，原点取固定的底盘参考点（建议旋转中心），x 向前、y 向左。
- C：相机系，由相机标定定义；像素坐标不能直接当 B 系毫米坐标。
- yaw：B 系相对 M 系 x 轴的角度，逆时针正，rad。IMU 的上电零点、当前底盘右转正约定都要通过适配器换算到此定义。

### 相机安装

旧硬件评审记录：双视觉连接在旋转机械臂的上部板。这不能直接证明相机光学安装的位置，但必须检查是否随转盘、升降或伸缩运动。

如果相机固定在底盘上，标定固定外参即可。如果相机随机构运动，外参是 `T_B_C(q)`，取决于拍摄时的实际关节姿态 q；不能使用目标角或收到图像时的新角度代替拍摄时实际姿态。

首版推荐每次定位先将机构放到已标定的观察姿态并保持。以后如要任意姿态定位，再增加机构运动学和拍摄时关节状态插值。

毫米坐标需要正确的相机内参、畸变、安装姿态和目标平面。相机高度改变、目标在台面而非地面、物料叠层改变高度时，原先的像素到毫米映射可能失效；分别标定或用几何模型，不共用一个未经验证的比例尺。

### 地标与航向

地标表的键至少为 `station_id + landmark_id`，保存该固定圆环/标记的实测地图坐标。重复出现的“3号环”不能仅凭 ring_id 当成同一地标；前往哪个工位和预期位置范围只用于缩小候选，识别歧义时拒绝提交。

单个圆环中心提供两个平面位置约束。已知航向时可以反算车体 x/y；未知航向时，单个中心不能独立确定 x/y/yaw。即使圆投影成椭圆，椭圆轴角也不能直接当作唯一的地图航向。

航向校正需要方向性图案、已知工位边缘，或至少两个位置已知且身份明确、几何条件合适的地标。当前 theta_rad 字段只有明确测量来源、参考系和有效标志后才能参与 yaw 校正。仅识别可移动物料的中心/颜色不能提供固定地图锚点。

## 6. 相对纠偏和全局校正的计算

### 6.1 局部对准

将目标中心转换为 B 系位置 `r_meas_B = [rx, ry]`。根据机构动作标定期望相对位置 `r_des_B`，它是目标相对底盘参考点的位置，通常包含夹爪/相机安装偏置，不一定为 [0,0]。

```text
e_B = r_meas_B - r_des_B
v_B = limit(Kp * e_B)
```

此符号基于“测量值是目标相对车体的位置”：车向目标方向移动，测量距离下降。第一版可先用 P 控制，增加限速、加速度限制、容差/滞回；低置信度、帧过期或身份变化时停车，不继续沿用最后一帧追目标。若输入定义成“车体相对目标的位置”或“已求好的车体位移指令”，符号须重新核对。

新视觉帧到来才更新误差；10 ms 的任务循环不代表相机每 10 ms 有新测量。帧间可有界保持最近输出，超出有效期清零。各阈值由相机帧率、端到端延迟、噪声和实车响应确定，本计划不承诺某个固定毫米精度。

### 6.2 利用已知地标反算车体位置

已知地图地标中心 `P_M_L`，视觉测得其 B 系相对位置 `r_B_L`，航向为 theta：

```text
P_M_B = P_M_L - R(theta) * r_B_L
R(theta) = [ cos(theta)  -sin(theta) ]
           [ sin(theta)   cos(theta) ]
```

示例仅为算术说明，不是本车真实点位：地标地图位置 (1200,2250)，车头朝地图 +y，即 theta=90°；目标在车体前方 200 mm、左方 10 mm，即 r_B_L=(200,10)。地图相对向量为 (-10,200)，反算车体位置为 (1210,2050)。

若期望相对位置为 (200,0)，局部纠偏会让车向左移动约 10 mm。完成后仍用实际新观测反算位姿，不能把它无条件写死为计划的停靠坐标。

航向误差会传入平移估计：离目标越远，该影响越大。只有中心可用时保留 IMU 航向并降低相应定位质量；不要声称本次同时消除了 yaw 漂移。

## 7. 如何保存校正，避免后续覆盖

保持两个概念：

- odom：由实际轮端增量和 IMU 形成的连续短期运动估计，允许随距离漂移。
- map：经已知地标校正的场地位姿，供全局导航使用。

完整实现保存一个平面变换：

```text
T_map_body = T_map_odom * T_odom_body
T_map_odom_new = T_map_body_visual * inverse(T_odom_body_at_measurement)
```

地标校正调整 map 与 odom 的关系，原始轮端计数、IMU 原始 yaw 和短期控制反馈继续保持连续。这个连续里程/可校正地图的划分参考 [robot_localization 官方状态估计文档](https://github.com/cra-ros-pkg/robot_localization/blob/rolling-devel/doc/state_estimation_nodes.rst) 的坐标框架说明；H723 上只需要实现所需的二维变换，不要求运行 ROS。

首版停稳校正也可以保存“新地图锚点 + 当时 odom 基准”，以后以基准后的运动增量继续预测。只校正 x/y 时保持原来的地图航向关系；朝向可观测时才更新 yaw 关系。

不要直接调用 `HWT101_ResetZeroDrift()` 来实现地图重定位：当前函数会启动静止零漂标定流程，语义不同。也不应每次地标校正都清零电机编码器。

提交顺序：结束旧动作和积分窗口 → 停稳新测量 → 定位模块验证并提交 → 更新快照/版本 → 调整相关目标参考并清理旧控制误差状态 → ACK → 下一段从新地图位姿规划。旧导航末段不得在校正之后又执行“设成计划终点”的写入。

修正过程中只有 MotionTask 发布普通运动目标。首版冻结为零目标后提交，减少地图位姿跳变对位置控制器的冲击；原始航向/角速度反馈不随地图坐标校正而跳变。

## 8. 接口草案

以下仅为模型草案，不参与当前构建。

```c
typedef struct {
    uint32_t observation_id; /* 本地唯一观测编号，不仅是可回绕的线序号 */
    uint16_t station_id;
    uint16_t landmark_id;
    uint16_t seq;
    uint32_t capture_tick;   /* 换算到主控时间域；未知时需显式标记 */
    uint32_t receive_tick;
    uint32_t extrinsic_revision;
    float target_x_body_mm;
    float target_y_body_mm;
    float target_yaw_body_rad;
    float confidence;
    uint8_t position_valid;
    uint8_t yaw_valid;
    uint8_t capture_time_valid;
} LandmarkObservation;

typedef struct {
    uint32_t request_id;
    uint32_t generation;
    uint32_t source_observation_id;
    uint32_t base_pose_revision;
    uint32_t measurement_tick;
    uint16_t station_id;
    uint16_t landmark_id;
    float x_map_mm;
    float y_map_mm;
    float yaw_map_rad;
    uint8_t valid_axes;      /* X/Y/YAW，未观测轴不能覆盖 */
} LocalizationFixRequest;

typedef struct {
    uint32_t request_id;
    uint32_t generation;
    uint32_t applied_pose_revision;
    int result;             /* APPLIED/REJECTED_STALE/REJECTED_TARGET/... */
} LocalizationFixResult;
```

Perception 发布完整观测快照；Motion 向定位服务发有界校正请求；定位服务发带 request_id/generation 的回报。相同 observation_id 只能使用一次，防止同一测量被反复当作独立证据。队列满和回报丢失需有明确失败/重试策略，任务不无限等待。

首次接口冻结建议保留现有 RING 帧兼容，另用明确版本增加 station/valid_axes/时间信息；不能修改字段含义后仍当作旧协议。校验和、完整字段、数值有限性、范围、模65536序号和帧最大长度均需验证。

## 9. 校正接受条件

定位模块独立校验，而非完全相信 Motion 的候选结果：

1. 活动请求、generation、预期工位和地标吻合，地标地图坐标有效。
2. 完整测量、置信度与多帧散布满足要求；同一旧帧不能多次计数。
3. 测量时间有效或满足首版延迟上界策略；相机观察姿态和外参版本吻合。
4. 候选位姿与预测差值在允许范围，姿态/车体边界符合工位几何；明显大跳变进入重识别，不能自动覆盖。
5. 只接受被实际观测的轴；缺 yaw 时不更新 yaw。
6. 首版满足底盘/机构停稳条件，校正后不会被旧积分或旧导航动作覆盖。

预测偏差的门限应允许本来要纠正的正常漂移；设置太小会拒绝所有有用校正。置信度分数不等于毫米精度，须与实测重复性、标定误差结合。

## 10. 分阶段实现和验收

### A：统一观测与坐标

新增 `App/Inc/landmark_observation.h`、`App/Src/vision_geometry.c`、地标参数表。先只输出目标相对毫米坐标，手动将车前/后/左/右移动已知距离，检查轴、符号、比例；检查旋转机构、观察高度和工位平面的影响。

### B：实现局部纠偏

新增 `App/Src/visual_docking.c`，复用 MotionTask 执行，保持一个底盘目标所有者。先在单工位验证“捕获→低速对准→停稳”，遮挡/延迟/错误ID时能够停止和回报。验证从多个初始偏差方向收敛，并记录精度与耗时，而不只看屏幕偏差归零。

### C：实现停稳地标校正

新增 `App/Inc/localization.h`、`App/Src/localization.c`，由 SensorFusionTask 唯一服务。接入里程预测、IMU航向与校正请求/ACK；更新 GridNav 兼容视图。人为加入已知定位偏差，确认“视觉校正→下一段规划起点正确→下一段运动增量继续累加”，且不发生原计划终点覆盖。

### D：纳入比赛流程

移动请求增加 `dock_target / require_visual_align / require_pose_fix` 等明确参数。粗加工、暂存、其他可观察固定地标的工位分别标定目标；首版仅在这些确定节点重定位。完成结果必须等校正 ACK，再开放机构动作。

### E：有需要再增加行驶中融合

建立主控/视觉时间关系、拍摄时机构姿态和历史 odom 缓冲，按测量时刻校正后传播到当前时刻；再考虑 EKF 的过程噪声、测量噪声、创新门限和部分观测。不能把延迟图像的位置直接当成当前位姿。正式前记录延迟分布和噪声，证明连续融合相对停稳方案有收益。

### 关键验证

- 单个圆环时不产生伪造 yaw 修正；两个可区分地标/方向特征时验证 yaw 方向与角度回绕。
- 帧重复、缺字段、NaN/无穷、校验失败、错站点、延迟和失去目标均不能提交有效校正。
- 精对准过程中既有里程导航不能同时覆盖速度目标。
- 停稳后新帧用于校正，旧帧不能覆盖新位姿。
- 姿态校正和局部对准完成后，真实放置位置与下一段路径均满足要求；显示偏差归零不作为唯一验收。

待用户确认：相机实际安装位置、是否随机构运动；输出像素还是毫米及其原点；theta 的观测来源；可识别固定地标的身份和方向信息。

# V14：记录发车姿态，出库后边走边展开

本版没有通过工具连接或操作实车。21:45日志中的ZDT5=-43.37deg（约3.60%、下降8.63mm），ZDT6=-279.44deg（约38.36%）；DM角度不在该日志中。新指令会从新鲜反馈实际读取三轴姿态，不编造DM角度，不把所选发车位置重新当作电机零点。

## 一次记录并保存

烧录本包，启动应显示CAMERA_DEPLOY_V14。保持/摆好所需发车姿态，先停止动作、底盘失能，DM失能并保持机构静止：

```
&dis
&arm stop
&dm off
&arm start save
```

等待`[ARM START] SAVED`，再发送：

```
&arm start status
```

SAVED/status显示5/6的相对角度和百分比、DM相对现有软件零点的实际角度。必须等到SAVED；串口OK只表示收到命令。记录需4组新鲜、稳定的位置/状态反馈且稳定至少300ms，DM必须失能、静止且有有效参考。ZDT轴可保持使能以支撑静止机构，不需要让升降轴自由下落。保存过程不会驱动机构或改写电机内部零点，原有效记录在写入失败时保留。

## 发车前恢复

```
&arm start
```

或`&arm start go`。流程依次抬5号到最高、DM恢复记录角度、6号恢复记录位置、5号回到记录高度。到位后显示`[ARM START] READY`并保持使能。

这是调用一组目标姿态，不是把当前位置当零点。TOP5、RETRACT6和DM软件零点必须已经正确。更换驱动器、驱动器重建坐标、修改零点/方向/行程后，先重新建立正确零点再记录姿态；不能用camera init在发车姿态下将它误认成最高/最内。保存的姿态绑定原零点、跨度、方向和DM CAN IDs，检测到不一致会拒绝恢复。

READY后按原流程摆车、`&match reset`、`&startpose 1`或2、等IMU完成，再`&depart`。match reset不会自动移动机械臂；请在depart前等待发车姿态READY。

## 出库联动

出库动作完成后自动同时执行：底盘去QR，ARM任务执行camera展开（5号先回最高、DM回现有软件零点并保持、6号伸到-300deg）。不用额外发送arm camera。

小车先到QR时停车等待展开READY，之后才切换相机/启动QR识别及原流程。ARM失败、超时或DM保持丢失会阻止识别；展开失败的异步回报会终止当前底盘流程。STOP/reset取消尚未完成的展开请求，不会让旧请求的READY完成新一次发车。复位与请求结果使用独立token交接，任务之间不直接修改另一任务的FSM。

保留camera升降上限15RPM、加速60RPM/s，6号原生位置模式上限80RPM，W25软件零点指令和底盘里程计控制。底盘与机械臂仍共享部分ZDT总线，真正的并行反馈质量、到位时间和机构净空需要实车验证；两个任务不等于完全没有通信或机械影响。

## 存储与限制

发车姿态使用W25倒数第5/6个4KB扇区（8MB时0x7FB000、0x7FA000），版本/序号/CRC/双备份/写后校验。原DM软件零点用倒数第3/4扇区，导航和PID用最后两个扇区。记录的是三轴，舵机状态日志只是PWM输出估计，本版不将其当作实测舵机角度保存。

请勿在录入写Flash时同时从另一串口保存/擦除PID或导航Flash，现有W25驱动使用同步SPI。上电只加载姿态，不自动动作。真实W25断电保存和并行运动尚未由工具实机验证。

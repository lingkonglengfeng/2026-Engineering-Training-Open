# V131：外环圆弧优先，修复第一个外环弯被跳过

## 日志确认的问题

V130第一次QR→RAW的实际起点约(2123,1148)，A*段长1000mm向北、850mm向西，精确目标(1250,2100)。沿实际起点加栅格段长会得到规划拐点y=2148；实际直线到位记录y=2146。精确目标车道是y=2100，差约46～48mm。

V130内部段接圆弧要求两者误差≤8mm，因此在进入圆弧前直接返回原停车转向，且这一返回分支没有日志。不是圆弧运行失败，也不是这次车身校验否决圆弧；圆弧还没启动就被段坐标匹配条件跳过。

这属于毫米起点/终点与整数格段长混用的适配问题。

## 修复

当前外环四角90°弯继续默认优先圆弧。相邻段的格心取整差允许到一格50mm，然后从真实毫米起点及精确终点重建正交拐点和两侧距离，重新检查整条轨迹。不是让车辆继续走到偏了48mm的拐点，也不是关闭禁区检查。

本次输入会得到：起点(2123,1148)，东北圆弧拐点(2123,2100)，终点(1250,2100)。相切圆半径仍150mm，初始直線距离变为952mm，最终横向距离873mm；两侧各扣除150mm接入圆弧。

初始航向门槛与现有导航对向统一为3°，车身检查的航向包络相应为3～5°，比V130原来的2～5°更充分。仅空间不足、段长不足、车还在动或状态不支持时保留原转向，并新增`SKIP`原因日志。超过50mm的异常目标/车道差仍不按格心误差处理。

默认及指令保持：

```text
&outerarc status
&outerarc on
&outerarc off
&outerarc radius 150
&outerarc speed 140
```

停车空闲时可配置。RAM默认ON，R150mm、弯道上限140mm/s；工位面向、扫码点的面向二维码动作、180°掉头和非外环角继续原流程。QR点转向不属于本次修复的第一个外环角。

机械臂/视觉参数保持V129/V130。云端“6分20秒版”V129提交`3b05ead`和标签保持不变；V131为本地试验，未覆盖该基线。

## 现场应看到

QR到位面向并扫码后，前往RAW途中应有：

```text
[ARM] CAMERA_DEPLOY_V131 ...
[OUTER ARC] START corner=(2123,2100) end=(1250,2100) R=150mm ... two segments
[OUTER ARC] phase=1 ...
[OUTER ARC] phase=2 ...
[OUTER ARC] DONE actual=(...) ...
```

具体坐标随本轮真实起点略变。若仍未接入，会输出`SKIP exit lane mismatch >one cell`、`SKIP geometry/leg/heading not eligible`、`SKIP start baseline still moving`，或原来的`footprint clearance rejected`，据此继续诊断。

日志末尾RAW阶段的FAULT只有截断状态，没有完整原因；不能将其归因于未启动的圆弧。

## 验证

113910项回归通过，新增原日志1000/850mm、48mm格心差的东北首弯复现，以及98mm异常车道差保持拒绝。8个方向的场坐标轮速斜坡、80ms反馈与部分转向效率85%的仿真继续通过：最大横向偏差2.06mm，末端误差≤2.92mm，弯中未停车。

Keil0错误、0警告。未烧录或执行实机动作；下一轮需实际确认`START/phase/DONE`及车身扫掠。包内附V129回退HEX和V130原理示意图。

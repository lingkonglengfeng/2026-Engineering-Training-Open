# V247 PRELIM：保留圆弧计划，余速归零后重取里程基准

仅修改初赛 `codex/arm-control-panel`。决赛代码、固件和分支仍为V245，不同步本次修改。PC2.6.7、相机应用、机械臂和W25参数均不变。

## 问题与修复

2026-11-01 20:25开始的run005，二维码→圆盘原地对准完成后立即出现 `[OUTER ARC] SKIP start baseline still moving`，随后走普通两段直线与原地转向。转向控制先清除active标志和目标轮速，applied轮速仍可能渐变归零；旧圆弧入口只尝试一次，因这个短暂状态永久放弃了本段圆弧。

V247只改变“圆弧几何和足迹检查已通过，但轮速/运动需求尚未归零”这一分支：

1. 返回“已接管”给导航调用方，避免继续启动普通直行；进入专用异步等待状态，原路线、段索引和工位动作保持。
2. 发送一次既有普通减速停止请求，使用原加减速渐变；不发立即停机、不新增MATCH故障或等待超时。
3. 周期检查applied轮速和运动需求均归零，并等待当前里程查询空闲。等待期间不忙等、不重复发停止/查询，也不提前增加圆弧启动计数。
4. 丢弃减速前的里程就绪标记，重新请求四轮基准。走原启动查询完成路径，再用当前条件重建、检查并启动圆弧；实际运动从新基准开始。

取消/STOP沿用原导航取消逻辑，会退出等待状态；晚到的轮速归零不恢复已取消动作。若重新检查时圆弧关闭或几何/足迹不适用，仍按原规则回退普通路线。原查询失败、工位动作超时和其他既有处理保持。

正常已归零的入口不增加额外等待。V246出弯提前制动/航向锁存保持；所有速度、加速度、半径与原到站条件保持。本次不修改圆盘视觉搜索4秒预算或其他识别参数。

## 日志与使用

遇到本轮余速情况应依次看到：

```text
[OUTER ARC] WAIT_STOP: residual wheel output; keep curve, normal braking then fresh baseline
[OUTER ARC] STOPPED: query fresh wheel baseline, retry kept curve
[OUTER ARC] START ...
```

`outerarc status`增加 `waiting_stop=1/0`。正常无余速时直接START；等待阶段不会打印SKIP或假报START。出弯继续使用EXIT_HEADING_LOCK日志。

使用初赛目录的 `Engineering_Training_Project_V247_PRELIM.hex`，或编译该初赛Keil工程。启动标记为CAMERA_DEPLOY_V247_PRELIM，arm ui返回firmware=247、variant=PRELIM。不需要更新上位机或重存W25。旧V246固件保留，决赛仍用V245_FINAL。

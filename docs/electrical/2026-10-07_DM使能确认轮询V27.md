# V27：DM使能确认期间持续查询保持位置

本次用户日志里5号上端已记录为11729counts，实际11725counts，距顶部约0.00437mm，measured=1；此前顶部高度未知的问题已经解除。当前拒绝发生在DM_Motor_Enable的FC后使能确认阶段，不是设置内部零点失败。

旧版只发送一次FC和一次POS，在300ms确认期间暂停正常周期发送。若首个POS反馈仍为失能，后面没有新控制帧来请求更新状态。通用等待器也未检查最后一次osDelay返回时的回包。失败后的日志enabled=1/code=1说明当时看到使能，但无法独立证明该帧在确认窗口内到达，也可能被随后FD回包覆盖；不能仅凭这些回显确定电机硬件问题。

V27在FC后立即发送捕获的当前原始位置，以0.10rad/s保持，然后每20ms再次发送同一POS来请求新反馈，最多1秒；确认即返回，不固定等待1秒。FC只发一次，不在轮询里重发。整个确认阶段目标不是0rad，不写FE，不改变内部零点或偏置。通过后再由home发送0rad目标。真实故障、非法位置、发送失败和明确STOP仍中止；没有新鲜使能反馈仍失败并请求失能。

失败日志打印失能请求前捕获的确认数据：HAL、反馈计数基线及结果、状态码、年龄，便于区分未回包、持续失能及真实故障。启动标记CAMERA_DEPLOY_V27。

烧录会丢失RAM中记录的5号上端。先确认5号实际在最高位置，保持使能稳定后重新记录：

```
&arm enable 5
&arm top 5
```

等待UPPER RECORDED，再设置发车目标引用：

```
&arm start defaults
&dm clear
```

等待CLEAR confirmed，随后：

```
&dm home
```

等待动作结束，再用`&dm query`确认角度接近0度。此次不需要重新发送`dm zero save`。若失败，保留新的enable failed及HOME FAILED两行；它们包含确认阶段诊断。

验证：生产DM使能代码在Cortex-M模拟器504项断言通过，覆盖首帧仍失能、600ms延迟确认、截止时刻回包、旧缓存不能确认、保护故障、STOP取消、CAN发送忙和计时回绕；查询/内部零点362项通过；机械臂驱动4配置均通过。仅主控编译和模拟验证，没有烧录板卡、操作真实电机或修改相机程序。

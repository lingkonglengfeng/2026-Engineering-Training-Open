# V206：公共升降ACK重发与TEMP末段诊断

## 上升也出现了缺ACK未运动

此前run002中，红色已识别且下降收到接收ACK，随后16:49:57.679下发5号回顶绝对目标0、238RPM，没有记录到该上升ACK。约15秒后反馈仍为46.728%，触发原`percent motion timeout`。驱动启用、反馈新鲜，没有报告堵转或保护触发。

这证明命令已入队，但缺少接收回执且位置没有上升；不能仅凭缺回执确定是命令、回执丢失还是其它执行链路问题。驱动器收到命令便自行执行，主控没看到ACK本身不等于硬件被禁止运动。

V205的圆盘下降已有独立ACK/重发，但回顶及其它普通5号定位走公共百分比控制器，原先只发一次原生ABS命令，然后一直等到位。这次将重发覆盖公共路径。

## 本版修复范围

- 公共`ArmCalibration_MovePercent(LIFT,...)`的上升、下降都缓存同一绝对目标、所选RPM与目标高度。包含回顶部、CAMERA展开、姿态等待/抓放升降、上位机百分比轴控制等目前使用该公共入口的动作。
- 100ms无本次有效接收ACK且实际仍在目标窗口外，补发同一绝对位置命令；首次加两次补发最多3次成功入队。HAL_BUSY没有入队，不消耗成功次数，仍按时间戳间隔尝试。
- 收到本次0x02或0x9F确认后停止补发，**仍按原编码器位置、稳定样本及时间确认到位**。ACK不会直接让动作成功，也不替代回顶确认。
- 如果实际已接近目标，就继续原稳定确认，避免ACK丢失时反复触发已在收敛的电机。已处于目标窗口的无位移动作也不强制下发多余命令。
- 重发不重复STOP、不重新启用、不改变速度/加减速、不重置动作起点或延长原超时。三次仍失败时保留原目标与原超时/故障处理，没有新增“三次就立即停机”的条件。
- 停止、取消、已有伸缩恢复中断升降后，不再后台补发；新的定位重新建立接收序号/时间边界，不采用之前排队的回执。

普通原生升降的补发在原反馈新鲜度、启用、故障检查通过后执行，不要求每次重发前都等一份新的位置样本，但仍须满足原有效反馈规则。目标窗口和稳定阈值未改。

圆盘定时下降继续使用V204/V205自己的ACK事务，公共控制器在其IDLE期间不会重复补发它；收到下降ACK并完成预计时间后，伸出50mm与闭爪并行，伸出预计时间/PWM均结束才抬升。没有把圆盘下降改为位置到位等待。

本次不自动重复底层相对脉冲试验命令，以免相对位移累计；目前自动流程和界面常用的5号绝对定位入口已覆盖。6号策略、全局CAN自动重传、W25格式、顶部/半程转运、提速和PC识别参数不变。

## 最新TEMP停滞：run003核对结论

只检查分轮索引指向的16:58:38～17:04:02这一轮run003，及按对应时间范围定位的图像CSV；没有从头分析整条串口会话。

关键顺序：

1. 17:02:37第二轮ROUGH已完成，开始向TEMP运输；CAMERA恢复与行驶并行。
2. 17:02:39出现机械臂反馈等待，17:02:43.666已恢复；6号相机姿态命令收到0x02，17:02:44.936确认CAMERA READY。
3. 17:02:44.950开始第二轮TEMP叠层视觉纠偏，容差±10px；17:02:46.305进入同步阶段7，轴线−0.35度、置信度87、三环有效。
4. 此后没有整体纠偏DONE或开始TEMP放置的记录。对应图像记录后段位置约X=−0.6px、Y=4.5px，三环可信，已经在位置容差内。
5. 17:04:02.389电脑TX发送`&STOP`，随后主控回复OK并进入`FAULT TEMP_BATCH2`。

因此需要区分：**直接终止由电脑STOP触发；STOP之前的停滞发生在TEMP同步视觉纠偏完成条件，尚未开始实际放料**。日志没有给出该时刻机械臂放置电机自动故障；短暂反馈等待也已恢复，不能把它当作最后的停滞原因。

现有资料缺少停滞期间连续的角度有效性、置信度及主控稳定计数，尚不能区分角度数据、同图像条件或稳定确认的具体卡点。本次不修改同步纠偏阈值/动作策略，不宣称已经修复TEMP卡点。

为补齐这个实际诊断缺口，V206复用已有只读LIVE状态输出：同步纠偏期间，静止等待且满足原来的无运动需求、轮速为零及角速度条件时，最多每5秒自动输出XY和角度快照。运动中不强制打印，不发送运动/STOP指令，不改变任何到位或停机判定。手工`valign status`仍按原规则可用。

```text
[ALIGN] LIVE status state=... stable=... px=... valid=... rings=...
[VYAW] LIVE enabled=1 phase=7 axis=... valid=... q=... n=... error=... stable=... goal_IMU=...
```

下一次卡住时，从本轮这两行即可查看XY状态、角度质量和稳定进度，而不必仅凭外层FAULT猜测。

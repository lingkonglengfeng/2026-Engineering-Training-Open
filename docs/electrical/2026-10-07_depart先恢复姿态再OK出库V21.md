# V21：depart先恢复发车姿态，收到新OK才出库

用户确认start指机械臂的arm start保存姿态，不是底盘返回启停区。

## 新发车流程

按原来摆车并设置地图起点：

```
&match reset
&startpose 1
```

或startpose 2。等IMU完成，再发送：

```
&depart
```

程序进入PREPARING，底盘保持失能，仅机械臂恢复W25保存的发车姿态。确认三轴实际到位后显示ARM START READY和MATCH WAIT_START_OK。此时发送新的：

```
&OK
```

才使能底盘、执行出库。提前的OK、同一READY时刻以前接收的OK不会缓存到后面使用。重复depart不重启准备动作。保存姿态缺失或不匹配、ARM失败、准备超时不会进入出库。等待人工OK期间保持姿态，OK时再次检查新鲜实测发车姿态与IMU/CAN。

出库之后仍自动边去QR、边展开到摄像机姿态；QR入口等展开和CAM1握手。CAM2继续屏蔽，二维码点仍是手动确认OK。WAIT_START_OK专用于出库前，不与各工位WAIT_OK混淆。

## DM恢复内部零点（本包已包含）

不加载旧W25软件零点，home/camera使用DM原始0rad；设置零点采用电机自己的FE保存指令。上电不会自动重新设置零点。

一次性校准：STOP、dis、dm off，手动摆好机械零位并保持静止，发送dm zero save，随后dm query检查。以后用dm home回零。具体说明见包内V20文档；普通dm zero和W25零点入口会拒绝软件零点操作。

**旧发车姿态绑定以前的软件参考，可能不再匹配。** 内部零位设置正确之后，把三轴摆回希望的发车姿态，底盘失能、DM失能、三轴静止，发送arm start save并等SAVED。这是更新发车姿态记录，不是重新设置电机零点。不要在摄像机完全展开姿态下误录为发车姿态，除非那就是你要的发车状态。

## 行为与验证

准备、等待OK、出库、去QR使用不同请求token；取消/reset后的旧结果不能完成新请求。机械臂忙时最多在原准备120秒预算内等待，不无限重试；同一任务实例保持ARM/CAN命令所有权。准备期间不接受底盘路线修改，停止/reset可取消。

保留DM轻微晃动下的有界使能、设置零点/到位的严格静止检查、5号30RPM/6号80RPM、心跳3.5秒和像素500ms过期停车、里程计及朝向路径。

仅编译/模拟验证，尚未烧录、写电机Flash或进行真实出库测试。

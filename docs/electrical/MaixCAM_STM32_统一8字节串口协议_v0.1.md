## 1. 推荐格式

每帧固定**8字节（64位）**，串口115200、8N1，发送二进制，不发送十六进制文本，不附加CRLF。8字节上线约0.694ms。一组完整的XY/航向/质量观测由多个帧组成，各帧仍8字节。

```text
6B  TYPE  META  D0  D1  D2  D3  CRC8
```

| 字节位置（从0起） | 内容 | 定义 |
| --- | --- | --- |
| B0 | `0x6B` | 固定帧头，接收同步用 |
| B1 | TYPE | 消息类型，`0x01`就是颜色 |
| B2 | META | 有效标志、4位序号、3位目标ID |
| B3～B6 | D0～D3 | 4字节载荷，由TYPE规定 |
| B7 | CRC8 | 对B0～B6实际计算的校验字节 |

**固定0x6B不能检测正文是否传错。** 因此把它用于帧头，最后保留真正CRC；不同时再加固定帧尾。按这里的字段，8字节已正好容纳两轴16位数、目标ID、有效性、序号和校验，首版不再压成6/7字节。

## 2. META：一个字节容纳状态与目标

```text
bit7        bit6 … bit3       bit2 … bit0
 VALID       SEQ（0～15）       ID（0～7）
META = (VALID << 7) | (SEQ << 3) | ID
```

- `VALID=1`：该测量有效；`0`：无目标、无法测量或未标定。无效坐标填0，**坐标0本身不是无目标标志**。
- 相机测量SEQ是图像编号模16，同一次图像的坐标、角度、质量帧共享SEQ，下一图像加1。CAM2二维码分组共享当前成功SET请求SEQ作为会话号，同会话首个完整任务锁定，重复发送不递增SEQ。
- ID按TYPE解释：颜色ID、圆环ID、二维码组号或测距方向。0=未指定；无效测量可以保留所请求的目标ID。不能仅凭ID判断它属于哪个工位。
- 有效物料/圆环ID为1～6；二维码组号1～4，距离方向1～4。颜色沿用项目现有冻结表：1红、2黄、3蓝、4绿、5浅蓝、6黑；这是项目约定，实施前须与实际Maix脚本及比赛物料核对一致。圆环ID为1～6，工位身份另由运行上下文确定。PLATE_PX 的 ID 固定0。

ID是颜色/圆环身份，不是通用多目标跟踪UID。统一服务物料target=0首次选择一个颜色后保持颜色，具体物料仍由现有最大合格区域策略选择；同色多物料不提供稳定UID，正式取料应由主控指定颜色并保证当前取料视野具有唯一目标。

4位SEQ为省字节的明确取舍：20Hz时0.8秒就回绕，**不能当作全局唯一编号，也不能只凭它判断数据新旧或精确统计丢帧**。接收端同时记录时间和工位上下文；多帧拼组限定在50ms内。

## 3. 类型与4字节载荷

所有16位数均**低字节先发**，有符号数用16位二进制补码。未使用/保留字节发送0。

| TYPE | 名称与方向 | META.ID | D0～D3 |
| --- | --- | --- | --- |
| `0x01` | COLOR，相机→主控 | 颜色 | D0=置信度0～100，255=未知；D1～D3=0 |
| `0x02` | MAT_PX，物料像素偏差 | 颜色 | D0/D1=`int16 dx_px×10`；D2/D3=`int16 dy_px×10` |
| `0x03` | RING_PX，圆环像素偏差 | 圆环 | 同上，单位0.1像素 |
| `0x04` | ALIGN_MM，车体平移对齐偏差 | 当前目标 | D0/D1=`int16 e_forward_mm×10`；D2/D3=`int16 e_right_mm×10` |
| `0x05` | ALIGN_YAW，车体转向对齐偏差 | 当前目标 | D0/D1=`int16 yaw_error_deg×100`；D2=置信度；D3=方向测量来源 |
| `0x06` | FRAME_INFO，观测质量/年龄 | 当前目标 | D0/D1=`uint16 age_ms`；D2=置信度；D3=质量标志 |
| `0x07` | QR_GROUP，二维码任务码 | 组号1～4 | D0/D1/D2：组1/3为三个工程颜色ID（1..6互异），组2/4为位置1..3排列；D3固定4 |
| `0x08` | OBS_DIST，距离观测 | 1前/2左/3右/4后 | D0/D1=`uint16 distance_mm`；D2=置信度；D3=0 |
| `0x86` | VOBS_PC_BRIDGE，CAM2电脑视觉障碍扩展 | 本类型专用：帧龄向上取整的10ms单位值 | D0/D1=`uint16 front_gap_mm`；D2/D3=`int16 body_right_mm`；小端 |
| `0x09` | PLATE_PX，圆盘底部水平切线切点像素偏差 | 固定0 | D0/D1=`int16 dx_px×10`；D2/D3=`int16 dy_px×10`；只控制切线Y时忽略X |
| `0x80` | SET，主控→相机 | 请求目标，0=任意 | D0=模式；D1=工位；D2=输出Hz；D3=请求标志 |
| `0x81` | ACK，相机→主控 | 回显请求目标 | D0=被确认的TYPE；D1=结果码；D2=当前模式；D3=当前工位 |
| `0x82` | HEARTBEAT，相机→主控 | 0 | D0=协议版本1；D1=当前模式；D2=当前工位；D3=状态标志 |
| `0x83` | RING_COUNT，相机→主控 | 固定2 | D0=可信可见圆环数0～3，>=3封顶3；D1=当前工位；D2=当前成功SET请求SEQ（0～15）；D3=0 |
| `0x85` | PLATE_SCENE，相机→主控 | 固定0 | D0=0未知/异常、1SEARCH、2ACQUIRE、3FOUND；D1=当前工位；D2=当前成功SET请求SEQ；D3=0 |

其他TYPE保留，不能私自改变既有TYPE的单位或字节含义。后续地标重定位可另分配TYPE，但仍使用同一8字节封装。

### 数值、坐标与来源

- XY范围：-3276.8～+3276.7像素或mm。角度单位0.01°，发送前归一化到[-180°,180°)。量化用四舍五入，半位远离0；超范围/非有限数报VALID=0，不截断或冒充有效测量。
- 像素偏差：`dx=u-u_des`，向图像右正；`dy=v-v_des`，向图像下正。期望像素点由相机标定配置，不默认一定是图像中心。当前程序保留界面屏幕像素右/上正，发送端除以 FIT_CONTAIN 显示比例并反转 Y，得到图像像素右/下正；目标为图像中心，对应用户指定的屏幕中心。圆环的零偏置是 (0,0)，修改目标偏置时须同步主控标定。
- ALIGN_MM：`e=目标在车体系的实测位置−期望位置`；车体向前正、向右正，与当前底盘SetVelocity接口一致。用于前进/右移的小量修正。期望位置包含夹爪及相机安装偏置，不能一律设成(0,0)。
- 像素转换到毫米必须依据当前相机/机构观察姿态和目标平面标定。未完成转换只发像素帧，不能把150px编码成150mm。地图/重定位若采用车体向左正，先对这里的右向值取反。
- ALIGN_YAW为`期望航向−实测航向`，逆时针/左转正；D3：0未知、1方向标记、2已知工位边线、3多地标。无方向的单个圆心不能提供航向，不能把0°当成已测得对准。
- FRAME_INFO质量标志：bit0=毫米标定可用，bit1=当前相机观察姿态已知，bit2=航向可观测；bit3～7=0。age_ms表示该图像实际采样到送入发送链路的已知耗时，65535=未知；主控还需考虑发送/接收队列延迟。不要用处理结束时间冒充采样时间。置信度255=未知。
- 距离65535=未知，此时OBS_DIST的VALID=0。测量有效和动作是否允许执行是不同层次，由后续控制流程判断。

ALIGN_MM是局部误差，不能直接冒充场地绝对位姿。重定位还需要工位+固定地标ID、测量位置和可靠航向；移动物料中心不能作为固定地图锚点。

## 4. 请求模式与切换（已实施0/2/3/8）

SET的META：VALID固定0，SEQ是主控请求号模16，ID是目标ID。ACK回显相同SEQ/ID，VALID=1表示成功，0表示失败；请求号与相机图像号分别计数。

| SET.D0模式 | 相机输出 |
| --- | --- |
| 0 | 停止观测流，仅心跳/回执 |
| 1 | COLOR（保留，当前未实现） |
| 2 | MAT_PX，可附FRAME_INFO |
| 3 | RING_PX + RING_COUNT，同图像位置与计数，当前v8服务已实施 |
| 4 | 物料ALIGN_MM + FRAME_INFO（未标定，当前失败ACK结果3） |
| 5 | 圆环ALIGN_MM + FRAME_INFO（未标定，当前失败ACK结果3） |
| 6 | CAM2 QR_GROUP，station4/target0/flags0；扫码v1与主控已实施 |
| 7 | OBS_DIST，可附FRAME_INFO（保留，当前未实现） |
| 8 | PLATE_PX + PLATE_SCENE 圆盘切点及本帧检测状态，ID固定0，v12实施 |

SET.D1工位：0通用、1物料区、2中转/粗加工区、3最终暂存区、4二维码区、5始停区1、6始停区2。SET.D2：流模式1～50Hz，建议20Hz；模式0时为0。SET.D3 bit0=请求航向帧，其余位为0；仅模式4/5可请求航向（规划接口）；当前已实施模式flags只能0。

ACK.D1：0成功、1模式错误、2目标错误、3毫米标定未就绪、4无法观测航向（保留）、5工位错误、6频率/标志错误、7相机/算法资源失败（新增）。失败保持旧配置。HEARTBEAT每500ms一次（共享识别主循环，实际可被长检测/驱动调用延后），META.SEQ=0、VALID=1表示相机服务运行；D3低3位沿用质量标志，其余0。相机重启默认模式0、工位0，等待重新SET；主控收到回执/心跳中的未知版本或上下文变化，清掉旧观测组。

每个串口同时只允许一个活动观测上下文及一个待确认SET。相机先发完或丢弃旧流的排队数据，再成功ACK，再发新配置的观测；主控以ACK为上下文边界，不把旧工位数据混入新工位。同一请求重试保持同SEQ且处理幂等；当前主控接口500ms等待ACK、最多重试2次，总3次尝试；使用UART中断发送，不在ISR中解析/等待。相机2秒内同完整请求重试只返回缓存ACK，不重复打开相机。资源切换实际可能超过等待窗口，最终超时后应由主控流程发新请求，不能靠迟到位置解锁控制。

## 5. 接收与对齐规则

1. UART是字节流：可拆包/粘包，不能把一次DMA回调当作一帧。
2. 搜索0x6B，攒满8字节，检查CRC及TYPE/字段范围。失败只丢最前1字节继续滑动搜索；帧中出现0x6B、0x0D、0x0A都只是数据，不能提前重新起帧或按换行截断。
3. 半帧超过50ms未补齐就丢弃重同步；CRC错/环溢出只计数并重同步，不使用受影响的观测。
4. 每个端口单独维护上下文及拼组缓存；XY/角度/INFO按端口+上下文+ID+SEQ组合，收集窗口50ms，不能用上一次角度配这一次XY。连续同SEQ在窗口内是同一图像/重复帧，不视为新观测；超时清组，SEQ回绕不独立判定新旧。
5. 毫米对齐首版需要有效ALIGN_MM和同组FRAME_INFO；请求航向时还须有效ALIGN_YAW。未请求航向则只用平移，保留IMU航向保持。持续有效、稳定、满足动作所需数据年龄后才用于纠偏；阈值另由控制层标定，协议不新增当前导航的过冲停机逻辑。
6. 当前CAM2 QR_GROUP必须4组，ID1..4、D3=4、同SEQ且等于成功SET会话号，50ms内完整才发布；颜色组1/3按工程5浅蓝6黑发送（规则5黑6浅蓝需互换），位置组2/4为123排列。主控还原规则原码并存独立工程颜色/位置数组。残组、旧会话、跨端口不发布，重复与矛盾组不覆盖本会话已锁定结果。未找到/歧义时相机不发送QR_GROUP，只心跳。识别稳定后重发同一32字节组直到STOP，组内不插心跳或ACK。旧ASCII仅调试保留，不用于新qrscan流程。

### 圆环计数与连续搜索（相机v8配套）

模式3的每次新观测先发 `0x03 RING_PX`，再发 `0x83 RING_COUNT`，构成16字节组；两帧META的图像SEQ相同，ID固定2。META.VALID分别解释：位置有效表示已可靠定位中间圆环，计数有效表示当前图像的可见计数可信。因此可信0个也可发COUNT.VALID=1；只看到2个时位置必须VALID=0、坐标填0，计数VALID=1、D0=2。看到至少3个但中间身份有歧义时位置仍无效，不能靠COUNT=3恢复旧坐标。

主控只接纳已确认RING上下文中的观测。计数D1必须匹配工位，D2必须匹配当前成功SET请求号，两帧图像SEQ和ID一致且在50ms内到齐；接收顺序颠倒也支持。同一图像SEQ重复不更新观测年龄。组在首帧接收时开始计龄，原接口满200ms失效，当前平滑局部配置以Window接口选择400ms；这是接收年龄，尚不代表曝光到接收的总延迟。丢半组、跨工位/请求、STOP、清观察或相机重启都不能拼用旧计数。旧组到新计数变化的边界先作废旧场景，避免继续拿旧中间圆环移动。

相机仅在提交新观测组时递增图像SEQ；限频跳过的图像不消费SEQ。位置和计数之间不插入心跳/控制帧；短写最多保留50ms，STOP/SET丢弃旧尾部并留55ms恢复间隔后发送新上下文ACK。主控同图像配对完成后，可信2个允许沿标定的画面右侧搜索；3个且位置有效时直接用本帧坐标纠偏，3个但位置待确认时停止搜索等待。2026-10-05新增2号点例外：当前工位可信0个时按车体左侧低速寻找（默认0.040，原0.020的两倍；两圆环仍0.020），与两圆环共用累计搜索/运动预算。1个、其他工位0个、计数不可信或过期均停止移动；串口没数据不是0个。上述搜索由`valign search`开关控制。连续纠偏与搜索的具体速度、稳定条件见[连续视觉PID与三圆环搜索](2026-10-05_连续视觉PID与三圆环搜索.md)。

### 圆盘场景与首次寻找（相机v12配套）

模式8每图像先发09位置，再发85场景，组成16字节观察组，同图像SEQ/id0。PLATE_SCENE的META.VALID表示本帧正常检测且状态可信，与位置VALID独立。1=SEARCH仅由正常完成检测的NO_EDGE_ARC授权，09位置无效且坐标0；2=ACQUIRE用于EDGE_OK候选尚未完成3帧确认或AMBIGUOUS_EDGE，位置无效且不授权搜索；3=FOUND必须与有效切点坐标一致。异常、未知原因、状态矛盾、NaN/超范围坐标均09无效、85 VALID0/D0=0，不以故障帧授权移动。新灯控0x84仍未实施。

主控按50ms、同端口/同SEQ/id0/工位/成功SET请求号配对，STOP/清观察/换模式即作废；重复组不刷新年龄，支持两种到达顺序。初到1号点连续3个独立可信SEARCH组才允许沿已标定画面右侧有界寻找，ACQUIRE/异常/缺半组均不搜索；拿到有效位置就用当帧坐标进入纠偏，若已经在容差内则停车终验。已拿到目标后的丢失不重新沿右盲找。老v11正常09位置仍可纠偏，但没有85，不能授权1号新搜索。

本次仅平滑局部纠偏配置选择400ms接收窗口、260～360ms渐降，传统GetPixel/GetRingScene及脉冲配置仍200ms。这扩展的是已接收合格观察的使用时长，不代表实际曝光新鲜度；无效新组、上下文/串口故障不延长为有效位置。圆盘与圆环的当前规则见[纠偏流畅性与圆盘搜索更新](2026-10-05_纠偏流畅性与圆盘搜索更新.md)。

这里没有塞满帧的可变长度、浮点、字符串或C结构体内存布局。位置帧内X/Y一起发送；角度、质量、二维码分组也全部固定8字节。

## 6. 已计算的十六进制例子

以下每行**正好8字节**，末字节已经计算CRC，串口助手须使用HEX发送。

| 含义 | 完整8字节 |
| --- | --- |
| 颜色1、置信度90、图像SEQ9 | `6B 01 C9 5A 00 00 00 05` |

## 7. CRC与打包参考

CRC：宽8位、多项式0x07（x⁸+x²+x+1）、初值0、非反射、结果不异或。计算B0～B6共7字节，B7发送结果。自检字符串ASCII的123456789应得F4。用逐位算法或等价查表算法均可，但两端参数必须相同。

下面是协议打包参考；实际相机源码以 `vision/protocol8.py` 为单一来源，通过 `tools/sync_protocol8.py` 嵌入三个单文件程序。C端显式解析各字节，不发送或解析 sizeof(struct) 布局。

```python
import struct
import math

def crc8(data):
    c = 0
    for b in data:
        c ^= b
        for _ in range(8):
            c = ((c << 1) ^ 0x07) & 0xFF if c & 0x80 else (c << 1) & 0xFF
    return c

def make_frame(msg_type, seq, target_id, valid, payload):
    if not (0 <= seq <= 15 and 0 <= target_id <= 7 and len(payload) == 4):
        raise ValueError("bad frame fields")
    meta = (int(bool(valid)) << 7) | (seq << 3) | target_id
    head = bytes([0x6B, msg_type, meta]) + payload
    return head + bytes([crc8(head)])

def fixed10(value):
    if not math.isfinite(value):
        raise ValueError("invalid measurement: send VALID=0")
    scaled = value * 10
    q = int(scaled + 0.5) if scaled >= 0 else -int(-scaled + 0.5)
    if not -32768 <= q <= 32767:
        raise ValueError("measurement out of range: send VALID=0")
    return q

# Camera UART.write(packet): byte stream, not packet.hex() text.
packet = make_frame(0x02, 9, 1, True,
                    struct.pack("<hh", fixed10(150.3), fixed10(16.9)))
assert packet.hex(" ").upper() == "6B 02 C9 DF 05 A9 00 64"
assert crc8(b"123456789") == 0xF4
```

## 9. 本次接入、读取与验证

- 位置类型：`0x02` 物料、`0x03` 圆环、`0x09` 圆盘切点；每次观测只发一帧8字节，不带可变长文字或CRLF。圆环 a_deg/av/align/q 保留在本地显示，不改变位置帧定义；未经车体标定的图像行角不能编码成 ALIGN_YAW。
- 相机 UI/颜色标定文件继续使用比赛顺序 5黑/6浅蓝，线上映射为工程冻结顺序 5浅蓝/6黑，避免更改原标定样本的标签。
- 图像编号每次新图像 send 调用递增，包括限频跳过帧；线上只取低4位。普通输出最多20Hz，实际受识别帧率限制。MODE/VALID变化优先。
- 短写最多缓存一帧，50ms未写完就放弃。失效/强制切换时不继续发送旧有效半帧；异步等待55ms，让接收器50ms半帧超时，然后发送当前新观测。不 sleep、不注入换行；所以极端短写下失效帧不是立即上线，主控200ms超时仍须保留。正常完整写入失效帧可立即发送。退出/断电无法保证最后一帧成功。
- STM32 在 VisionTask 中解析，ISR仍仅复制DMA字节。CRC/语义失败只滑动丢首字节；嵌入6B/CR/LF/@按数据接收。两个端口分别缓存，类型或目标切换使该端口旧位置失效；错误/溢出后失效并重新同步。50ms内相同ID/SEQ/坐标有效重复帧不刷新接收年龄，不作为新观察。
- `Vision_GetPixel` 返回1表示已有快照（包括 valid=0），必须检查 `out.valid`。显式无效或接收年龄>=200ms时输出坐标清零；数据年龄是主控收到至当前时间，**不是图像采样年龄**。未发送 FRAME_INFO，不存在已知采样年龄/已标定毫米/可靠车体航向。

## 2026-10-07：原始三环行方向扩展（CAM1 v17 / MCU V32）

`0x0A RING_AXIS`不等于已标定车体偏航误差；原预留`0x05 ALIGN_YAW`不改变语义。

| 字段 | 编码 |
| --- | --- |
| TYPE | 0x0A |
| META | VALID、同图4位SEQ、ID=2 |
| D0,D1 | 小端int16，原始图像行方向×100；x向右/y向上，无向直线，范围[-9000,9000) |

## V194：CAM2无线障碍观测扩展0x86

仅CAM2电脑桥1.4.0支持；0x08原有OBS_DIST定义保持不变。

```text
6B 86 AGE10 GAP_LO GAP_HI RIGHT_LO RIGHT_HI CRC8
```

- `AGE10`：相机完成读帧到桥准备实际写UART的帧龄，向上取整到10毫秒；0～20有效。它不是其他类型的VALID/SEQ/ID位域。
- `GAP`：车头前沿到圆柱近侧外壁的净距离，uint16小端，当前接收50～500毫米。
- `RIGHT`：圆柱相对车体中心线的横向位置，右正左负，int16小端，当前接收±190毫米。相机左偏100毫米由电脑视觉侧修正。
- `CRC8`：沿用前7字节的CRC-8，多项式0x07。

PC仍使用PCV1 RESULT的epoch、帧号及相机原时间戳封装，发送AGE10占位0。桥在真正开始写UART前验证连接、epoch、图像帧和采集时效，重填AGE10与CRC；该旁路同时适用于CAM2的STOP和QR模式，不改变二维码四帧组及其会话校验。

主控只将其作为观测，接收后由主控当前比赛会话和前向导航状态决定是否标图/重规划；重复发布不重复消费，STOP/reset失效旧观测。主控另计UART接收与任务排队时间。图像或网络丢失只是不再提供新观测，不额外触发整车停机。

示例（帧龄50ms、净距300mm、车体右向-106mm）：`6B 86 05 2C 01 96 FF BE`。

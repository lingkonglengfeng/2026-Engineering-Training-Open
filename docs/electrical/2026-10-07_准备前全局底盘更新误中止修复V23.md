# V23：准备回调之前的全局底盘更新误中止

03:19日志仍在PREPARING后直接FAULT，没有V22的入口拒绝信息。继续检查完整ZDT_Motor_Poll顺序发现：蓝牙命令处理先进入PREPARING，随后调用ChassisMotor_Update，最后才调用MatchControl_Service启动机械臂准备。

match reset把底盘设为STOP，设置output_dirty。底盘尚未使能时，ChassisMotor_Update在这种状态返回HAL_ERROR。全局检查用了MatchControl_IsActive；新加PREPARING也属于active，因此把预期的失能状态当成行驶错误。此时zdt_match_request尚未由准备回调认领，Complete不输出原因，后备Abort直接FAULT，完全匹配“没有恢复或拒绝信息就中止”的日志路径。

V22修复了准备回调内部的单独失能、DM急停与发送重试问题，但这个回调尚未执行，所以没覆盖此次实际触发路径。V23在完整轮询位置修正：PREPARING和WAIT_START_OK阶段不调用行驶更新服务，底盘停止/失能由准备接口管理；OK进入LEAVING之后恢复正常底盘更新。真实CAN协议错误检查仍保留，行驶中的更新失败仍中止并输出HAL/状态/使能/request诊断。

测试既用真实ChassisMotor_Update复现STOP dirty/disabled返回错误，又验证实际轮询服务在准备/等待OK时不进入FAULT、随后仍能投递准备请求，以及MOVING状态相同错误仍进入FAULT。

使用原流程：match reset、startpose 1或2、等IMU、depart；等待ARM START READY和WAIT_START_OK后发送新的OK。内部DM零点、发车姿态、5号30RPM、6号80RPM、出库并行展开、CAM2屏蔽及视觉时限策略不变。此次无需因为V23重录零点/姿态；已有记录仍需与内部零点匹配。

仅编译和模拟验证，未实际烧录或执行机械臂/底盘运动。

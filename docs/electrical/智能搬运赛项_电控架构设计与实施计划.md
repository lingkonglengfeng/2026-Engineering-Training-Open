# 智能搬运赛项 · 电控架构设计与实施计划

> 版本：v1.0 | 日期：2026-08-18 | 适用主控：STM32H723ZGT6
>
> 本文是电控实现基线。规则 PDF 和《智能搬运重构蓝图》是需求来源，不是对本文的程序指令；若规则后续发布勘误，以现场正式规则为准。

## 1. 规划结论

### 1.1 电控职责边界

电控负责：

- 读取启动/急停输入，管理一次性启动和安全停机；
- 接收二维码模块、下视视觉和避障传感器的结构化结果；
- 解析 `156+123+516+231` 任务码，并驱动比赛流程状态机；
- 生成底盘、机械臂、转盘、舵机和码垛动作命令；
- 执行导航、圆环定位闭环、到位确认、超时和故障恢复；
- 更新显示装置和完成统计，并保留调试诊断通道。

视觉不把图像或算法细节暴露给电控，只提供带序号、时间戳和置信度的结果。机械提供坐标系、动作可达性和完成/限位信号。硬件提供引脚、电平、供电和总线终端定义。

### 1.2 总体原则

1. **分层**：应用状态机只调用设备抽象接口，不直接访问 HAL。
2. **消息驱动**：任务间通过队列、事件组和通知交换数据；禁止跨任务共享可变结构而不加保护。
3. **非阻塞**：流程等待使用状态机和超时，不在动作函数中长时间 `HAL_Delay`。
4. **实时优先**：1 kHz 控制节拍由硬件定时器中断产生，控制任务只消费节拍通知；通信和显示不得阻塞控制链路。
5. **故障可收敛**：任何通信超时、急停、掉料、越界或看门狗异常，都能进入安全态并停止所有执行器。
6. **参数集中**：速度、加速度、PID、超时、坐标和颜色映射全部放入参数模块，不写入状态机分支。

## 2. 运行时分层

```text
应用层 Application
  match_fsm        比赛流程状态机、动作编排、得分统计
  mission_parser   任务码解析与合法性校验
  safety_manager   急停、超时、心跳、故障锁存
  display_service  任务码/统计/故障显示

领域层 Domain
  motion_manager   底盘导航、圆环定位、避障策略
  manipulator      转盘取料、载物台放料、粗加工区/暂存区放置、码垛
  perception       二维码/颜色/圆环/障碍物结果模型
  scoring          抓取、放置、码垛和回站统计

设备抽象层 BSP/Drivers
  chassis_can      4 个 ZDT 电机和底盘同步命令
  arm_can          达妙机械臂 CAN1
  vision_uart      二维码/视觉协议和 DMA 环形接收
  display_uart     陶晶驰屏幕协议
  servo_pwm        夹取舵机、转盘舵机
  hwt101_uart      HWT101 TTL 姿态传感器（USART10）
  i2c_sensor       I2C 扩展传感器
  input_output     按键、限位、LED、急停

STM32 HAL/CMSIS/FreeRTOS
```

应用层禁止包含 `stm32h7xx_hal_*.h`。设备抽象层向上只暴露 `open/send/read/stop/health` 等接口，便于替换电机型号、视觉模块或屏幕。

## 3. FreeRTOS 任务模型

优先级使用 CMSIS-RTOS 数值；数值越大越优先。控制相关任务优先于流程和显示。实际栈大小以 `uxTaskGetStackHighWaterMark()` 实测后收敛。

| 任务 | 周期/触发 | 建议优先级 | 初始栈 | 主要职责 |
|---|---:|---:|---:|---|
| `SafetyTask` | 事件 + 10 ms | 48 (`Realtime`) | 512 B | 急停、心跳、故障锁存、统一停机 |
| `ControlTask` | 1 kHz 通知 | 40 (`High`) | 768 B | 底盘/机械臂控制计算、输出最新目标 |
| `MotionTask` | 10 ms | 32 (`AboveNormal`) | 1024 B | 导航、圆环 PID 外环、避障降速 |
| `MatchTask` | 事件驱动 | 24 (`Normal`) | 1536 B | 比赛状态机、动作原语编排 |
| `PerceptionTask` | UART/CAN 事件 | 24 (`Normal`) | 1024 B | 解析视觉、二维码和障碍物帧 |
| `ActuatorTask` | 事件/10 ms | 24 (`Normal`) | 1024 B | 舵机、转盘和机械臂动作序列 |
| `CommsTask` | UART/CAN 事件 | 16 (`BelowNormal`) | 768 B | 统一发送队列、重试、链路统计 |
| `DisplayTask` | 100 ms + 事件 | 8 (`Low`) | 512 B | 屏幕刷新，故障态优先 |
| `TelemetryTask` | 100 ms | 8 (`Low`) | 768 B | 调试日志、运行计数、参数快照 |
| `Idle/Watchdog` | 空闲钩子 | 1 | - | 喂独立看门狗前置条件、低功耗/统计 |

### 3.1 RTOS 对象

| 对象 | 类型 | 生产者 → 消费者 | 约束 |
|---|---|---|---|
| `q_vision_rx` | `Queue` | ISR/UART → `PerceptionTask` | 固定长度帧，满队列丢旧帧并计数 |
| `q_cmd_motion` | `Queue` | `MatchTask`/`MotionTask` → `ControlTask` | 只保留最新目标或显式序号 |
| `q_actuator` | `Queue` | `MatchTask` → `ActuatorTask` | 动作带超时、取消令牌 |
| `q_display` | `Queue` | 各服务 → `DisplayTask` | 低优先级，可合并重复刷新 |
| `q_can_tx` | `Queue` | 领域层 → `CommsTask` | 发送端单一所有者，避免 HAL 竞争 |
| `eg_system` | `EventGroup` | ISR/任务 → `Safety/Match` | `START/STOP/FAULT/READY/ESTOP` |
| `sem_control_tick` | 计数信号量/任务通知 | `TIMx ISR` → `ControlTask` | ISR 只发信号，不做浮点和 HAL 总线访问 |
| `mtx_params` | `Mutex` | 参数服务/显示/遥测 | 参数更新采用快照，禁止持锁发串口 |

UART 接收使用 DMA + 空闲线中断或环形缓冲，ISR 只搬运字节并唤醒解析任务。FDCAN 使用 RX FIFO + 过滤器，ISR 只入队。所有 `FromISR` API 的中断优先级必须满足 FreeRTOS 的 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 约束。

## 4. 比赛流程状态机

状态机是唯一能推进比赛阶段的模块，所有状态都有进入动作、运行条件、成功条件、超时和失败转移。

```text
BOOT
  -> SELF_TEST -> WAIT_START -> READ_TASK
  -> FIRST_PICK_1 -> FIRST_PICK_2 -> FIRST_PICK_3
  -> FIRST_PLACE_PROCESSING -> MOVE_TEMP_STORAGE
  -> RETURN_RAW_MATERIAL -> SECOND_PICK_1 -> SECOND_PICK_2 -> SECOND_PICK_3
  -> SECOND_PLACE_PROCESSING -> STACK_TEMP_STORAGE
  -> RETURN_START -> FINISH

任意运行态 -- STOP/FAULT/超时 --> SAFE_STOP
SAFE_STOP -- 人工复位且未启动过 --> WAIT_START
```

每个物料动作必须满足 `夹取确认 -> 载物台存在确认 -> 才允许离开原料区`。放置动作必须满足 `目标环定位有效 -> 执行放置 -> 视觉/限位确认 -> 更新统计`。第二批码垛额外检查颜色一致，失败则锁存 `STACK_COLOR_MISMATCH`，不得继续盲动。

### 4.1 状态数据

```c
typedef struct {
    uint8_t color[3];       /* 1 red, 2 yellow, 3 blue, 4 green, 5 light-blue, 6 black */
    uint8_t ring[3];        /* 1..6, task groups 2/4 */
    uint8_t valid;
} mission_batch_t;

typedef struct {
    mission_batch_t batch[2];
    uint8_t raw_code[32];   /* canonical ASCII, NUL terminated */
    uint8_t parse_error;
    uint32_t sequence;
} mission_t;
```

任务解析必须拒绝：组数不是 4、每组不是 3 位、字符不在 `1..6`、圆环编号越界、同一批颜色/圆环违反规则、缓冲区无 NUL 或超时不完整帧。解析成功后保存规范化字符串并发送显示事件。

## 5. 设备接口与通信契约

### 5.1 视觉/二维码统一帧

建议先冻结为 ASCII 线路协议，便于调试；量产/决赛前可切换为二进制，但上层消息模型不变。

```text
@QR,156+123+516+231,seq=12*CS\r\n
@RING,id=3,x=12.4,y=-1.8,theta=0.6,conf=0.94,seq=21*CS\r\n
@COLOR,id=2,color=6,conf=0.91,seq=22*CS\r\n
@OBS,front=184,left=255,right=93,valid=1,seq=23*CS\r\n
```

`CS` 为从 `@` 后到 `*` 前的 XOR-8；每帧必须含长度上限、序号、校验和接收时间。超时、重复序号和校验错误只记故障计数，不直接让普通流程继续使用旧数据。`PerceptionTask` 输出统一结构：`type/seq/timestamp/valid/confidence/payload`。

### 5.2 电机与舵机

- FDCAN1（PA11/PA12）用于机械臂；FDCAN2（PB12/PB13）用于 4 个 ZDT 底盘电机；FDCAN3 预留。
- 底盘输出采用“目标速度 + 斜坡 + 同步触发”，四电机一组提交，禁止逐电机无同步地更新导致车体扭矩不一致。
- 设备驱动必须提供 `enable() / set_velocity() / set_position() / stop_immediate() / read_status()`，并把驱动器堵转、过热、过流、限位映射到统一故障码。
- 舵机仅由 `servo_pwm` 服务操作，动作使用目标角、最大变化率和到位等待，不在业务层直接修改 CCR。

### 5.3 硬件接口事实源

以当前 `Engineering_Training_Project.ioc` 为实现事实源：FDCAN1=PA11/PA12，FDCAN2=PB12/PB13，FDCAN3=PF6/PF7，USART1=PB14/PB15，USART2=PA2/PA3，USART3=PB10/PB11，UART4=PC10/PC11；SPI1 使用 PA5/PA6/PA7，PA4 为 GPIO 软件 CS。与旧文档中出现的 PA9/PA10、PB8/PB9 描述冲突时，必须在硬件评审中确认并修正文档，不能凭经验改代码。

## 6. 控制与安全策略

### 6.1 控制链

```text
1 kHz TIM ISR
  -> ControlTask 通知
  -> 读取原子化目标快照
  -> 底盘速度/PID/限幅/斜坡
  -> 写入 CAN TX mailbox
  -> CommsTask 发帧
```

视觉圆环定位是 10~20 Hz 外环，输出位置误差和置信度；`MotionTask` 在置信度不足时降速或请求重识别。1 kHz 内环不得等待视觉、串口、互斥锁或动态内存。

### 6.2 统一安全态

`SafetyTask` 维护故障锁存字：`ESTOP`、`START_INVALID`、`CAN_TIMEOUT`、`VISION_TIMEOUT`、`MOTOR_FAULT`、`LIMIT_HIT`、`PAYLOAD_MISSING`、`STACK_COLOR_MISMATCH`、`TASK_PARSE_ERROR`、`WATCHDOG_NOT_READY`。进入 `SAFE_STOP` 时按固定顺序：停止运动目标 -> 发送电机急停 -> 禁止舵机/机械臂危险动作 -> 亮 ERR_LED -> 刷新屏幕 -> 保留故障快照。

急停 ISR 只置位事件和硬件断使能（若硬件具备），不调用可能阻塞的 HAL 或 RTOS API。恢复必须人工确认；比赛“一次启动机会”通过 `start_consumed` 锁存实现，复位前不得再次启动。

## 7. 工程目录建议

在现有 CubeMX 生成目录外新增 `App/`，避免重新生成覆盖业务代码：

```text
App/
  Inc/
    app_types.h        统一消息、状态、故障码
    app_config.h       参数默认值和版本
    app_events.h       RTOS 对象和事件位
    mission_parser.h
    match_fsm.h
    safety_manager.h
    motion_manager.h
    perception_protocol.h
    device_interfaces.h
  Src/
    freertos_app.c     任务和 RTOS 对象创建
    mission_parser.c
    match_fsm.c
    safety_manager.c
    motion_manager.c
    perception_protocol.c
    display_service.c
    actuator_service.c
    telemetry.c
  BSP/
    bsp_can.c/.h
    bsp_uart_dma.c/.h
    bsp_servo.c/.h
    bsp_input.c/.h
```

`Core/Src/freertos.c` 只保留 CubeMX 入口和 `MX_FREERTOS_Init()` 调用，业务任务放进 `App/Src/freertos_app.c`；这样重新生成 `.ioc` 后不丢失状态机和协议代码。

## 8. 分阶段实施计划

### 阶段 0：接口冻结（1~2 天）

- 核对 `.ioc`、原理图、接插件和实际板卡，冻结 CAN/UART/舵机/急停/限位表；
- 冻结视觉帧、二维码格式、超时和坐标系；
- 建立故障码、参数表、状态机转移表；
- 用旧代码只提取 PID、Mahony、运动学和动作经验，不复制其阻塞式流程。

**退出条件**：四方接口评审通过，任何引脚冲突有明确 owner。

### 阶段 1：底层可观测骨架（3~5 天）

- 配置 FDCAN RX FIFO/过滤器和 TX 队列；
- 将四路 UART 改为 DMA + IDLE 环形接收；
- 建立 `SafetyTask/ControlTask/CommsTask/TelemetryTask`，移除空转的 `defaultTask`；
- 完成 LED、急停、看门狗、运行计数和故障快照；
- 用 PC 模拟器发送视觉帧，验证校验、超时和重复包处理。

**退出条件**：连续 30 分钟总线/串口压力测试无堆栈溢出、队列溢出可计数且不死机。

### 阶段 2：动作原语（1 周）

- 完成底盘速度、原地旋转、里程/姿态闭环；
- 完成转盘取料、载物台确认、圆环放置、码垛动作；
- 所有动作支持 `start/poll/cancel/timeout/result`；
- 逐动作记录实测耗时、位置误差和电流/温升。

**退出条件**：动作原语可脱离比赛状态机单独运行，急停能在一个控制周期内停止目标输出。

### 阶段 3：任务状态机与视觉联调（1 周）

- 接入二维码解析、6 色和圆环定位；
- 完成第一批、第二批、暂存区码垛和回站流程；
- 加入物料在载物台确认、颜色一致、环号与顺序一致校验；
- 屏幕显示规范化任务码、阶段、成功/失败统计和故障码。

**退出条件**：仿真回放可覆盖正常、漏帧、错码、低置信度、障碍物和急停路径。

### 阶段 4：整车标定与回归（持续）

- 标定轮径、轮距、零位、舵机角度、圆环坐标、速度/加速度和各链路超时；
- 每次改参数自动记录版本、环境和结果；
- 按“单动作 -> 半流程 -> 全流程 -> 连续两次”回归；
- 最后冻结比赛配置，禁止现场临时改协议和引脚。

## 10. 本仓库当前差距

当前工程已经具备 STM32H723、FreeRTOS 源码、FDCAN1/2/3、USART1/2/3、UART4、USART10（HWT101 TTL）、SPI1、I2C1、TIM4 PWM 和按键/LED 的 CubeMX 基础。HWT101 已配置为 USART10 单字节中断接收，FDCAN 的 FIFO/过滤器数量仍为 0，其他高速 UART 尚未启用 DMA 接收。因此下一次提交应先完成阶段 1 的底层骨架，再开始写比赛状态机；直接把状态机塞进 `defaultTask` 会重现往届代码的阻塞和不可诊断问题。

# V280 / PC2.6.18：工位地图每轴上限放宽到 ±300mm

按本次要求，“工位地图”页每个坐标轴的偏移上限从 **±10mm 放宽到 ±300mm**。只改初赛，决赛仍 V245/PC2.6.7。上限是**允许调整的包络**，不是允许把车开出场地：主控整组应用前会同时检查四个车心接近点和对应视觉锚点是否仍在 2400×2400mm 场地内，越界整组拒绝、RAM 不变。

## 界面（PC2.6.18）

- 标题、说明、局部放大虚框和输入框范围都跟随实际上限显示；输入框范围为“基准±300mm”，1mm 步进不变。
- 局部放大图按上限自动缩放（±300mm 时仍能一次拖到全部范围），蓝点拖动/点击映射仍是 1px 对应实际毫米。
- “读取主控地图”后以主控回报的 `limit=` 为准：新固件显示 ±300；连旧固件时仍只允许 ±10，PC 不会超发写入。
- 面板先在本机校验（每轴偏移不超上限、坐标 0～2400mm）再下发 `fieldmap apply`，避免明显越界的整组命令发到主控才被拒。
- “应用全部到RAM”“保存当前RAM到W25”“从W25读回”流程、预览区分（空心基准/绿色RAM/蓝色预览）都不变；改图本身不发车。

## 主控（V280 PRELIM）

- `Core/Inc/station_map.h`：`STATION_MAP_LIMIT_MM` 10 → **300**。
- `fieldmap apply` 仍要求 8 个整数，顺序固定 QR/RAW/ROUGH/TEMP 各 dx dy；新增整组几何校验 `StationMap_Valid()`：基准+偏移后的**车心接近点**与**视觉锚点**都必须落在 0～2400mm 内，否则 `[FIELD MAP APPLY] REJECTED: ... within +/-300mm and on-field targets required`，原 RAM 保持。
- `fieldmap status` 的 `limit=` 改为实际常量（300）；`[ARM]` 启动特性串同步改为 `STATION_MAP_UI_OFFSETS300MM_W25_PRIVATE18_17`。
- W25 记录格式不变：int16 偏移、version=1、序号+CRC、初赛倒数 18/17 扇区双银行；旧 ±10 记录照常读取，启动只读不擦写。
- 示例（ROUGH，基准接近 1200/380、锚点 1190/360）：预览输入 (1204,394) → 偏移 (+4,+14)，自动接近目标 (1204,394)，视觉锚点 (1194,374)。所有工位仍共用同一个偏移整组，一、二轮都生效。

## 图上这个点：目标位置还是视觉纠偏后的位置？

- 地图上的空心点（基准）和蓝点（预览）是**车中心接近停车目标**，也就是主控固定路线/命名点要开到的位置（`x,y = 基准 + 偏移`）。它是“我要到达的目标位置”。
- 面板“视觉锚点”一行才是视觉纠偏参考（`anchor_x/anchor_y`）：它和接近点**同步加同一个偏移**，避免视觉对齐完成后目标又跳回旧坐标；它不是地图主点。
- 视觉纠偏**之后**的最终车心位置由相机闭环实时决定（像素误差→差速），面板不显示也不保存它；面板保存的只有基准、目标偏移和目标/锚点坐标。

## 验证

- 离线 `python tools/tests/run_station_map_tests.py`：92 项检查 0 失败，覆盖 ±300 整组接受、±301 拒绝、越场拒绝、锚点同步、W25 保存/损坏回退/存储忙。
- 离线 `python tools/tests/test_field_map_panel.py`：5 项通过，覆盖旧固件 `limit=10` 兼容、`limit=300` 组包、±300 边界、±301/越场/非整数拒绝、地图读回与保存链路。
- 未烧录、未实车验证。±300 只放宽参数，A*（含 6×6 车体膨胀、转向惩罚）与执行层不变：目标不可通行时仍按原逻辑吸附/告警或 NO PATH。

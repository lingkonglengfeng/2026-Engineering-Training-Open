# V287 PRELIM / PC2.6.21：最多两障碍，新观测替换最旧

原版本已经最多两条记录，但第3个独立障碍会LIMIT2拒收。用户要求改为始终最多保留两条，并在新障碍到来时移除最旧的一条。

## 行为

同一障碍仍按原候选点/相邻格/短时位置关联更新，刷新最后有效观测时间，不消耗新槽。两槽满后，新独立障碍替换最后观测时间最早的记录；相同时间优先替换1号槽，uint32时钟回绕按有符号时间差比较。迟到的旧时间戳不能把记录的新时间改旧。

原已落图障碍因KNOWN分支绕过更新，这次补齐同一已拥有障碍的重观测更新，使它能真实刷新时间。手动已知地图区域仍不自动当成新视觉对象。接收条件、视觉确认帧数和坐标换算不放宽，停止/不满足原有效上报条件的画面不会因此变成新记录。

淘汰时移除旧槽专属地图，清空其观测/吸附/已落图状态；新对象按原近距提交或V286出发前落图机制加入地图，不携带旧道路封锁。仍然最多两条有效视觉记录，不按地图格子数计数。

## 地图与存证

运行期格子用来源位表示：bit0手动障碍，bit1/2对应两视觉槽。各槽可独立删除/替换矩形或圆形范围；剩余视觉对象和手动区域的重叠格保留，固定场地禁区不受影响。对外GridNav_IsObstacle仍返回布尔值，规划器仍只判断是否被占用；没有新增大数组。清空对象时同步清视觉槽，避免没有记录的孤立旧封锁。

日志新增[VOBS EVICT] session/obstacle/old_site/new_site/removed，显示替换的槽和移除的占用格数。PC2.6.21收到替换日志后清理该槽的存证关联及去重键，使同槽/同候选点后来再次成为新实例时仍可自动保存截图，已归档历史文件保留。

没有新增停机保护、速度门限或相机指令；继承V286出发前使用确认缓存及原NO_PATH暂停。不因替换主动停车，下一次原规划/避障处理使用更新后的地图。

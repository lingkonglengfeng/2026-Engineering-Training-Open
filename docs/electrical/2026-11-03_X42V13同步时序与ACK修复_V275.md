# V275 PRELIM：X42 V1.3同步时序与ACK修复

初赛固件V275，上位机仍PC2.6.15，决赛仍V245。本地提交，暂不推送，不烧录、不运行实车。保留V274短段保持航向导航、V273 CAMERA重发和V272参数W25，无需重调原参数。

## 原因与依据

最新run009、run010出库300mm目标的实测里程分别约-0.1/-0.3mm，约1.8秒触发原有`odometry no progress`。V274开启同步缓存，但按新板方式紧接着发送广播，未适配旧V1.3命令间隔和驱动器接收确认。CAN FIFO入队成功不能证明驱动器已完成命令处理。

仓库厂家手册`docs/vendor/zdt-x42s/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.pdf`第7页明确旧X42 V1.3支持多机同步，但耗时长、多条发送；第37页要求同步命令间留几毫秒，第60页给出广播FF 66 6B。旧日志缺少驱动器同步回执，不能据此断言唯一失败点。

## 修复

- 速度同步改为非阻塞状态机：冻结本批四轮目标，逐轮发送F6缓存速度命令，每次至少间隔3ms。四轮收到各自本次发送之后的新`F6 02 6B`回复，且最后一轮也留足间隔后，才入队广播触发。
- 某轮20ms没有确认就重发该轮同一快照；不把旧ACK或FIFO入队成功当成确认，不发送半组同步。负回复和缺回复保留等待诊断，不新增故障停机；原里程无进展/总动作超时保持。
- 1～4号有效F6应答在CAN接收中断中记录为volatile单字令牌，主控读取原子快照，不依赖串口日志消费速度。坏校验、错误帧型/地址/包号不作为本轮确认。
- 四轮使能/失能恢复原即时执行方式，不缓存使能，不让使能覆盖速度缓存。速度批次独立处理。运动同步仍开启。
- 原控制器与斜坡继续按4ms计算，但实际线上四轮目标提交为协议批次，不能再每4ms连发五帧；最快受3ms间隔和ACK延迟限制，需实车核对转向及视觉闭环效果。速度、加减速和PID数值不变。
- 普通减速到零会继续提交最后的零速批次，不能因软件斜坡已为零而漏发物理停车。立即STOP、初始化/重新使能和转向衔接直行会取消未触发的旧软件快照；原直接STOP路径保留，不等待ACK或同步批次。

没有使用阻塞delay或在中断发送电机命令。

## 日志与使用

烧录`Engineering_Training_Project_V275_PRELIM.hex`，继续用PC2.6.15正常准备发车。若缺少应答，会每约500ms打印：

```text
[CHASSIS SYNC] waiting F6 ACK id=... reply=0x..; retry SAME snapshot, no trigger yet
```

若持续无F6回复，需确认四个驱动器的控制命令应答配置已开启，并按轮号检查；新回复为E2/EE时需结合驱动器状态/协议核对。日志里的旧02令牌也不会被当成本批接收成功。当前版本不绕过ACK自动改成非同步，也没有取消里程无进展检查。

## 验证

实际底盘/场地控制器配假CAN端口、生产CAN接收ISR共30893项检查通过，覆盖目标缓存与3ms间隔、四轮齐全后触发、缺ACK重发、真实解析02/负回复/坏校验、物理零速批次提交、STOP取消和原控制语义；版本/指令21项通过。Keil0错误0警告。离线检查不能证明实机四轮已动作，需烧录后验证。

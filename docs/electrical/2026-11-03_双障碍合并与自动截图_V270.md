# V270 PRELIM / PC2.6.13：双障碍记录与自动截图

本次只更新初赛 `codex/arm-control-panel`，决赛保持V245。代码本地提交，按用户要求不推送、不烧录。相机桥不需要更新；烧录初赛V270后，重开原桌面“视觉上位机”入口，连接CAM2和主控串口即可自动记录，无需另按截图键。截图在电脑保存，不写入W25。

## 两条障碍记录

每轮最多保留两条视觉障碍记录，已经落图的记录也占一个名额。15个候选吸附点仍用于规划，并非只能识别两个候选点。准备/重置清本轮记录和原有临时障碍；不会按观测年龄删除已经确认的静态障碍。

同一候选点、实测落点处于同一或相邻50mm栅格（含斜邻格），合并到最近的已有记录。连续观测相隔不超过1000ms且落点相距不超过250mm，也关联为同一条：覆盖本轮约205mm/0.8秒的P01→P02跳点。未落图时更新吸附候选；已落图后保留原规划位置，不因邻格重识别再封一条路。第三个无法关联的观测返回`LIMIT2`，不添加第三个路障，不新增停机。

这限制的是记录数，不能证明真实障碍身份。两个相距很近的实物可能合并；两个相距很远的估计也不会为了凑数量强行合并。现有识别、800mm起减速、400mm内停车落图、NO_PATH等待人工处理等流程保留；速度不变。

## 自动保存内容和位置

默认目录：`vision/pc_vision/screenshots/cam2/obstacles/<本轮串口日志文件名>/`。独立串口会话没有运行日志时按串口会话分组。

每组同名文件：

- `_raw.png`：CAM2原图。
- `_overlay.png`：识别标注图，叠加障碍编号、候选点、小车坐标/航向、视觉落点和规划位置。
- `.json`：主控完整确认行、当前小车坐标与航向、观测时小车坐标与航向、原始视觉落点、吸附规划点、串口会话/本轮日志、图像帧号和各端时间。

首次确认、吸附点变化、正式落图各存一组；重复帧不反复存。同一额外候选的`LIMIT2`也只存一次便于查误识别。`KEEP_NEARER`仍会保存已经确认的第二条记录。串口日志同时打印保存路径，上位机CAM2状态显示本轮记录数和本次上位机存证组数。

有线串口回传用`session/seq`关联发送前缓存的原始观测帧，JSON的`exact_observation_frame=true`。现有相机无线桥未携带这对编号，因此无线确认及落图保存收到确认时的当前画面，明确标注`exact_observation_frame=false`和`image_kind=current_camera_view`；JSON保留图像、确认时间和原始确认上下文，不能将其当成严格同步的观测原帧。

保存使用有界后台队列，不在视觉/串口线程同步压PNG或写磁盘。队列满计入丢弃数，磁盘错误显示在上位机并写状态日志，不发送停车或改变运动指令。电脑图传或串口断开时无法补出缺失画面；没有画面时记录失败原因，不伪造截图。

## 串口接收时间修正

旧UART环形缓冲只保留字节，调度到命令解析时才传入HAL当前时间，导致“串口排队年龄”接近0；期间如果转向，旧观测可能套用错误时刻的车位姿。V270在接收环形缓冲同步保存每字节时间戳，用一条`vobs`首字符的到达时间计算排队延迟，再使用既有位姿历史换算。沿用原200ms观测上限；普通准备、OK等指令仍使用原处理时间，未更改发车语义。该问题在代码中成立，但仅凭旧日志无法证明每次假障碍都由它引起。

`VOBS ACK`新增`obstacle/site/merged/raw/plan/car/yaw/frame_car/frame_yaw/age/queue`；`VOBS MAP`记录落图时车位姿和记录编号；`VOBS STATE`增加`obstacles/phase/wait/mask/stable_ms`，便于区分等待停车反馈与无路等待。

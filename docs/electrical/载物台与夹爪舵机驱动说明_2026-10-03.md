# 载物台与夹爪舵机驱动

新增 `Core/Inc/arm_servo.h`、`Core/Src/arm_servo.c`，并扩展本次新增的机械臂驱动、串口处理及测试。原有 `servo.c/.h`、`tim.c`、任务、串口/CAN 分发及 Keil 项目登记均未由本次修改。

## 通道与参考来源

| 机构 | 当前工程引脚 | PWM 通道 | 默认控制 |
| --- | --- | --- | --- |
| 夹爪 | PD12 | TIM4_CH1 | 型号未知，仅启用脉宽接口，开合位置待标定 |
| 载物台 | PD13 | TIM4_CH2 | 按学长工程的 360° 位置映射，支持三个载物位置 |

用户指定的参考工程为 `D:\projects\Engineering training competition\competition project - 11_26_比赛版`。只读取参考，没有修改它。

- `Device/SERVO/servo.c` 的 `servo360_angle_control()`：`compare = 500 + 2000 × angle / 360`，写入 TIM2 比较值。
- `Core/Src/tim.c`：TIM2 预分频 239、周期 19999；结合其 240 MHz 定时器时钟，计数单位为 1 μs、PWM 周期为 20 ms。
- `Device/Car_ctrl/car_ctrl.h`：`carplate1_pos=44`、`carplate2_pos=137`、`carplate3_pos=229`、`carplate_ori=160`。
- `Device/TASK/task.c`：载物台在 TIM2_CH3 使用上述三个角度进行位置切换。因此本次按可定位的 360° 舵机处理，不按连续旋转速度舵机处理。确切型号仍未知。

新工程使用 TIM4，按当前 275 MHz 时钟重配为 PSC=274、ARR=19999，保持相同脉宽含义。角度换算四舍五入，旧工程截断，差异最多 1 μs。三个默认位置为 744、1261、1772 μs；160° 对应 1389 μs。新机构上的零位、方向和槽位仍需实测调整。

## 初始化与任务

```c
#include "arm_servo.h"

/* 原工程 MX_TIM4_Init() 完成后，在机械臂所有者任务里执行一次。 */
arm_servo_config_t servo_cfg;
ArmServo_DefaultConfig(&servo_cfg);
HAL_StatusTypeDef result = ArmServo_Init(&servo_cfg);
/* 必须检查返回值，再接受舵机命令。 */
```

初始化配置两路 PWM，但不启动输出，不自动使能舵机。显式使能夹爪时第一帧为 1500 μs；载物台为 1389 μs，舵机会从实际位置移向该命令位置。首帧不是物理反馈；可在初始化前修改各自 `enable_us`。

新增模块独占 TIM4，不能同时调用旧 `Servo_Init/Servo_Update/Servo_Set*`。两套驱动虽然符号不同，仍会争用同一个定时器。当前原有 `Servo_*` 没有外部调用者。

不需要新增任务。新 `ArmCalibration_Poll()` 已调用 `ArmServo_Update(HAL_GetTick())`，按前述机械臂说明将它接入 `armTask` 的 10 ms 循环即可。普通目标变更采用非阻塞脉宽斜坡，默认 500 μs/s；长时间调度间隔按最多 50 ms 计算，避免恢复后突然补走大幅度。达妙使能握手及串口打印仍可能阻塞所有者任务，这期间硬件保持上次 PWM，斜坡暂停。

把 `arm_servo.c` 与此前的 `arm_driver.c`、`arm_calibration.c` 一起登记进 Keil。原任务/串口/CAN 接入点仍按《机械臂三轴驱动使用说明》处理，本次未自动接入旧代码。

## 串口调试

所有命令以回车结束，经 `ArmCalibration_PostCommand()` 投递，由机械臂任务处理。不要一次连发动作序列，应观察机构并等待输出斜坡结束。以下数字为调试示例，夹爪实际张开/夹紧脉宽由实测决定。

```text
arm table enable
arm table go 1
arm table go 2
arm table go 3
arm table angle 160
arm table pulse 1400
arm table save 1
arm table stop
arm table disable
```

`table save 1|2|3` 保存当前稳定输出，修改 MCU RAM 中的槽位，不写 Flash；还在斜坡过程中会拒绝保存。槽位编号使用 1–3。

```text
arm grip enable
arm grip pulse 1500
arm grip save open
arm grip pulse 1600
arm grip save close
arm grip open
arm grip close
arm grip stop
arm status
```

必须先确认实际张开、夹紧位置，再分别 `save open/close`。没有对应标定时，`open/close` 报错，不拿学长夹爪的 186°/238° 冒充本车开合值。保存前应确认斜坡已结束并且实际机构到位。

若后续确认夹爪角度范围，例如 270°：先 `arm grip disable`，再 `arm grip span 270`，之后重新使能，即可使用 `arm grip angle 135`。载物台也支持 `span`，但必须在对应通道禁用时修改。`arm grip/table speed <微秒每秒>` 可调整脉宽斜坡速度，不是舵机实际角速度。

## 停止与返回值

普通 `arm stop` 仍逐一尝试三个电机停止，并将两路舵机冻结在当前 PWM 输出，保持夹爪夹持及载物台位置。不会把舵机自动送到中位，也不会主动撤销夹爪力矩。

`ArmServo_RequestSafeStop()` 可在 ISR 置位请求，下一次周期服务停止两路 PWM 并锁存。需要人工处理现场后用 `arm grip clear` 或 `arm table clear` 清除这个**全局舵机安全停锁存**，再分别显式使能。安全停会撤销 PWM，持物风险由机构与上层流程处理；它不同于普通保持停止。未锁存时 `clear` 不改变输出。

PWM 启动/停止失败会返回底层状态并标记故障，停止失败不会伪报已关闭。之后可重试 `disable`；成功后再显式使能。超范围脉宽、角度、非法编号、NaN/Inf 和未标定动作都报错，不静默截断。模块只针对位置舵机，不能把连续旋转舵机的非中位脉宽当作位置保持。

`output_us`、`target_us` 和 `ramping` 是软件输出状态，不是实际角度、到位或夹持反馈。PWM 保持不证明抓到了物料。

## 验证

GNU Arm GCC 与 Keil Armclang 以 Cortex-M7/硬浮点分别编译三个新增模块，使用 `-Wall -Wextra -Werror`，通过。两组 Unicorn 模拟测试分别 888、883 个检查通过：包含原机械臂测试、TIM4 比较寄存器写入、两路通道独立、参考槽位、斜坡限速、普通停止保持、开合位置保存、参数拒绝、安全停及 PWM 失败处理。没有实机烧录或输出测试。

新舵机独立对象约 3.8 KiB 代码、92 B 静态 RAM；三个新增模块对象合计约 14.1 KiB 代码、1041 B 静态 RAM。不新增任务、动态队列或任务栈；最终固件还需计入链接及格式化/数学库依赖。实机需测量 PWM 20 ms 周期、脉宽、方向和有效行程。舵机功率来自原设计的独立供电，与主控共地；实际保持电流与功耗取决于舵机和负载。

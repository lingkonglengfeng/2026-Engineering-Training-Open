# V29：按用户两组实测角度设置默认姿态

| 姿态 | 5号升降角度 | 6号伸缩角度 | DM角度 |
| --- | --- | --- | --- |
| camera（06:05:56） | -0.6647° | -0.0055° | -0.0162° |
| start（06:06:40） | -0.7526° | -186.8170° | +134.6173° |

对应原始计数：camera为5=-121、6=-1；start为5=-137、6=-34009。两组日志5/6零点均为0counts，DM raw_deg与arm_deg相同。默认值按这些现有零点解释，写入主控源码后重新编译；主控重启恢复这两组默认值，不使用W25姿态存储，不发送DM零点FE。

使用：

```
&arm camera
```

回第一组摄像头姿态；等待ARM CAMERA READY。

```
&arm start
```

回第二组发车姿态；等待ARM START READY。

查询目标：`&arm camera status`、`&arm start status`。查询实际角度：`&arm query 5`、`&arm query 6`、`&arm query dm`。

发车仍使用`&prepare 1`或`&prepare 2`，自动恢复这组start；等WAIT_START_OK后发`&OK`，出库后与驶向QR同时恢复这组camera。速度继续5号30RPM、6号80RPM，顶部容差和>100mm下降保护不变。

本次仅设置姿态目标，无需重新写DM内部零点。若之后重新定义零点，角度的参照会改变，应重新核对两组实测姿态。姿态到位沿用现有允许误差；5号这两次约0.088°的差异很小，不要求为这点差别反复纠正。

可以临时修改目标（RAM）：

```
&arm camera set -0.6647 -0.0055 -0.0162
&arm start set -0.7526 -186.8170 134.6173
```

`&arm camera defaults`、`&arm start defaults`也恢复上述实测值。startup标记CAMERA_DEPLOY_V29，start启动信息会显示实际默认三轴角度。

验证包含start默认135度附近恢复、新参考绑定；camera从第二组实测计数与DM角度返回第一组，确认6号使用回缩方向，完成后角度匹配且不写DM零点；并保留原300度长行程测试场景作为显式自定义目标的回归。仅编译和模拟，未烧录板卡、操作电机或上传相机程序。

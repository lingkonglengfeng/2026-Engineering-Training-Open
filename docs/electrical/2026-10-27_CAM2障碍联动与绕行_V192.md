# CAM2 障碍联动与绕行 V192

本版在现有双路电脑视觉、主控串口日志和比赛路径上增加前视圆柱障碍的试验性联动。CAM1物料/环/圆盘与CAM2扫码合同保留；原V191放料微调与全程计时保留。相机桥接仍为1.3.0，无需因本功能重新安装。

## 数据口径

- CAM2输入为640×480已转正原图；黑色圆柱按规则直径50毫米处理。
- 用户提供的约300毫米、200毫米均为**车头前沿至圆柱近侧外壁的净距离**，两张对应中段宽度约78、122像素。
- 初版经验估距 `gap_mm ≈ 23900 / width_px`，摄像头相对车体中心线约向左100毫米。
- 横向右为正，初估 `right_mm ≈ -100 + 50*(u-319.5)/width_px`。此式假设镜头朝向与车身平行、畸变影响较小；只有两组近距离约数，未完成独立精度验证。
- 达到约78像素且连续新帧确认后，才有机会报告近障。近于200毫米的外推仍是粗估，界面明确标注；不以截断高度估距，左右截断不报告横向位置。
- 地图圆柱中心前向为 `gap+140+25` 毫米，140来自现有280毫米车体模型。占位半径采用圆柱25毫米加定位余量25毫米，覆盖相交栅格；现有车体膨胀继续由规划器完成。

## 通信与动作

沿用上位机已集成的主控调试串口（用户当前COM10、115200），不是通过二维码结果帧夹带控制命令。两路相机经热点图传，PC串口负责本版障碍联动。

主控状态行：

```text
[VOBS STATE] v=1 session=123 armed=1 eligible=1 x=... y=... yaw=...
```

PC裸ASCII报告，CRLF结尾，长度不超过现有63字符控制台限制：

```text
vobs <session> <sequence> <front_gap_mm> <body_right_mm> <age_ms>
```

年龄是PC取得/解码该帧至实际串口写出的时间，包含PC待发送时间；主控另计入其控制台排队时间，使用最近8个轮位姿样本回推观测对应的位置。它**不代表相机曝光到主控的完整端到端时延**。自动观测使用最新单槽，实际发送前复查会话、新帧与开关；不挤满手工指令队列。轻量观测由视觉工作线程直接提交，截图或Tk绘图阻塞不会切断后台更新。

首次支持前向直线路段。主控在合适的里程状态下才置eligible；横移、倒车、转弯、机械臂工位作业不把前视图像当作行驶方向。开启需静止；按用户最新要求保留现有速度参数（当前默认比例0.65），没有新增低速开启限制，也不自动调速。STOP/reset后会话失效，不由后台自动重新开启。

收到合格观测后，保留当前比赛请求与工位路径目标，暂停当前底盘段，取得后续真实轮编码器稳定样本并结算已行进距离，然后增添障碍、从实际位姿重新规划。地图Y轴翻转沿用原换算；绕行专用精确段距吸收非格心起止偏差，并核验实际车体足迹和转向扫掠。绕行真正到达原目标后，才按原流程完成该动作，不提前报告工位到达。

## 已提前告知用户的暂停行为

正常避障需暂停当前运动段以便重规划。若重规划无路，保持本次避障暂停位置，打印无路信息，等待清障后手动重试；不把比赛置FAULT、不跳过工位，不继续执行已被障碍阻挡的旧路径。此行为在实现前已向用户说明。

不新增图像丢失、串口失联或低置信度导致的整车停机保护。这些情况只停止发送/接受不合格障碍观测并显示原因；现有程序原有错误处理保留。

## 首次操作

1. 更新本版主控HEX与电脑上位机代码；相机桥仍使用原1.3.0。只开一个上位机实例。
2. 双路接入运行，接入主控串口；关闭其他占用COM10的串口工具。
3. 保持当前速度参数，不额外发送调速命令；第一版按用户要求以现有速度试验。
4. 发送 `&prepare 1` 或 `&prepare 2`，等待两路相机回执及机械臂READY。
5. 在CAM2页显式开启障碍联动，确认主控VOBS状态为armed=1；若开启被拒绝，先查看日志原因；此版没有0.20速度限制。
6. 发送一次 `&OK`。先选择前向直线路段测试单个圆柱，在约30厘米触发区验证识别、停车位置、地图位置与绕行。速度按当前设置执行；首次实车结果用于验证实际识别、制动和重规划表现，不宣称已经验证速度与触发距离的适配性。
7. 无路时先确认场地是否真的容得下绕行。清障命令沿用原 `&free x y` / `&clear`；确认地图修改后手动发送 `vobs retry`。关闭障碍开关本身不恢复被阻挡的旧运动段。

本版默认不启用障碍联动，连接串口不会自动出发。自动绕行仍需实车验证制动、相机安装误差及热点时延；400毫米通道或外环局部空间可能无可行路径。

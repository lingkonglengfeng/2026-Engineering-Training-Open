## 默认流程

> **2026-10-05按用户要求，上电默认开启视觉纠偏。** 相机应运行统一入口；按工位握手成功后才使用新像素纠偏。需要纯底盘调试时停车发送`&valign off`临时关闭，之后可用`&valign on`重新开启；该开关只在RAM中，重启回到开启。

1. QR运动完成后，在 `ZDT_Align_RequestCameraMode()` 请求圆盘模式；收到成功ACK后才进入QR的 `WAIT_OK`。
2. 1号原料点：导航、工位朝向完成 → 检查圆盘模式ACK → 停稳 → USART1圆盘偏差纠偏 → 连续新图像确认对准 → 请求工位2圆环模式 → 成功ACK → `WAIT_OK`。
3. 2号粗加工点、3号暂存点：导航、工位朝向完成 → 检查当前工位圆环模式ACK → 停稳 → USART1中间圆环偏差纠偏 → `WAIT_OK`。
4. 第二轮开始去1号点时，再请求圆盘模式；第二轮1号点对准后请求圆环。两轮均纠偏。

QR和回场等待点不进行本次圆盘/圆环纠偏。相机模式由同一路相机切换，不要求同一串口同时运行两个独立程序。

**串口切换已经接入统一服务程序。** 相机只上传并运行 `vision/maixcam_service/main.py`，保持双向USART1连线：MaixCAM A16/TX→STM32 PB15/RX，PB14/TX→A17/RX，共地，115200 8N1，3.3V TTL。原独立圆盘/圆环程序仅用于诊断，不响应SET。

`ZDT_Align_RequestCameraMode(station)` 通过 `Vision_RequestMode(camera,mode,station,target,20,0)` 异步发送8字节SET；圆盘模式8、工位1、target0，圆环模式3、工位2/3、target2。排队成功不视为切换完成；检查pending=0、confirmed=1、result=0以及模式、工位、目标、频率、标志和本次请求号匹配才继续。2→3即使仍识别圆环，也发新station=3请求，清除旧工位上下文。

开始驶向新工位时可以提前排队切换，相机设置和底盘运输并行；到站仍检查ACK。接收层500ms没ACK最多重试2次，总3次；流程阶段等待上限2500ms。失败ACK、超时、纠偏期间心跳确认丢失都会停车进入FAULT，不使用旧坐标。收到ACK后只调用 `Vision_ClearPixelObservations()` 清除到站前观察，保留模式和心跳状态，不调用会取消配置的 `Vision_SetCameraProtocol()`。

## 数据源与移动方式

| 工位 | 端口 | 观测类型 | 目标ID | 控制轴 |
|---|---|---|---|---|
| 1号点，两轮 | USART1，CAM1 | PLATE_PX，0x09 | 0 | X、Y |
| 2号点，两轮 | USART1，CAM1 | RING_PX，0x03 | 2，中间环 | X、Y |
| 3号点，两轮 | USART1，CAM1 | RING_PX，0x03 | 2，中间环 | X、Y |

数据沿用固定8字节协议 `6B TYPE META X_LO X_HI Y_LO Y_HI CRC8`，坐标小端有符号int16，除以10得到图像像素，右正、下正。图像中心已由相机程序转换成 `(0,0)`。圆盘程序的0x09观测是**底部水平切线的切点**；主控将这个切点对准相机设置的目标像素，并非圆盘几何圆心。若现场只需圆盘切线高度，设置1号点只控制Y。

默认控制增益是 `F=0.0007*dx`、`R=0.0007*dy`，单位为归一化速度/像素，仅为低速调试起点，不代表已标定像素毫米比例。前向/右向合轮速指令最高0.035、最低0.015；按250 RPM与当前轮径约为最高37 mm/s。靠近目标后每次最多移动100ms，停稳250ms后等待下一张新观察，实际每步通常几毫米。

## 完成、失效与后续位姿

- 两轴都在±5图像像素内，连续至少5张新有效观察且持续至少200ms、轮速为零及IMU角速度低，才宣布对准。反复读取同一帧不累计。
- 为避免4位线上SEQ回绕误计数，接收端增加本地 `observation_id`；重复帧不刷新它。到站前或停稳前的观察不驱动车辆。
- 无效、过期200ms、错误类型/ID以及UART上下文异常都停止当前移动，重新停稳再识别。2026-10-04根据低识别率现场反馈，临时将失去正确新观测的等待由10秒放宽到20秒、单次纠偏总时长由45秒放宽到90秒、累计移动指令时间由2.5秒放宽到10秒。外围阶段限时按纠偏配置加3秒覆盖ACK/里程查询，比赛单段120秒总超时保留。仍超限时失败停车，并打印最后像素偏差、累计移动时间和最新数据年龄；到位容差、稳定帧数和旧图像失效条件不变。
- IMU超过150ms未更新、航向变化超过3°、CAN错误、电机失能或 `STOP`/`match reset` 都结束纠偏。普通手动移动不会抢占正在纠偏的底盘。
- 纠偏前后查询四轮编码器，将实际平移投影到当前地图方向，更新后续导航起点；不重置IMU、不把视觉中心当作已知全局地标。麦轮滑移仍会影响这一段轮端位置估计。

## 调试命令

可通过UART4有线控制台或蓝牙发送，参数目前保存在RAM，重启回到本页默认值；原有 `&save` 不保存它们。修改参数时应停车并处于IDLE或WAIT_OK。

```text

&valign on                         启用自动到站纠偏（当前默认开启）
&vsource 1 1 plate 0 3              1号点：CAM1，圆盘，双轴
&vsource 1 1 plate 0 2              1号点：CAM1，圆盘，只控制Y
&vsource 2 1 ring 2 3               2号点：CAM1，中间环，双轴
&vsource 3 1 ring 2 3               3号点：CAM1，中间环，双轴
&vgain 1 .0007 0 0 .0007            1号点：Fdx Fdy Rdx Rdy增益矩阵
&vgain 2 -.0007 0 0 .0007           2号点：反转图像X对应的移动符号
&vtune 3 5 .035 100 250             3号点：容差px、最高速度、移动ms、停稳ms
```

首次实车验证固定相机高度与姿态，观察低速移动是否确实减小两个像素偏差；若某轴误差持续增大，停车后改对应增益符号。具体增益、像素容差和停稳时间需要实际标定，相机检测/曝光时延也需要在实车验证。

看到 `[CAM1] request ... waiting ACK` 表示请求已建立；`[CAM] mode ACK confirmed` 表示阶段切换已确认。`[ALIGN] station ...` 后依次等待ACK、停稳和正确新图像；`[ALIGN] done ...` 表示对准，1号点还要确认切圆环成功后才进入 `WAIT_OK`。`ok` 在切换或纠偏过程中不推进下一工位。尚未完成硬件双向通信、实际切换延迟和纠偏增益验证；最终固件使用主工程重新编译的HEX，不用覆盖后续改动的相机服务快照HEX。

### 主控停止/复位与相机v4配套

STOP、比赛取消/故障、match reset、dis/off/disable、关闭自动视觉纠偏，现在都会请求配置使用的相机进入STOP，并立即作废旧像素和本地模式gate。新的`Vision_RequestStop`只排队，不在运动任务里阻塞UART；若旧SET正在TX，保留其缓冲直到完成，卡住的TX由Vision任务按既有50ms期限abort，随后留55ms串口帧恢复间隔发送STOP。重复STOP/reset在同一在途停止请求上合并，旧ACK不能重新确认旧模式。

STOP确认前或停止超时后，新的识别模式请求返回BUSY，旧位置不可用。视觉开启时出发会检查停止复位是否仍未确认；无相机调试（valign off）继续可用。`&camstat`新增`reset`字段，1表示停止仍排队/等待确认/失败需重试，0表示停止障碍已解除。成功日志为`[CAM1] STOP reset ACK confirmed; old targets cleared.`；失败保持旧像素无效，提示用match reset重试和camstat检查，不假装已清相机状态。

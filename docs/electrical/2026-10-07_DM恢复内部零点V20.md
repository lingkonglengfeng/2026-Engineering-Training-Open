# V20：恢复DM内部零点，忽略W25软件零点

用户要求不再用软件零点，恢复DM电机自身保存的零点。启动只使用原始0rad作为DM回零目标，不加载旧W25软件零点、不自动发送FE、不在上电当前位置重新定义零点。旧W25记录保留但不生效，发车姿态的W25保存功能继续保留。

## 明确设置电机内部零点

先停止流程，并让底盘静止：

```
&STOP
&dis
&dm off
```

手动把DM转盘放到希望的机械零位，保持静止，再发送：

```
&dm zero save
&dm query
```

zero save通过DM自身FE指令请求保存当前输出轴为内部零点，要求新鲜、静止、已失能反馈；发送后验证反馈接近原始0，保持失能。保存零点会改变电机坐标，不能在任意角度每次启动都执行。电机断电保存是否正确仍需用户实际断电验证。

以后回零：

```
&dm home
```

arm camera也回到电机原始0。普通dm zero/zerohere等RAM软件零点入口及dm zero w25入口会拒绝，提示使用明确的dm zero save；避免无意修改电机内部Flash。

原发车姿态绑定旧DM软件参考，改用内部零点并设好之后，重新摆好发车姿态、失能DM并保持静止，执行arm start save一次，再查询arm start status。否则旧记录可能因参考不匹配被拒绝；不要悄悄把旧角度解释成新的零位。

## 并行展开的使能晃动修正

02:22日志中5号已确认到位，DM失能反馈速度0.12454rad/s（约7.1deg/s），旧W25使能准备要求<=0.05rad/s，所以DM home被拒绝并停止QR行驶。这不是视觉故障。

使能准备接受<=0.5rad/s的有限晃动，先用新鲜反馈使能保持当前位置，再向内部零位运动；更大速度返回BUSY，camera流程最多等待3秒、间隔100ms重试。设置零点仍要求<=0.05rad/s，回零到位仍要求角度1deg内、速度<=0.05rad/s且3组新反馈稳定至少200ms。不能将允许使能等同于已到位。

保留PMAX=18.5、升降30RPM、伸缩80RPM、CAM2屏蔽、心跳3.5秒和像素500ms过期停车、出库并行展开及里程计路径。

仅编译与模拟验证，未实机执行FE、烧录或电机断电验证。恢复内部零点方式不等于已证明此前任意角度上电回零异常的根因。

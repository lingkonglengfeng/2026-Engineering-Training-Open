# CAMERA反馈时间误判修复 V81

## 本次现场记录说明

V80完成圆盘三颗物料后，软件库存为`tray=0x7`。后续状态显示ROUND1 phase10、CAMERA state9（失败）；DM约−0.0162°，6号约−300.08°，5号离TOP约0.54mm，均有新鲜反馈且无当前堵转/保护。

因此，任务没有继续是因为先前已经进入失败状态，不是这些状态读取时电机仍未到位。`camera status`里的HAL0只代表状态指令执行成功，不代表CAMERA动作成功。失败之后，即使电机后来到位，也不能自动用当前姿态覆盖之前的失败。

旧版没有保留CAMERA最初的失败原因，日志又缺少相应FAILED段，不能凭稍后的健康状态唯一确定现场触发原因。

## 已复现并修复的缺陷

CAMERA、姿态动作和物料监控原来使用循环开始时取得的`now`，之后才读取DM反馈。CAN中断可以在这两步之间更新反馈和时间戳，导致反馈时间比`now`晚几毫秒。无符号`now-last_tick`此时溢出，最新反馈会被当成超过反馈期限。

加入模拟“读取反馈时推进时钟3ms并收到新帧”的测试后，旧版CAMERA、姿态动作、物料监控均能复现失败；修复后均通过。修复方式是先取得一致的反馈快照，再读取比较用的时钟。CAMERA入口也重新获取时钟，避免前面的发送、串口打印和调度等待使周期开始时间过旧。物料轴状态检查同样在快照后读取时钟。

本修复不扩大反馈超时、角度或高度容差，也不忽略堵转/保护。真正过期的反馈仍失败，STOP/失能仍会取消任务。补充了跨32位毫秒时钟回绕的CAMERA测试。

## 新增的故障回溯

```text
&arm camera status
&arm round1 status
&match status
```

CAMERA失败会保存：失败阶段、原因、发生时间、当时DM角度/速度/反馈年龄，以及5/6号位置与状态反馈年龄。`camera status`新增：

```text
[ARM CAMERA] last_failure phase=... reason=... elapsed=...ms
[ARM CAMERA] at_fault DM=...deg vel=... age=...ms ZDT5 age=.../...ms ZDT6 age=.../...ms
```

这些值是失败时快照，不会被随后恢复正常的反馈替换。下一次接受新的CAMERA动作后清空。

ROUND1在CAMERA失败取消时保留相同原因和`failed_phase`，不再只留下`inner arm action cancelled`。OK被拒绝时也打印MATCH当前状态及站点，区分“仍在运行”和“已经FAULT”。

## 使用

更新后启动日志应含`CAMERA_DEPLOY_V81`。第一轮三红流程、槽位205°/295°/25°、原示教圆环取回高度、现有速度和6号三次堵转尝试均保持。

当前V80失败现场不要反复发OK强制跳过。更新固件会重新初始化RAM库存；重新试跑前取走载物盘已有三颗物料，清空目标圆环，再按原流程：

```text
&match reset
&prepare 1
```

2号发车位用`&prepare 2`。等待READY再发`&OK`，之后各站等WAIT_OK再发下一次OK。完整路线操作见包内第一轮流程说明。

如果再次失败，先发上面的三个状态指令，补上`&arm status`和`&arm query dm`，保留`last_failure/at_fault`回显后再复位。无须为了诊断重复抓取或重新设置零点。

## 验证范围

生产C状态机模拟、原有三次重试/真实过期反馈失败/停止取消回归及Keil构建；未烧录、未操作真实电机、未实机验证本次现场是否由时间误判触发。

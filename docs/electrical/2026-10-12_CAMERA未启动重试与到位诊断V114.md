# V114：CAMERA原生位置动作未启动的重试和诊断

## 这次日志说明什么

用户日志启动版本为V111。第一轮ROUGH物料已取回三个载物盘槽，去TEMP时恢复CAMERA失败：

```text
native stable residual >2%; check microsteps/input scale
at_fault ... ZDT6 age=9/49ms
angle_deg=+1.269 encoder_count=231 input_pulses=12
```

此时反馈新鲜，输入脉冲与零点附近的编码器计数相符，未到CAMERA的−300°目标。驱动器REACHED位可能沿用上一次动作；HAL_OK也只说明主控发送接口接受排队，并不证明电机执行完成。

原代码把约0.36°的小变化视为动作已启动，可能让零点附近抖动配合旧REACHED走到“大残差/检查细分”的分支。这条软件路径可以在生产C模拟测试复现。实际原命令未执行的物理或通信原因仍需新回显/实物验证，不能由旧日志断言为某个CAN故障或细分错误。

## 改动

- CAMERA原生位置控制用有意义的编码器变化证明启动：大行程按0.5%行程约3.64°，小行程门槛按本次行程25%缩小；到位仍按原实际位置容差确认。
- 等待1.5秒后，若位置仍在起点附近、反馈新鲜、使能正常且无堵转/保护，重放缓存的同一绝对位置目标。
- 初次命令加最多两次重试，总共3次；与已有堵转重试共享这个预算，速度沿用60/30/15RPM的上限。
- 未启动重试为STOP、使能确认、重发原绝对目标，不执行反方向2mm。真实堵转仍使用之前的观察/清保护/反向退让/重试流程。
- 已有明显运动、已经到位、超出范围、反馈丢失、其他轴或DM故障都不能走未启动重放。STOP/失能/流程取消仍取消缓存动作。
- 原2%小残差边界保留，不把大位置错误当成功。不使用全行程速度反馈补救，也不修改零点、细分或写入Flash。
- `&arm camera status`增加故障时6号起点/实际/目标百分比、原始计数、flags、ACK和动作启动标志，之后读到健康反馈也不会覆盖这份故障快照。

## 使用

只烧录本包STM32 V114 HEX；摄像头程序无需更新。V114包含V113正确时序：夹爪完整闭合后抬升，实际升到半程开始DM和6号并行，升顶且DM/6号实际到位后才最后下降。夹爪1000µs/s、5号150RPM、6号60RPM、DM112.5°/s及其他V111参数保持。

原`&match reset`、`&prepare 1|2`、一次`&ok`不变。启动标记为`CAMERA_DEPLOY_V114`。

新诊断例子：

```text
[REACH START RETRY] attempt=2/3 SAME ABS=2667 ... STOP/enable/replay, no reverse retreat
[ARM CAMERA] no meaningful startup: from=... actual=... target=... flags=... ACK=...; SAME ABS retry
[ARM CAMERA] at_fault reach from=... actual=... target=... raw=... flags=... ACK=... motion=...
```

如果再次失败，保留当前状态，发`&arm camera status`、`&arm status`、`&zdt query 6`。正常到位会显示`CAMERA READY`，无法由重试回显替代实际到位。

# 机械臂三轴驱动与现有工程审阅

当前达妙操作已更新：`dm on/off`、`dm zero`自动查询反馈，`dm zero save`明确保存电机内部零点并保持失能。旧arm enable/disable/zero dm兼容；永久设零也可arm zero dm save。下文保留历史实现记录，最新语义和断电验证见[达妙简化操作与内部零点](2026-10-05_达妙简化操作与内部零点.md)。

本次只新增 `Core/Inc/arm_driver.h`、`Core/Src/arm_driver.c`、`Core/Inc/arm_calibration.h`、`Core/Src/arm_calibration.c`、独立测试和本文档。未修改已有源文件、任务、CubeMX 配置和 Keil 工程文件；未烧录或发送实机运动命令。仓库原先已有的未提交修改未处理。

后续同日新增 `Core/Inc/arm_servo.h`、`Core/Src/arm_servo.c`，并扩展上述新增模块，实现载物台和夹爪控制。舵机参数、学长工程依据与命令见[载物台与夹爪舵机驱动说明](载物台与夹爪舵机驱动说明_2026-10-03.md)。三路电机和两路舵机仍复用同一个机械臂所有者任务。

## 电机分工

| 接口枚举 | 电机及机构 | 总线/地址 | 正方向 |
| --- | --- | --- | --- |
| `ARM_DRIVER_ROTATION` | 达妙，机械臂转盘 | FDCAN1；ESC=0x01，反馈=0x11，POS 命令=0x101 | 按旋转方向配置 |
| `ARM_DRIVER_LIFT` | ZDT 42，升降 | FDCAN2，ID=5 | 上 |
| `ARM_DRIVER_REACH` | 28 步进，齿轮齿条带动摄像头前后 | FDCAN2，ID=6 | 前 |

用户已确认 ID 6 也是 ZDT 驱动器及 Emm 固件。旧文档里的“两台 ZDT35”与此次用户提供的 42/28 分工不一致，本次按用户说明实现。

## 审阅结论与实现边界

1. `arm_task.c` 已经拥有唯一达妙实例并每 10 ms 执行 `DM_Motor_Service()`。新增驱动复用它，不创建第二实例、不重新初始化总线、不抢占 CAN 回调。
2. `zdt_motor.c` 已有按地址使能、停止、相对脉冲移动接口。新增驱动只发 ID 5/6，全部使用 `buffered=0`，不调用广播 `ZDT_Motor_SyncTrigger()`。底盘会发广播同步启动，因此不能在这里缓存机械臂动作等待全总线同步。
3. 现有 ZDT 位置命令固定为 Emm `0xFD` 分包，且相对方式字节固定为 `0x02`。`ZDT_FIRMWARE_X` 不会切换这个位置接口的帧格式。新增驱动不更改底层协议；必须确认两台驱动器支持这套命令。
4. 现有 ZDT 速度接口会缩放速度字段，但位置接口直接发送 `speed_rpm`。新模块也原样传递位置速度参数；42/28 驱动器上的实际速度、加速度含义需要台架核对，不能直接套用底盘速度标定。
5. `DM_Motor_SetPos()` 忽略底层发送返回值并返回 `HAL_OK`。新增旋转接口检查实例的 `last_err`；失败时清除周期目标并锁存达妙故障，避免失败目标随后被周期重发执行。恢复需先调用现有 `ArmTask_ClearFault()`，再显式使能。
6. 达妙 `DM_GetPosRad()` 返回原始位置，而 `SetPos()` 会叠加 `pos_offset_rad`。新增驱动以原始坐标定义旋转零点，下发前扣除这个偏移，避免 `dm zerohere` 后重复叠加。
7. 达妙原有使能函数包含两段各 300 ms 的反馈等待，头文件“全部无阻塞”的旧注释不完全符合当前实现。新增普通运动函数不增加等待；达妙使能继承现有握手及日志耗时，只能在任务上下文调用。
8. 现有工程没有把 ID 5/6 的到位、当前位置和报警反馈暴露出来。新标定模块按厂商手册新增 `0x3A` 状态、`0x36` 位置查询和解析，以及低速寻端点状态机。它需要现有 CAN 接收代码把反馈投递进新增队列，不能绕过现有代码再读取同一个 FIFO。运动函数返回值仍不代表到位。
9. 现有控制台与 `armTask` 都能修改达妙实例，缺少覆盖全部访问的互斥机制。新增控制函数必须放在服务达妙的同一任务中调用；UART/CAN 接收端使用新增 `PostCommand` / `PostCanFrame` 队列端口投递数据，不能并发使用旧 `dm ...` 控制命令。队列为静态内存，CAN 投递支持 ISR。按“不修改其他工程代码”的要求，本次写好这些端口而未插入已有任务和回调。

## 参数标定

初始化只复制配置，不发使能或运动命令。默认角度范围 `0..360°`，默认旋转速度 `90°/s`，线性轴默认位置速度参数 60、加速度 200。默认毫米换算系数为 0，因此毫米接口拒绝运行，脉冲接口可用于标定。

- `lift/reach.reverse`：0 表示正向脉冲发顺时针命令，1 表示反向。以实际机构的上/前方向确认。
- `lift/reach.pulses_per_mm`：实际“协议脉冲数 / 机构毫米”。以驱动器实际细分、传动比和实测行程计算，不按机座尺寸猜测。
- `lift/reach.max_move_pulses`：单条命令的脉冲数上限，0 表示只有 `INT32_MAX` 数值边界。它不是总行程限位，反复相对移动仍可能越过机构端点。
- `rotation_zero_rad`：机械臂 0° 对应的达妙原始输出轴弧度，只保存于 MCU RAM，不写电机 Flash。
- `rotation_ratio`：达妙输出轴转数 / 机械臂转数；直连为 1。达妙内部减速比已经体现在输出轴反馈中，不应再次乘内部减速比。
- `rotation_reverse`：机构旋转方向；角度上下限可按机械避让要求缩小。完整一圈目标为 360°，不会取模变成 0°；不能据此实现无限多圈旋转。

若电机一转为 `P` 个协议脉冲，电机每转带动齿轮转 `1/R` 圈，齿轮模数 `m`、齿数 `z`，则：

```text
齿轮节圆周长 = π × m × z（mm）
前后轴 pulses_per_mm = P × R / (π × m × z)
```

升降若是丝杆，电机每转的实际升降距离为 `L` mm，则 `lift.pulses_per_mm = P/L`。若采用带轮、齿条或其他传动，直接用实际每转位移计算。毫米接口四舍五入到最近整数脉冲，非零但不足半个脉冲的请求会被拒绝。

## 函数使用

把新增 `arm_driver.c`、`arm_calibration.c`、`arm_servo.c` 手动加入 Keil 的 Application/User 组，头文件搜索路径已含 `Core/Inc`。由于本次未修改 `.uvprojx`，原有固件构建不会自动包含新增文件。两路舵机还需按其说明显式调用 `ArmServo_Init()`。

初始化示意：仅执行一次，可以在原有总线初始化完成后由机械臂所有者任务执行。实际标定参数未知时，先保持毫米系数为 0。

```c
#include "arm_driver.h"
#include "arm_calibration.h"

arm_driver_config_t cfg;
ArmDriver_DefaultConfig(&cfg);

/* 在这里填入实测方向、单次脉冲上限、传动比和毫米换算系数。 */
HAL_StatusTypeDef result = ArmDriver_Init(&cfg);
/* result != HAL_OK 时拒绝进入机械臂工作流程。 */

arm_cal_config_t cal_cfg;
ArmCalibration_DefaultConfig(&cal_cfg);
cal_cfg.lift_reverse = cfg.lift.reverse;
cal_cfg.reach_reverse = cfg.reach.reverse;
result = ArmCalibration_Init(&cal_cfg);
```

下面是独立的命令示例，每条都应由所有者任务按请求执行并检查返回值；不要将全部命令连发作为动作序列。

```c
result = ArmDriver_Enable(ARM_DRIVER_ROTATION);
result = ArmDriver_Enable(ARM_DRIVER_LIFT);
result = ArmDriver_Enable(ARM_DRIVER_REACH);

result = ArmDriver_RotateToDeg(90.0f);   /* 绝对机械臂角度 */
result = ArmDriver_RotateByDeg(-30.0f);  /* 相对最新反馈位置 */

result = ArmDriver_LiftByPulses(200);    /* 上；脉冲数只作接口示例 */
result = ArmDriver_LiftByPulses(-200);   /* 下 */
result = ArmDriver_ReachByPulses(200);   /* 摄像头前移 */
result = ArmDriver_ReachByPulses(-200);  /* 摄像头后移 */

/* 仅在填写对应 pulses_per_mm 后可用；数值只作接口示例。 */
result = ArmDriver_LiftByMm(10.0f);
result = ArmDriver_ReachByMm(-10.0f);

result = ArmDriver_Stop(ARM_DRIVER_LIFT); /* 停止升降，保留使能 */
result = ArmDriver_StopAll();            /* 三轴停止，两路舵机保持当前输出 */
```

返回值约定：

| 返回值 | 意义 |
| --- | --- |
| `HAL_OK` | 初始化有效、命令入发送队列成功，或合法零脉冲空操作；不代表线性轴已到位 |
| `HAL_BUSY` | 队列不足、达妙使能/控制占用，或重复初始化；调用者决定何时重试 |
| `HAL_ERROR` | 参数、标定、使能、反馈、总线或发送检查失败；不得继续动作序列 |
| `HAL_TIMEOUT` | 透传底层超时；不得按已完成处理 |

ZDT 的本地使能标志只表示本模块发过使能请求。上电重启、掉电、故障或其他代码的使能/失能动作不能通过这个标志获知。必须由应用层统一拥有 ID 5/6 的命令与反馈。

停止与失能不同：步进 `Stop` 只发停止，保留使能力矩；`Disable` 明确撤销使能，垂直负载的防坠由机构和应用层负责。达妙 `Stop` 使用原有失能路径并清周期目标。总线故障时停止帧也可能发不出去，`HAL_OK` 也只确认入队，不是硬件急停确认。

## 堵转端点标定及串口命令

本地厂商用户手册第 72–74 页确认：Emm 实时位置为每圈 65536 计数；`0x3A` bit0 为使能、bit1 为到位、bit2 为堵转、bit3 为堵转保护。CAN 数据去掉串口地址字节，分别解析为 `36 sign position[4] 6B` 和 `3A flags 6B`。依据：`docs/vendor/zdt-x42s/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.pdf`。

寻端点流程：先读取新鲜状态/位置；旧堵转或旧保护标志仍在则拒绝启动；确认使能后以默认 20 RPM 运行，忽略起步前 300 ms 的堵转瞬态；连续两次新反馈出现堵转/保护标志后发送停止；停止后继续查询，收到两次位置不再变化的样本才记录端点。失联 500 ms 或整段超过 15 s 则停止并报告失败。速度、方向、查询周期和超时由 `arm_cal_config_t` 配置，寻端点速度限制在 1–100 RPM。

手动放置的端点用 `mark`，会先发送停止，再等待稳定位置；不会直接拿缓存位置作端点。端点记录只在 RAM，不清零步进编码器、不写电机 Flash、不自动解除保护。堵转也可能来自途中障碍，因此端点需操作者确认；若已触发驱动器堵转保护，驱动器可能已经撤销力矩。

ASCII 命令以回车结束，不加 `&`。下列步骤需逐条执行，等待上一步完成通知：

```text
arm help
arm enable 5
arm mark 5 min         # 手动放到最低后，等待 LOWER RECORDED
arm clear 5           # 仅在旧堵转/保护仍有效时显式解除
arm seek 5 max         # 向上寻端点，等待 UPPER RECORDED
arm status            # 打印下端、上端、相差计数及圈数
```

命令中的 `# ...` 是说明，不要一起发送。ID 6 可同样使用 `mark/seek 6 min|max` 标定后端/前端。默认正方向按配置映射，第一次必须确认实际方向。示例回报：

```text
[ARM] id=5 fresh stall; stop queued raw=... flags=0x05 stall=1 protected=0
[ARM] id=5 UPPER RECORDED raw=... flags=0x05 stall=1 protected=0
[ARM] id=5 lower=... upper=... span=... counts rev=... travel_mm=...
```

后续测得实际端点距离后设置 `arm travel 5 <行程毫米>`。它把上下端点间的反馈计数换算成实际高度，最低点为 0 mm；`arm scale 5 <控制脉冲每毫米>` 用于相对毫米动作，两者含义不同。ID 6 同样支持 `travel/scale`。串口测试动作接口：`arm pulse 5|6 <正负脉冲>`、`arm mm 5|6 <正负毫米>`。为保持单一动作所有权，标定期间除 `status/help/stop` 外的串口命令均返回 busy。

## 达妙软件零点与高度联锁

`arm disable dm` 先失能并请求新反馈，等待反馈后再执行 `arm zero`。零点接口要求新鲜反馈确认已失能且接近静止，仅修改 MCU 内的软件零点。若设置后全角度范围超过达妙原始 ±12.5 rad 量程会拒绝；可先用 `arm limit <最小角度> <最大角度>` 缩小范围。软限位超界直接报错，不静默截断；`arm rotate <角度>` 是绝对角度，`arm by <角度>` 以实际反馈作相对运动基准。

例如 `arm guard 50 0 90` 表示：高度低于 50 mm 时只允许 0–90°，高度达到 50 mm 后使用整体旋转范围。50 mm 和 0–90° 都是使用示例，需按机构测量修改。高度来自升降端点标定、`travel` 和新鲜位置反馈；未标定或反馈过期时拒绝旋转。已使能旋转的当前角度或目标角度进入禁区时，周期服务请求达妙失能和升降停止。

开启联锁后，普通向下脉冲动作还会检查预测高度；缺少毫米换算系数时拒绝向下动作。向下寻端点没有已知位移，要求达妙已失能并处于低高度允许角度区域。联锁轮询依赖任务周期和反馈延迟，不替代机构防撞距离及实机停车距离校核；默认不开启，必须配置阈值后才生效。

## 保持原代码不变时的接入位置

新增代码目前**未接入原固件**。以下是接入说明，不表示已修改工程。完成初始化及 Keil 文件登记后，需要三处调用：

1. `Core/Src/arm_task.c` 的所有者任务循环内，在每次 `DM_Motor_Service()` 后调用 `ArmCalibration_Poll()`。该函数排空新命令/反馈队列，执行标定、高度联锁和定期查询。
2. `Core/Src/zdt_motor.c` 的 `ZDT_Process_Command()` 中，对 `arm` 命令调用 `ArmCalibration_PostCommand(command)` 并返回。只投递，不在这个串口任务直接调用运动函数；检查返回值，队列满时报告 busy。
3. 同文件的 `ZDT_Motor_RxFifo0MsgPending()` 获取 CAN 帧成功后，把 ID 5/6 的 `0x3A/0x36` 回包调用 `ArmCalibration_PostCanFrame(&frame.header, frame.data, length)`。此端口只复制固定长度数据，支持 ISR；会保留投递时间，队列等待不会刷新旧反馈。若选择从既有任务接收队列投递，应保证前级延迟有界。

三个端口之外，不需要另建 UART 读取器、另一个达妙实例或同名 HAL 回调。CAN 队列可缓存 15 帧，命令队列可缓存 3 行，每次轮询处理最多一条串口命令。队列满时返回 `HAL_BUSY`，发送端需处理；不能默默丢掉急停请求。新 `arm stop` 是任务层停止请求，不是硬件急停。

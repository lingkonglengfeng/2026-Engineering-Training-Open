# V185：PD1锁止按键兼容OK启动

日期：2026-10-26。基于V184比赛工程，桌面SHOW_DEMO_D1副本不改。

## 接线与引脚

PD1与按键一端连接，另一端接GND；按下锁止为导通到地、低电平有效，断开为上拉高电平。
PD1在`gpio.c`中由推挽输出改为上拉输入，从开机输出写入掩码及输出初始化掩码中移除；`Engineering_Training_Project.ioc`同步改为GPIO_Input、GPIO_PULLUP，标签START_BUTTON。
旧`light.c`曾将PD1声明为补光通道1；该旧通道现在不再占用任何GPIO，初始化和PWM输出均不触碰PD1。旧PD2通道保留。当前MaixCAM补光和视觉程序没有改动。

## 启动方式

先发送：

```text
&match reset
&prepare 1
```

等待`[MATCH] WAIT_START_OK` / `launch pose READY`，然后任选：

- 将锁止开关由断开切到导通；
- 发送一次新的`&ok`。

按键不会自动执行prepare，也不会在PREPARING未完成时绕过READY。`&prepare 2`同样支持。

## 锁止和开机导通行为

| 情形 | 行为 |
| --- | --- |
| 上电开关已经导通到地 | 不启动，持续导通也不触发；先断开稳定30 ms，再导通稳定30 ms |
| 上电开关断开 | 高电平稳定30 ms后具备接受一次新导通的条件 |
| READY后新导通 | 消抖30 ms后调用与串口相同的OK入口，仅触发一次 |
| 持续锁止 | 不重复触发；每次重新触发都需要先稳定断开 |
| 准备前或PREPARING中按下 | 当次按下被消耗，不会缓存到READY后启动；断开后再按 |
| 按下发生在READY前，但消抖结束在READY后 | 沿用首次检测到导通的时间戳，原有“必须是READY后的新OK”判断会拒绝 |
| 运行中、故障、结束或手动WAIT_OK时按下 | 实体按键忽略，不改变比赛状态，也不是STOP键 |
| 实体开关上电锁止但发送串口OK | 串口OK仍按原来的READY及启动检查执行，不受实体按键释放状态限制 |

30 ms消抖使用时间戳和状态机，没有delay/忙等。读取在现有ZDT任务Poll中进行，不新增中断或任务；现有PA1的EXTI1配置保持。
`match reset`不重新武装已经导通的开关；仍要断开再导通，防止重置后闭合状态变成新按下。

## 与OK兼容的实现

新增`start_button.h`保存候选电平、稳定电平、候选变化时间和一次性武装状态。
`ZDT_StartButton_Service()`只在WAIT_START_OK把有效按下送入原`ZDT_Match_Command("ok", pressed_tick)`。
串口事件先处理，再处理实体按键，因此同轮Poll中STOP已使流程退出READY时，按键不会重新启动。
原有OK分支和机械臂新鲜出发姿态、IMU零漂、CAN可用/BusOff/ErrorPassive及底盘使能检查逐字保持。

新增日志：

```text
[START KEY] PD1 active LOW, debounce30ms; boot-held needs release then press; READY only, same OK checks
[START KEY] PD1 press ignored: wait launch READY, release then press again
[START KEY] PD1 pressed -> OK; release required before next press
```

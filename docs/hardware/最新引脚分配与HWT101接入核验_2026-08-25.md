## 结论

当前引脚分配以根目录 `.ioc` 为唯一事实源；`docs/hardware/Engineering_Training_Project.ioc` 已同步为同一份配置。最新版引脚表为 [智能搬运赛项_引脚分配表.md](智能搬运赛项_引脚分配表.md)。其中必须区分“工程中已配置”与“已冻结、待操作者写入 CubeMX 的规划”；IPS200 属于后者。

HWT101 不是本工程的 I2C 设备，而是 TTL 串口姿态传感器。它占用独立的 `USART10`，不会占用 SPI1，也不会占用 I2C1。

| HWT101 信号 | 主控引脚 | CubeMX 配置 | 说明 |
|:---|:---|:---|:---|
| TTL_TX | PE2 | USART10_RX, AF4 | 传感器发送，接主控接收 |
| TTL_RX | PE3 | USART10_TX, AF11 | 主控配置命令，接传感器接收 |
| GND | GND | - | 必须共地 |
| VCC | 按模块标识供电 | - | MCU 收发逻辑必须为 3.3V TTL；传感器 TX 为 5V 时必须电平转换 |

当前工程参数为 `USART10, 115200, 8N1`，中断优先级为 4。程序已校验 WIT 的 11 字节数据帧，并提取 `0x55 0x52` 的 Z 轴角速度与 `0x55 0x53` 的 Yaw 角。

## 参考资料核验

若模块为出厂默认 9600 或未收到有效帧，先用上位机确认或设置为 115200；否则将 CubeMX 的 USART10 和 `Core/Src/usart.c` 一并改为模块实际波特率后重新生成、编译。只改文档无效。

## W25Q64 结论

W25Q64 采用普通 SPI 时可与其他从设备共享 `SPI1_SCK/PA5`、`SPI1_MISO/PA6` 和 `SPI1_MOSI/PA7`，只需独立 CS。因此通常**不需要**额外启用 SPI 外设，也不需要因为增加 W25Q64 而重新分配三根 SPI 总线引脚。

需要在 CubeMX 中修改的情形：SPI1 已被另一器件的片选占用且没有空闲 GPIO、需要改用另一组 SPI 引脚、要配置 DMA/中断，或决定采用 QuadSPI/OctoSPI。普通 SPI 接入时，在 CubeMX 新增或选择一个空闲 GPIO 作为 W25Q64 的 CS，并同步更新引脚表即可。

## IPS200 屏幕 SPI2 规划与待执行配置

IPS200 改为独立使用 SPI2：`PA9/SPI2_SCK`、`PC1/SPI2_MOSI`、`PC2_C/SPI2_MISO`，并使用 `PC6/IPS_CS#`、`PC7/IPS_DC`、`PC8/IPS_RST#` 三个控制脚，背光接 3.3V 常亮。当前 CubeMX 的 SPI2 全双工主机分配正是 `PC1=SPI2_MOSI`、`PC2_C=SPI2_MISO`；IPS200 不使用 MISO，所以 PC2_C 不连接屏幕。该方案使 W25Q64 继续独占 SPI1 的 `PA4/PA5/PA6/PA7`，两个器件没有总线或片选冲突。

当前工程实际尚未启用 SPI2，PC1、PC2_C、PC6/PC7/PC8 尚未写入 `.ioc`，屏幕还不能使用。操作者在 CubeMX 中启用 `SPI2 / Full-Duplex Master / Hardware NSS Disable`，选择 `PA9=SCK`、`PC1=MOSI`、`PC2_C=MISO`；再将 PC6/PC7/PC8 都设为推挽输出、无上下拉、Low speed、初始高电平，并分别标记为 `IPS_CS`、`IPS_DC`、`IPS_RST`。SPI2 设置为 `8 Bits / MSB First / CPOL Low / CPHA 1Edge / NSS Software / Prescaler 32`。不改时钟树时，SPI2 首版速率约为 `183.333 / 32 = 5.73 Mbit/s`。完整逐项清单见 [引脚分配表第 3.5 节](智能搬运赛项_引脚分配表.md#35-ips200-的-cubemx-配置清单由操作者执行)。

# 初赛与决赛独立目录

> 历史开发记录。当前公开版的分支、安装和贡献流程见 [开发与协作](README.md)。

## 使用流程

1. 初次切到初赛且尚未准备W25区时，先用决赛V245和配套上位机，在“机械臂控制 → 一键动作 / 参数保存 → 初赛 / 决赛W25参数”选择初赛并准备。看到 `[ARM PROFILE] READY target=PRELIM active=FINAL HAL=0` 后再刷初赛。已有准备标志时不会重置之后保存的初赛微调。
2. 烧录对应目录中 **V245** 的HEX，再双击该目录上位机入口。界面PC2.6.7，读取状态显示V245及初赛/决赛参数区。旧V237、V244只作归档，不包含全部统一功能。
3. 在“圆盘 / 圆环取放”读取四姿态，修改后先应用到RAM，再保存姿态到W25；看到 `[ARM DISC PARAMS] SAVED HAL=0` 才算成功。初赛新增四姿态区无记录时使用V237原姿态基准加零增量，不读取决赛姿态。圆环/舵机预置另用普通主控参数保存。
4. 双路视觉接入运行，点击“准备：只归位与零漂”，保持车静止，等待 `WAIT_START_OK`。
5. 在实际起点摆正放稳。PD1短按松开选1号区并发车，按住至少1秒松开选2号区并发车；也可点击上位机对应发车按钮。当前位置/朝向在接受发车时绑定。
6. 后续切换比赛仍须烧录另一套固件。W25按钮选择当前版本是读取；选择另一版本是保存当前值并准备/核对目标区域，不切换代码，不把另一套参数套入当前RAM。

相机桥接共用，无需每次切换比赛重装。两套上位机依赖共用电脑Python环境，但配置和新日志分别写在各自 `源码/vision/pc_vision/`；不要同时连接同一串口/相机运行两套。

## 参数在哪里

| 内容 | 初赛8MB W25Q64地址 | 决赛8MB W25Q64地址 |
| --- | --- | --- |
| 圆环微调、夹爪与载物盘预置 | 0x7F8000 / 0x7F9000，兼容V237记录 | 0x7F4000 / 0x7F5000，沿用V243/V244记录 |
| 四姿态 | 0x7F2000 / 0x7F3000，V245新增 | 0x7F6000 / 0x7F7000，沿用原记录 |

有效保存值在上电时自动加载；PID/导航区域仍共用。目录中的参数JSON只是标明来源的历史/默认参考，不是本次读取的完整W25镜像，不会自动写入设备。

视觉配置分别在各自 `源码/vision/pc_vision/` 的 `config.json`、`config.cam2.json`、`serial_config.json`、`calibration.json`。`参数/本机视觉配置快照` 只保留创建时副本，不跟随调参自动更新。初始两套复制同一份本机配置，不代表历史初赛原始视觉标定。

## 修改、编译与GitHub

修改初赛只进入 `初赛/源码`，修改决赛进入 `决赛/源码`。公共代码保持一致，`Core/Inc/competition_profile.h` 的 `COMPETITION_PRELIMINARY` 默认值初赛为1、决赛为0，用于选择参数区和取盘顺序；不要在初赛工程中误改成决赛。

双击对应Keil入口编译，输出位于本套 `源码/MDK-ARM/Engineering_Training_Project/`。修改源码后应烧录新生成的固件，外层 `固件/` 归档不会自动更新。`版本信息.json` 记录整理时的提交和HEX哈希，后续部署需更新记录。

两套源码分别提交到 `codex/arm-control-panel` 和 `codex/final-gripper-control`，`origin` 都指向GitHub；正常同步使用 `git pull --ff-only`，保留未提交修改。原根工程也是决赛副本，通过Git同步，不会随另一份目录自动更新。

重新创建可在原工程根目录运行 `python tools/create_competition_layout.py`。默认目录存在时退出保留现场；可用 `--destination <尚不存在的新目录>`。需要两套本地分支均已同步至V245。源码克隆使用不可变Git对象硬链接，工作文件/索引独立，无对象alternates依赖；不复制日志、截图和Python环境。生成目录被原仓库忽略，GitHub保存脚本与说明。

归档HEX取自本机 `output/v245_competition_2026-11-01/`；其他电脑没有归档时需编译对应源码。详细升级依据见原工程 `docs/electrical/2026-11-01_初赛决赛统一流程_V245.md`。
